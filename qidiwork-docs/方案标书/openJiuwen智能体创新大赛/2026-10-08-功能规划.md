## 一、功能总览

参赛作品 = **QidiWork 底座（已建成）+ 三层增量（本档新规划）**：

```
┌────────────────────────────────────────────────────────┐
│ 增量③ 场景货架 UI（分类卡片 + 一键切换 + 场景高亮）        │ ← 新 UI
├────────────────────────────────────────────────────────┤
│ 增量② 对话路由（会话内意图识别 → 自动挂载场景 → UI 明示）   │ ← 新逻辑（轻）
├────────────────────────────────────────────────────────┤
│ 增量① 场景包（6 场景 × 人设/提示词模板/示例任务/产物归档）  │ ← 新内容（重）
├────────────────────────────────────────────────────────┤
│ 底座（已有，零改动复用）：内核 agent stdio + ACP 多会话、   │
│ office-workspaces 数据面、15 技能芯片、四格式预览、产物卡片、│
│ 权限审批、设置页、会话恢复、系统通知、安装包/升级器          │
└────────────────────────────────────────────────────────┘
```

**设计铁律**：参赛 fork 尽量不动内核（cf-shell/cf-agent）。三层增量全部落在 GUI 侧（src-tauri + Vue）与技能包侧（新增场景包目录），把工程风险锁在已验证边界之外。

## 二、增量①：场景包（内容层，工作量最大）

### 2.1 场景包数据结构（设计稿）

```
~/.qidi/scenes/<scene-id>/
├── scene.json          # 元数据：id/名称/图标/一句话描述/分类标签/示例任务清单
├── persona.md          # 场景人设（system prompt 注入物，含输出规范与禁则）
├── templates/          # 产物模板（docx/xlsx 模板文件，可选）
├── examples/           # "试试看"示例输入（小白一键演示用）
└── skills.map          # 该场景可调用的技能白名单（收敛 agent 行为半径）
```

- `scene.json` 由 GUI 货架渲染；`persona.md` 在进入场景时作为首条 system 上下文注入会话
- 场景包独立于技能包（skills v0.1.5 机制不动），参赛版安装器同时装配两者

## 三、增量②：对话路由（双通道的隐式通道）

### 3.1 分层路由设计（DR-1，已定）

- **L1 会话内路由（P0，参赛承诺口径）**：通用对话里直接说需求（"帮我写个请示"/"把这份扫描件转 Word"），由**场景人设 + 技能白名单**让主 agent 自主选择对应能力完成——本质是提示词工程 + skills.map 收敛，**零内核改动**；GUI 侧监听工具调用事件，按 技能→场景 映射表实时高亮"当前场景"徽标
- **L2 跨会话路由（P2 增强，不承诺）**：意图分类器判定场景跳转 → 自动新建/切换对应场景工作区会话。涉及会话生命周期管理，DEMO 阶段不做
- 决策理由：L1 已能演示"说话即切换"的体验（场景徽标 + 产物落对位置），L2 的增量是 UI 状态管理而非能力，评审感知差异小、工程风险差异大

### 3.2 显式通道升级（一键切换）

- 货架点卡片 → 若无该场景任务工作区则创建（`office-workspaces/<scene-id>/<task>/`）→ 注入 persona → 对话 Tab 置顶场景徽标
- 已有工作区继续沿用（现 WorkspaceSidebar 逻辑），仅加"场景分组"两层树：**场景 → 任务**
- 护栏：切换不丢对话（ACP 多会话原生支持）；每个场景卡带"试试看"示例一键跑通

## 七、演示承诺口径（创意材料引用）

- **承诺场景**：投标标书、公文写作、会议纪要、文档处理（4 个实机可演示）
- **深化场景**：数据报表（P1 期补齐演示）
- **规划场景**：合同审查（材料中明示 roadmap，不承诺）
- **量化主张**（DEMO 实测口径）：技术标初稿 5-10 人天 → 数十分钟；全程零提示词门槛（点选/口语即可）

## 八、功能风险与对策

| 风险 | 等级 | 对策 |
|---|---|---|
| 场景包 persona 质量不齐导致演示翻车 | 高 | 内容先行（创意期就写初稿）；每场景配 examples 自动化冒烟；演示只用打磨过的场景 |
| L1 路由"场景感"不足（徽标不切/切错） | 中 | 技能→场景映射表人工核准 + 兜底默认"通用助手"态，宁可不切不切错 |
| 批注闭环赶不上 12/30 | 中 | 独立排期不阻塞主线；DEMO 脚本设计为可剪 |
| 参赛 fork 与 qidicode 内核演进漂移 | 低 | 参赛期冻结内核版本（0.1.x 基线），只改 GUI/场景包层 |
| 六场景铺开稀释质量 | 中 | 承诺口径锁死 4+1；S6 明示 roadmap |

## 附：决策记录

- **DR-1**（路由分层）：L1 会话内路由承诺、L2 跨会话路由列为增强——理由见 3.1
- **DR-2**（场景数量）：承诺 4 实机 + 1 深化 + 1 规划，防演示质量稀释
- **DR-3**（S6 定位）：合同审查为唯一纯新建场景，排 P2 不进演示承诺——新开发风险隔离在承诺外
- **DR-4**（工程边界）：增量全部落 GUI 侧与场景包侧，内核零改动——复用已验证面，隔离工程风险
