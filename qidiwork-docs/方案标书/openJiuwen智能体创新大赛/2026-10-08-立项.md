## 二、选题论证

### 2.1 四方向对比

| 维度（权重） | 办公 | Coding | 科研 | 设备互联 |
|---|---|---|---|---|
| 现有资产复用（×3） | ★★★★★ | ★★★ | ★★★ | ★★ |
| 差异化壁垒（×2） | ★★★★★ | ★★★ | ★★ | ★★ |
| 需求真实度/可量化（×2） | ★★★★★ | ★★★ | ★★★ | ★★ |
| 评审现场可验证（×2） | ★★★★★ | ★★★★ | ★★★ | ★★ |
| 演示稳定性风险 | 低 | 中 | 低 | 高（computer-use 类不可控） |
| **加权结论** | **首选** | 否决 | 备选 | 否决 |

### 2.2 用户裁决记录（2026-10-08）

- **否决 Coding 方向**：编码智能体除面向编程外意义有限，社会价值叙事弱，赛道拥挤
- 科研方向（文献/实验助手）被 GPT 系产品充分覆盖，无差异化壁垒，不选
- 设备互联：无 HarmonyOS/硬件生态积累，演示稳定性差，不选
- **选定：办公方向**——拥有全仓库最厚的已验证资产（约 80% DEMO 能力今天已存在）

### 2.3 办公方向的资产盘点

| 资产 | 成熟度 | 参赛用途 |
|---|---|---|
| bid-write / bid-creation（标书 SOP 八功能） | 生产验证 | 旗舰场景：投标 |
| bid-review / hefei-bid-review（AI 评标预打分、雷达自查） | 生产验证 | 差异化核心：自检量化 |
| bid-price-analysis（蒙特卡洛报价） | 可用 | 投标场景深化 |
| bid-diagram（甘特图/网络图/S曲线/劳动力） | 生产验证 | 标书图表 |
| bid-drawing（CAD 审图）、seal-extractor（抠章） | 生产验证 | 投标周边 |
| pdf-to-word-ocr（扫描件→Word） | 生产验证 | 文档处理 |
| office-tools（PDF/Word/Excel/PPT 全操作） | 生产验证 | 多场景底座 |
| office-canvas（人工批注→整改闭环） | 可用 | 人机协作亮点 |
| office-workbench / QidiWork GUI 方案 v2 | 方案+原型 | **产品壳与交互设计直接复用** |

**结论**：办公方向不是"选一个赛道从头做"，而是"把已在生产验证的能力组装成参赛产品"。22 天冲刺期内，工作量集中在平台适配层与产品包装，而非核心能力建设。

## 三、作品定位

### 3.1 一句话

**面向办公小白的"开箱即用"办公智能体工作台：按办公场景细分建站，选类别一键进入，或说句话自动路由到对应场景智能体。**

### 3.2 作品名（候选，10/30 前定稿）

| 候选 | 理由 | 风险 |
|---|---|---|
| **蜂办（BeeOffice）** | 呼应 JiuwenSwarm 蜂群多智能体隐喻，评委叙事加分；多场景=多工蜂各司其职 | 音译辨识度中等 |
| **妙办（MiaoBan）** | 二字朗朗上口，"妙手办事"，小白亲和力最强 | 查重/商标未验 |
| **智办工坊（OfficeCraft）** | 强调"工作台/工坊"产品形态，与 QidiWork Workbench 血统一致 | 名字偏长 |

（待用户定稿；本档暂以"蜂办"行文，可全局替换。）

### 3.3 目标用户与痛点

| 用户 | 痛点 | 量化 |
|---|---|---|
| 中小企业投标专员 | 技术标编制 5-10 人天，评分点易漏，格式硬约束多 | 命中率/耗时实测自证 |
| 行政/文秘（办公小白） | 公文格式、会议纪要、扫描件整理全靠手工 | 每类任务耗时对比 |
| 中小企业主 | 请不起专业文案与造价咨询 | 替代咨询成本 |

核心洞察：**办公小白不会写提示词，也不该被迫学**。产品的第一交互不是对话框，而是"场景货架"——看得见、点得中。

## 四、场景分类体系（本次立项新增核心设计）

### 4.1 设计原则

1. **场景货架**：首屏按办公场景分类陈列，小白直接点选类别进入对应智能体，零提示词门槛
2. **双通道切换**：① 显式通道——界面一键切换（像切应用一样切场景）；② 隐式通道——对话中意图识别自动路由/切换（用户直接说需求，系统判断该谁接）
3. **先深后广**：投标为旗舰场景（资产最厚、差异化最强），其余场景用 office-tools 底座快速铺开，创意阶段承诺的场景数以能演示为限

### 4.2 首批场景分类（创意提交版口径）

| 分类 | 细分任务 | 输入 | 产出 | 底层能力映射 |
|---|---|---|---|---|
| 🏆 投标标书（旗舰） | 招标文件解析、施工组织设计生成、评标预打分、报价分析、图表/审图 | 招标 PDF/CAD | 标书 DOCX+雷达自查报告 | bid-write / bid-review / bid-price / bid-diagram / bid-drawing |
| 📄 公文写作 | 通知/请示/纪要/方案等法定格式 | 口述需求 | 规范 DOCX | office-tools + 公文模板 |
| 🗓 会议纪要 | 录音/速记→结构化纪要+待办 | 文本/录音转写 | 纪要+行动项 | office-tools |
| 📑 文档处理 | 扫描件 OCR、格式互转、合并拆分、抠章 | PDF/图片 | Word/Excel/印章 PNG | pdf-to-word-ocr / seal-extractor / office-tools |
| 📊 数据报表 | 表格清洗、汇总、图表生成 | Excel/CSV | 报表+图表 | office-tools |
| 📝 合同审查 | 条款风险点标注 | 合同 DOCX/PDF | 风险清单+批注版 | 需新开发（11 月后） |

> 每个分类是一个"场景智能体"，有独立的人设/技能/模板集。切换 = 载入该场景 agent 的会话上下文与工作区模板。

### 4.3 交互双通道规格

- **一键切换（显式）**：左侧场景货架（QidiWork GUI v2 三区布局直接支持）；切换动作 = 新建/加载对应场景工作区会话
- **对话切换（隐式）**：路由层 Agent 做意图分类，识别到场景跳转（"帮我写个请示"→公文场景）时自动挂载对应场景 agent 并在 UI 明示当前场景；不确定时反问一次
- **小白护栏**：每个场景入口内置示例任务（"点这里，看看我能干啥"），一键演示复用

## 五、技术方案概要

### 5.1 部署形态（参赛封装层）

```
参赛作品「蜂办」（JiuwenSwarm 编排）
├── 入口层：场景货架 UI + 会话路由 Agent
├── 场景 Agent 群：投标 / 公文 / 纪要 / 文档 / 报表 /（合同）
├── 工具层：文档操作、OCR、图表渲染、抠章（参赛封装版）
└── 人工批注闭环：批注→整改清单→精修→复核（office-canvas 模式）
```

- 基于 **JiuwenSwarm**（大赛推荐平台，蹭评分倾斜）：平台层是开源的，我们的价值在场景 agent 定义与工具封装
- 我们私有技能库仅作**内部弹药**：能力思想迁移，核心提示词模板/评分规则库/评测数据**不进参赛仓库**（见第九节白黑名单）

### 5.2 与 qidiwork 私有资产的关系（IP 边界）

- 参赛作品 = 独立封装层，构建于 JiuwenSwarm 之上；qidiwork 仓库、技能库源码、内部文档**零上传**
- 参赛封装层用**新写的**场景 agent 定义与工具胶水；demo 后端可跑云端 API，不暴露私有栈
- 运行效果与私有版本一致的承诺范围：创意/DEMO 阶段演示级一致；完整生产级能力仍在 qidiwork 私有侧

## 六、创新点提炼（创意材料口径）

1. **场景货架 + 双通道切换**：办公智能体的"应用商店"式交互——小白点选即用，熟手对话即达；区别于"一个大对话框打天下"的通用型产品
2. **垂直深度可自证**：投标场景不是生成黑盒——带 AI 评标预打分与雷达自查，产出自带"评分点命中报告"，效果可量化、评委可验证
3. **人机批注闭环**：用户在 Word/图片上直接批注，Agent 读取批注生成结构化整改清单并逐条落地、复核闭环——办公产品少见的"改稿不改人"体验
4. **多智能体分工叙事**：一场景一智能体，蜂群隐喻与 JiuwenSwarm 平台同构，架构叙事与主办生态深度契合

## 九、风险与合规（含 IP 保护策略）

### 9.1 IP 三方共享条款的应对（核心策略）

**原则：参赛共享的是"台上样机"，弹药库和工厂都在家。**

提交面白黑名单（创意/DEMO 全程有效）：

| ✅ 允许进提交材料 | 🚫 禁止进提交材料 |
|---|---|
| 产品架构图（抽象层） | 技能库源码、SKILL.md 原文 |
| 场景分类体系与交互设计描述 | 核心提示词模板原文 |
| 演示级场景 agent 定义（参赛封装层代码） | 合肥评分规则库细节、评标方法论全文 |
| 演示视频、截图、效果数据 | 蒙特卡洛报价模型实现 |
| 项目文档（技术方案写到"能复述架构"为止） | 内部评测数据、客户样本 |

配套动作：
1. **报名问卷逐条审读**——微信扫码问卷可能内嵌授权条款，勾选前全文过一遍（人工，10/30 前）
2. **领奖补充协议逐条审**——奖金领取阶段的协议是第二道闸，届时再议
3. **可选：核心方法软著/专利预登记**——若创意材料必须展示某方法论细节，先预登记再提交，固化权属证据
4. 测试样本脱敏：所有演示用招标文件/合同去标识化，防商业秘密泄露

### 9.2 其他风险

| 风险 | 等级 | 缓解 |
