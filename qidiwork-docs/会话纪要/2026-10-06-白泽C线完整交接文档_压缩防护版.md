### 5.2 关键教训（全部实战血坑）

| # | 教训 | 原因 |
|---|---|---|
| 1 | **fresh 读 cur_id** → max(cur, last)+10 | 双写方踩底 = 丢命令 |
| 2 | **原子写 ckpt**（tmp+os.replace）| SFS EDQUOT 瞬时双份覆盖 |
| 3 | **per-command stdout 截尾 [-8000:]** | 大输出拆多条命令 |
| 4 | **pgrep 自匹配** → 用 $! PID 捕获 | pkill/pgrep -f 杀自己 shell |
| 5 | **base64 部署用 replace 不用 format** | JSON 花括号被 format 误解析 |
| 6 | **sed 区间删除必须先验证终点命中** | 终点不命中 → 删到文件末尾 |
| 7 | **CWD 稳定性**：rm -rf 目标目录前先 cd 走 | CWD 被删 → getcwd() 失败 → 后续全崩 |
| 8 | **SFS EDQUOT 是瞬发误报**：等 5-10s 重试即解 | 非硬配额满 |
| 9 | **大文件操作走 /tmp**（492GB 本地）→ mv 回 SFS | SFS 配额只装"要活的" |
| 10 | **df 是物理事实，du 不是** | du 统计文件字节 ≠ 容量 |
| 11 | **每条命令一个 shell 进程**——PATH 不跨命令 | 每条命令重新 export PATH |
| 12 | **-X utf8 启动 python** | 防中文编码问题 |
| 13 | **断言护栏**（argparse 校验关键标记）| 防带病发射 |

4. **alpha 自适应跨尺度**——M2 1.08 / M3 2.145 / R1 1.286 / R2 −0.326
