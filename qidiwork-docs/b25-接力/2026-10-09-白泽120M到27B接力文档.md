## §1 三套移植件 SOP（120M 实战固化，27B 变体逐条标注）

### §1.1 断点系统 v3.2（--save-every / --resume / --save-offset）
- 机制：`--save-every 2000` **原子落盘**（tmp+os.replace 防 SFS EDQUOT 瞬时双份覆盖，交接文档 §5.2 教训 2）；`--resume` 确定性重放；`--save-offset` 相位锁（T0 基线 1000 vs T2 的 0，`专利证据矩阵` #19）。EDQUOT 是瞬发误报，等 5-10s 重试即解（教训 8）。
- 三次实战（总计损失 10 分钟量级 = 断点粒度 2000 步 × 实测 0.3-0.4s/步/次，交接文档 §13.7 步速口径）：
  1. 白泽 2.0 SFT 重训 10-06：~0.4s/步、~6.2h 完赛、完赛即推仓（交接 §13.7/§13.8）；
  2. A 轨 T0@120M on mix_v4：10-06 窗口 ~8h 跑 ~35k 步 ckpt 银行化、明续，10-06 20:58 完赛 51,726 步（四门裁决包 §二′）；
  3. 2.2 SFT（baize22_sft_v1）：10-07 崩溃后 `--resume` 续跑成功（step 27,200/E1，ckpt banked@26,000，`审计评审/2026-10-07-白泽数据结构与清理审计-GLM53.md` §面3）。
- **27B 变体**（接力审计 §4.1）：① save-every 按「4h 窗口 × 4-6 ckpt 预算」设定，**不按每 2000 步**（一次全量 save 可打爆 /opt）；② 启动前 `df -h /tmp /opt` 收两个数；③ save 间隔 ≤（窗口剩余 − 写盘时间 × 2），防窗口被强制 kill；④ 每次续跑首 50 步必访 val_ppl 与 grad_var，不达标下窗即停（预注册口径）。

### §1.2 Agent 自愈钩子（bashrc autostart）
- 机制：`/opt/atomgit/.bashrc` 挂 5 条 autostart 钩子（agent_autostart / sft20_autostart / t2_autostart / t0_autostart 等），容器重启开终端即自动复活 agent 与在训任务（交接文档 §4.3）。
- 四次零人工验证：① 10-06 凌晨 ~05:00 agent 死亡，晨起钩子自动复活（`会话纪要/2026-10-06-白泽20四门裁决包与明日计划.md` 晨间简报）；② 10-06 13:04 复活 PID 834 认领 #3560（交接 §13.1）；③ 10-06 15:05 主理人侧独立体检互证钩子在位（交接 §13.7）；④ 10-07 断点续跑前探针确认（数据结构审计 §面3）。
- **27B 变体**（接力审计 §4.2）：① 桌面首次进入容器先执行 `echo $HOME; ls -la $HOME/.bashrc /opt/atomgit/.bashrc` 并回写本文档——桌面 $HOME 与 bashrc 路径**完全未验证**，若 /tmp-backed 则重启即蒸发；② 桌面 ttyd 被「弹药库」主会话长期占用，**训练期容器操作先在 tty 会话打招呼**（单 tty 争用）。

### §1.3 Git 通道协议（cmd.json 单命令槽）
- 机制：GitCode 仓 `cmd/cmd.json` 单命令槽（PUT 整体覆盖语义，新命令覆盖旧命令，**不能排队多条**）；id = max(远端 cur, 本地 last)+10 防双写踩底；agent 5s 轮询消费、回写 `cmd/out_<id>_npu.log`（stdout 截尾末尾 8000 字符）；本地锁 `channel_pending.json` 手动链 PUT 前写/完成后删作纵深防御（交接文档 §5.1/§13.6；`target/tmp/c-line/skill_new_git-cmd-channel-protocol.md`）。
- 五律（base64 ≠ 入仓）：① base64 部署脚本用 `.replace` 不用 `.format`（JSON 花括号被误解析）；② 命令槽只传短指令，大文件走 git/仓；③ base64 部署的脚本完赛后**正式 commit 入仓**（120M 已固化并被验证三次，接力审计 §4.2；交接 §13.8 第三笔销账）；④ 发送 token 由环境注入不硬编码；⑤ 长任务用 setsid 挂后台与轮询分开写。
- 两条血坑（10-06 18:46 实爆实修，交接 §13.8）：**git 身份必须 config**——bw_push 克隆无 git 身份致 commit 静默失败；**管道状态陷阱**——`commit|tail` 管道掩盖 fatal 造成假 BEST_PUSHED → 身份内嵌 + 显式退出码 + 远端核验。
- **27B 变体**（接力审计 §4.3）：① Linux 内核 execve 单参上限 **MAX_ARG_STRLEN = 128KB/参数**（120M 已撞过，base64 分发脚本）——训练脚本更可能触碰，硬规则：文件走 git/仓，命令槽只传短指令；② **训练期命令白名单：只允许监控类命令，禁新跑模型加载类命令**（单卡余量 1.4G，agent 再加载模型即 OOM 杀训练）。

### §1.4 ckpt 三层口径条款（27B 专用，防打爆 /opt 45G 极限）
| 口径 | 体量 | 出处 | 处置 |
|---|---|---|---|
| bf16 基底权重 | ≈ 52G | 27B 通报 §一 | **只存一次**到 /opt SFS |
| fp32 纯权重 | ≈ 8B/param ≈ 104G | 接力审计 §4.1 | 不存 |
| fp32 全量（权重+AdamW 状态）| ≈ 12B/param ≈ **156G+** | 接力审计 §4.1 | 不存 |
| **只存训练参数**（LoRA + inter-pass 可训 ~113M + 尾4 LoRA adapter）| **1.5-3G** | 接力审计 §4.1 | **27B 唯一允许的 ckpt 口径** |

120M SOP 的 `save-every=2000` 语义若照搬 27B，一次 save 即可打爆 /opt（实测 45-48G/50G）。ckpt = 训练参数 + optimizer + dataloader offset + loop 状态语义标识（R-A：pass 边界状态携带 vs 重置）。

## §4 27B 重启首日实验单（挂发射前 gate）

**发射前 gate（未清不得点火——接力审计 §六.1/§六.6）**：
- [ ] G1 环境：`npu-smi` 2×910 Health OK；`transformers.__version__ == 5.18.0`；`/opt` 实测余量 ≥ 64G（52G 基底 + 2-3G LoRA/inter-pass ckpt + 10G 余量）；SFS 配额余量实测（写 1GB 探针读回计数）
- [ ] G2 驱动 50 步长跑稳定性通过（**双触发器基建翼，未闭环**）
- [ ] G3 词表口径闭环：27B vocab 实测取回（R-D）+ 全部弹药按 §3.2 重分词预算
- [ ] G4 license 核查（§5 两红线）
- [ ] G5 LoRA-only 对照臂先跑取得 PPL 分母锚点（120M 线用 t0@E5=29.50 作匹配分母的 E5 口径规则；27B 无锚点则 SESOI 三分支无分母可比——接力审计 §六.6）

**实验单（按序）**：
1. **J1 恒等初始化检查（零训练成本，首日必做）**：LoRA/inter-pass 模块插入后 step-0 logits 与 LoRA-only 基线逐位一致（alpha=0 / read_proj=0 / LoopNorm=1.0 by spec，M5 冻结正文 §3「正向信号检查」）——唯一能在零成本下发现模块插错位的检查；不做则后续所有数无法归因。
2. **T2 vs T0 A/B（γ 臂：loop 架构首次容量充足被测）**：同数据、同 tok 数，唯一变量 = 参数量（T2 带 loop vs T0 无 loop）。**第 N 席方法论修正：γ 必须绑 ε 的 tokenizer 修复再跑**（注册 `<|im_start|>/<|im_end|>` 单 token + 全量重渲染），否则 866M 指标被 im_end 格式污染、判决不干净（第 N 席 Q3#3；Opus 终裁未排期、K3 判不吃窗口，本席判 5h 买封箱定性值）。判定预注册 **SESOI 2.0% 三分支**（≥2.0% 有效改善 / ≤−2.0% 反效 / ±2.0% 内无差 = 120M 归零结论重演；中域数据不能作 patent 证据——C线会签 S1 甲案）。
3. **ε SFT v3 封箱判决（若桌面先跑 120M 侧）**：tokenizer v2 注册 im_end 单 token + 全量重渲染 + 2ep + replay 减半 312k 一把梭（~6.5h），过门概率 <15%、价值在闭合叙事；**预注册归账表必须把 tokenizer 份额与 2ep/replay 份额分开记，禁止把 SFT v3 整体收益记在 tokenizer 账上**（Opus 终裁分歧 1）。
4. **SFT 配方建议（27B 首次发射前必答）**：① 先确定用「同一套 d17」还是「d17+d18+d19+d20 四件装合训」——**四件装合训从未在任意规模被测试过**，建议先在 28M 轻量臂验一次再上 27B（接力审计 §六.4）；② 四件装在 27B 以「**固定 token 份额**」而非固定条数写预注册——d18 内 D 类边界拒答样本若在 27B 仅配 ~1.6% 不可判别，须 upsample ×N 保持原 token 份额或接 d19/d20 扩量版本（接力审计 §5.1）；③ 遗忘门 replay 剂量须重定义：120M 的 1.47% 是「优化剂量当量（步数×LR 积分）」，27B 步数×LR 分布完全不同——把 625k replay chunks 按「bpe32k→Qwen 词表重分词 + 27B seq 4096 切合」重算后写三档 0/0.2%/1.0%，剂量单位重定义为「Qwen 词表 token/param 当量」（接力审计 §5.3）。
5. **27B 数据缩放疑问（悬案，如实挂账）**：1.3M 样本对 7B 级 SFT 够不够？文献带 100k-1M 条高质量 SFT，1.27M 在上限但合理；Qwen3.8-27B 底模已具备语言/代码先验，SFT 边际收益在 27B 上不比 120M 低——**数量不是约束，但四件装合训的配方结构未验证**（接力审计 §5.1）。另注意：27B 从头预训路线已被公式拆断——mix_/M3 弹药（~500M-1B tok）在 27B = 0.02-0.04 tok/param（比 120M 更欠，与 M3 285 相差约 8000-15000×），**唯一可行路线是 Qwen3.8-27B 底模上的 LoRA/inter-pass 插件**（接力审计 §5.2）。

### §4.5 CANN host 开销与卡时重算（[Opus 补丁 2026-10-09]）
