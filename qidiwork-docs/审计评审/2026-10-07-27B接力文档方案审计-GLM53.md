## 一、总判

## 五、数据弹药适配（审计问题 ④）

按 120M 的四件装（d17 1.27M / d18 ×20k / d19 492 / d20 5000）在 27B 上的四个缩放问题：

### 5.1 d17 1.27M：数量够，但两个口径要写白

- **量级判断**：文献带 100k-1M 条高质 SFT；1.27M 在上限但合理。Qwen3.8-27B 底模已具备语言/代码先验，**容量阈值效应决定的 SFT 边际收益在 27B 上不比 120M 低**——数量不是约束。
- ⚠️ **口径要写白**：a) d17 的 1,275,379 条已在 C 线 2.1 SFT（T0@866M 底模 + 1ep）实跑过一次（四门裁决包 §三 + 10-07 晨间简报）；27B 首次发射前必须先确定它是否用「**同一套 d17**」还是「d17+d18×20k+d19+d20 四件装」——**四件装的合训从未在任意规模被测试过**（四门裁决包 §三 只验证到 d17 单档）。
- 🟡 d18 ×20k 靶向在 27B 的占比效应 =「**占比稀释**」而非增强：d18 内的边界拒答样本（d15 编造 08 的教训源）若在 27B 上仅配 1.6% 不可判别，则**要么 upsample ×N（保持原 token 份额），要么后续接 d19/d20 扩量版本**。**建议：四件装在 27B 上以"固定 token 份额"而不是"固定条数"写预注册。**

### 5.2 下限数据量——欠训墙公式的新据

- 120M 判决中的「**欠训墙 3.3 tok/param vs M3 ~285 tok/param，85× 差距**」在 27B 数学上**直接**适用：mix_/M3 系弹药（~500M-1B tok）在 27B 上 = **0.02-0.04 tok/param**（比 120M 更欠，与 M3 285 相差约 8000-15000×）——**这拆断了"27B 从头预训"这条路线**。接力文档必须写明白。
- 27B 的数据路线实际**只有一条可行**：**Qwen3.8-27B 仍是预训出的强大底模**——LoRA/inter-pass 插件路线（M5 Phase A 架构）是唯一可行路径。**首日实验单（§4）之所以合理，就是因为它在 LoRA 语境下拆解。**

### 5.3 遗忘门 replay 的剂量重估

- 120M 剂量点：0 / 0.08% / 1.47%（+零-replay 对照）。**27B 上必须重新定义剂量单位**：120M 的 1.47% 是「优化剂量当量（步数×LR 积分）」—— 27B 步数×LR 分布完全不同，**同数值 1.47% 在 27B 语义上不等于 1.47%**。
- 建议：**27B 端把 625k replay chunks 按"bpe32k→Qwen 词表重分词 + 27B seq 4096 切合"重算**，然后写三档：**0 / 0.2% / 1.0%**（预估低档反向，需预注册），**剂量单位重定义**为"Qwen 词表 token/param 当量"。

### 5.4 词表/分词器口径（**最困难的隐性雷区**）

C 线资产的词表实际是分裂的：白泽 120M 预训配方 = **Qwen3.8 原生 248,320 词表**（交接文档 §7.2）；**bpe32k 32k** 词表被用于 **SFT 数据渲染 / mix_v3.npz / eval_m4 评测渲染**（M4 会话记忆）；**8192 小词表**npy 曾与 Qwen3.8 混装（C 线裁定 §2 早已成为"8192 词表 npy 必须用 Qwen 248K 重分词"之明令）。**27B Qwen3.8 的 vocab = 未闭环**（台式机通报 R-D）。

- 建议接力文档**必列一张「口径表」**：**每个弹药资产的 name × 词表(248,320 / bpe32k / 8192) × 需重分词？ × 重分词谁做 → 判断其 27B 可用/不可用**。**"code 208.6M 达标"等 m5.1 数字在 27B 词表下 token 数会变 —— 写稿时必须标注该"达标"是 bpe32k 口径**。**这一列这张表，把桌面首周分词口径乱源直接钉死。**
