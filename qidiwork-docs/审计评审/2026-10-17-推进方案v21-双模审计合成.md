## 二、真 step-5 的 tap 设计审计（v2.1 核心）

### 采集点与开销
- 唯一 choke point = 组装 messages+tools 提交 sampling 处（cf-shell chat/sampling 路径）；**内存结构上、单次序列化之前计数**——绝不二次序列化/clone section
- 显式覆盖面：主回路 / 子代理 spawn 组装 / compaction 重宣 / replay harness（golden 覆盖非运行时）——**未覆盖路径必须在报告留白，不能默认被代表**
- 开销：字节计数 O(prompt) 亚毫秒；**真 tokenizer 禁进热路径**（复用既有估算器，无则 v1 用字符数离线校准）；搭现有 per-request usage/header 事件便车；采样 1%/dev flag；**验收线：新增延迟 <1%、新增载荷为 0**

### Section 分类学（最重要的设计意见——v2 清单的致命缺陷）
v2 的清单（工具 defs/技能清单/MCP schema/系统提示）**全是准静态"家具"**；长 agentic 会话的质量主体是**会话历史与 tool results**。最小分类：
```
系统提示（静态/动态分开）/ 内置工具 defs / 每 MCP server schema / 技能清单 /
会话历史（按轮）/ 近 N 条 tool results / attachments / 未归因残差
```
残差单独一行——残差增长即漂移或漏 section，直接喂金丝雀。**不放宽分类学则①的表不该开**（程序有把 20% 家具优化到极致、对 80% 质量视而不见的系统性风险）。

### 对账与缓存归因
- `Σsections + 残差 ≈ prompt_tokens`（provider usage 是唯一权威总量）偏差超阈告警——**tap 从一次性测量变常驻漂移检测器**
- tap 每轮输出**稳定前缀哈希**——缓存命中按 section 归因（如技能清单注入位置抖动导致前缀断裂）
- tap **永不成为限额/计费的第二真源**

### 最小实现路径（天级）
1. grep 枚举四个组装点 → 2. choke point section 枚举+计数（复用估算器）→ 3. 并入现有 usage 事件默认采样 → 4. 对账告警 → 5. golden 钉死（固定输入→期望 section 字节数）→ 6. 离线校准 chars→tokens 后才发布"单价"表

## 三、真 step-5 的五方向遗漏（全部采纳）

| 级 | 方向 | 要点 |
|---|---|---|
| **P0** | 输入侧未入账 | history/tool results/attachments 才是长会话质量主体；**Phase C（已生产缺省关）正是对口杠杆——tap 必须能归因它的节省** |
| **P0** | 缓存前缀稳定性无主 | 禁时间戳/nonce/顺序抖动；1KB 抖动可能比 50KB 稳定载荷更贵——**折进④不变量集合+tap 前缀哈希** |
| P1 | **子代理路径对等性** | 快照事实：子代理组装=install_system_prompt+replace_conversation、**技能注入=0**；若重负载在子代理侧而 tap 只盖主回路=事倍功半；**子代理上技能节省恒为 0，工具 defs+MCP 是仅剩杠杆** |
| P1 | 每工具调用计数 | dispatch 处按工具计数——支撑 per-tool MCP（v3）/用数据复核 411→28（目前是判断不是证据）/死载荷发现（announced-but-never-called） |
| P1 | 成本口径 | token→每模型 ¥（价目表×缓存乘数），按成本排优先级；副产品：小载荷降低严格上游线 400/429 暴露（sensenova 线大 prompt 400 实锤） |
| P1 | 回滚闸门未定义 | 灰度缺省关是纪律不是闸门——①/③/⑤ 各定指标+阈值+责任人（工具调用成功率/任务成功率/缓存命中率/TTFT） |
| P2 | 白名单发现代价 | 383 技能对 agent 不可见——"请求了但未注入"计数器定价（最大的一刀没有质量轴度量） |
| P2 | 排期外部依赖 | step-5 订阅 10-20 过期（⑤范围可能漂移）；金丝雀/tap 硬性限时（各数天）不得侵蚀①窗口 |

## 四、③MCP 降档的三补丁（step-5）

1. **投影缓存失效**：按 (server, tools-hash) 键失效 + ToolNotFound 回退原始 schema（防 tools/list_changed 后幻影工具）
2. **状态语义保留**：投影只能砍散文，**必须保留 required-args/enum/状态前置条件**（playwright 的正确使用靠描述暗示如"先 tab_list"）+ 每 server 工具调用成功率金丝雀配回滚线
3. **per-tool 投影是 v3**：前置=tap 的每工具计数器（顺带解决死载荷发现）；验收量**端到端任务成功率**非载荷字节
