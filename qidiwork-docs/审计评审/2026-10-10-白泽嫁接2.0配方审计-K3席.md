# 白泽嫁接 2.0 配方审计报告（step-5 独立审计席）

## 总体判定

**方向靠谱，细节不 ready——不建议照方直接开训。** 1.0 的失败归因（LR 过高、数据太少）方向正确，但 2.0 配方把钟摆从一边打到了另一边，引入了三个新的结构性风险：**数据配比失衡到插件可能"零效果"**、**步数与数据量不自洽（1.3M 条 vs 1500 步，多数数据根本见不到）**、**关键超参（batch size / seq len / 采样权重）缺失**。判据和评测纪律是全文最扎实的部分，无需大改。

判定：**修改后发射（conditional GO）**。预估修改工作量 < 0.5 天，不影响下窗口。

## 逐项审计

### 1. LR 1e-5 —— ⚠️ 矫枉过正，建议 2e-5 ~ 5e-5 + cosine

- 业界 r=16/qkvo LoRA 的惯例区间是 **1e-4 ~ 2e-4**（这就是 1.0 用的值，它 FAIL 的根因更可能是"1000 条窄分布数据 × 相对高 LR"的组合，而非 LR 单独作恶）。1e-5 比惯例下限低 10 倍。
- 后果不是"伤底模"，而是**插件学不到任何东西**——1500 步 × 1e-5 的参数位移极小，考出来 style 三连打平、HE 不掉，"PASS 了但插件是死的"，白白浪费一个窗口还得做 3.0。
- **建议值**：峰值 LR **3e-5**（介于 1.0 失败值与 2.0 提案之间的几何中点偏保守侧），warmup 30 步，**cosine 退火到 10%**。不建议按 loss 动态调——手写训练循环里加自适应 LR 是新代码新风险，违背"已验证组合不乱动"的管线纪律。固定 schedule + 中途快照（已有每 100 步存档机制）足够。
- 补充保险：**加考一个 step500 快照**。如果 step500 已现 HE 下滑，直接止损，不必跑完 1500 步。快照成本为零（机制已有），这是配方里目前缺失的最便宜的风控。

### 2. 数据配比 —— ❌ 本文档最大的坑，必须重算

**问题一：样本数份额 ≠ token 份额，且两种算法都失衡。**

- 按样本数：d18+d19+d20 ≈ 2.55 万 / 总量 130 万 ≈ **2%**。均匀采样下，1500 步里白泽味数据只出现 ~30 步的等效量——插件学不到风格，2.0 大概率考出"HE 达标、style 打平"，等于没插。
- 按 token 数（文档声称的算法）：d17 如果是长代码/长文本，单条 token 可能数倍于 d18 短问答，则目标数据份额**比 2% 更低**；反之 d17 若是短条目，份额可能到 10-20%，尚可。文档没有给出 d17 的平均 token 长度，**这个数不补上，配比就是瞎配**。
- **建议值**：目标泳道（d18+d19+d20+对话语料）按 token 占 **15%~25%**，用**加权采样**实现（不要 upsample 复制，d19 只有 492 条，复制 50 倍会记忆化过拟合）。具体：d20 代码保镖 8-10%、d18 5-8%、d19+对话 3-5%、d17 补余。这是单次迭代的合理起点，考完再调。

**问题二：1500 步 × 1.3M 条数据不自洽。**

- 文档全程未给 **per-device batch size、grad accumulation、seq len**。按 spike 的 27B 手写循环，实际吞吐可能是 batch 4~8 条/步，1500 步只能消化 **6k~12k 条——不到全量数据的 1%**。"四件装全量"在这个步数下是伪概念，实际生效的是采样器碰巧抽到的那一小撮。
- **建议**：二选一——(a) 明确"本轮采样 N 条子集，配方按 N 设计"，把 1.3M 降成"训练池"而非"训练集"；(b) 提速后把步数提到能覆盖至少 1 个 epoch 的采样子集（如 batch 8 × seq 2048 × 6000 步 ≈ 4.8 万条，fla 生效后 8-14h，超出窗口）。**现实选择是 (a)**：本轮定位仍是"配方探针"，不是"全量灌入"。

### 3. LoRA 架构参数 r=16/qkvo —— ✅ 不动，正确

- 本轮变量已经够多（LR、数据、步数全变了），再动架构就把 A/B 的对照价值毁了。r=16/qkvo 与 8B 轨迹逐点可对照是资产，保留。
- MLP/gate 扩展留到 3.0 以后。风格类知识确实更多存在于 MLP，如果 2.0 考出"能力保住但风格没学到"，**第一嫌疑人是注意力-only 的 target 模块，第二才是 LR**——这条请预先写进判读手册，否则考完无法归因。

### 4. 判据 —— ✅ 框架合理，两处收紧

- HE ≥ 93pp 硬门：**同意，但建议改为 "HE ≥ 88pp（93.3 − 5，与预注册的 5pp 掉幅限额对齐）且 style 必须显著胜出"**。93.3% 本身有测量噪声（30 题，1 题 = 3.3pp），硬卡 93 等于要求逐题不输，偶发噪声就会 FAIL，浪费迭代。更严谨的做法：同一考卷固定 seed 双臂同考（已有此纪律），掉幅 ≤5pp 判平。
- style 判据：启发式已饱和（3.0/3 双满），**LLM 评分必须落地**，否则判据 2 形同虚设。建议：风格锚点 rubric 3 条 × 0/1/2 分，用底模本身或另一个强模型做盲评（打乱臂序），分差 ≥ 0.5/条 算"明显胜出"。
- **补一条缺失判据**：**对话语料掺入后必须加一轮安全/隐私抽检**（脱敏是否干净、是否记忆了手机号/身份证/客户名），这是 §六诚实边界里提了但没进判据的项。掺私人对话数据的模型，泄露测试应该是一等公民判据。
- real_exec 提难度：同意终审报告自评，10/10 双满的考节不提供信号，本轮至少换 5 道 27B 底模会错 2-3 道的题，才有分辨力。

### 5. 思考路由 —— ✅ 可落地，建议砍到最简

- 关键词门（§四.2）可直接上线，零成本。但关键词清单太窄（"难/复杂/设计/架构/排查"），漏"为什么/对比/分析/推演/证明"等推理触发词，建议补全。
- 0.6B 分类器（§四.3）：**本轮不做**。多一个模型就多一条部署链和一类误判，关键词门 + 手动开关已覆盖 90% 场景。列入 3.0 backlog。
- 评测纪律"考思考型必须关思考"已验证有效，保持。

## 修改建议汇总（发射前必改 5 项）

1. **LR**：1e-5 → **3e-5，warmup 30 步，cosine 退火至 10%**；加 step500 快照中考核。
2. **配比**：发射前打印各泳道**实际 token 份额**，目标泳道（d18+d19+d20+对话）合计拉到 **15-25%**（加权采样，不复制 upsample）；承认本轮是采样子集探针，写明实际训练条数。
3. **补缺失超参**：batch size、grad accum、seq len 写进配方——没有这三个数，"1500 步"无法审计也无法复现。
4. **判据**：HE 改掉幅制（≥底模−5pp）；style 落地 LLM 盲评 rubric；新增**隐私泄露抽检**为硬门。
5. **应急预案写入发射链**：fla 验证失败 → 当场降 600 步；step500 HE 掉 >5pp → 止损回炉，不等跑完。

**改完这 5 项，此配方可发射。** 架构定案（三层）、评测纪律、管线工程沉淀三部分质量很高，是这套方案真正的护城河；问题全部集中在"训练侧数值配比"这一层，属于半天能修完的量级。
