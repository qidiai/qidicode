## 3. 共识区（≥3 席一致 = 判决）

1. **停止/循环层与内容层是两个独立故障**——五席全部独立得出（K3/MiniMax/mcode/Ling 明述，GLM H5 同款）：T5 是判别性实验（rep_penalty=1.2 → 10/10 停止、内容仍 0/10）。循环是解码伪影，低分不是。
2. **F4 剂量-响应排除"数据量不足"**——26 倍靶向剂量零生成响应，五席一致（GLM H1"总量不缺"）。
3. **容量墙是代码门（HE/MBPP 0/164）的充分解释**——K3/MiniMax/Ling/GLM 四席；mcode 保留 14% 但承认"尚无同预算容量对照"。
4. **loop 架构暂停主线投入**——五席全同：420M T2-vs-T0 差 0.02 ppl 属噪声级 + loop 从未在生成指标被测 = 未证收益；T0 为默认基线，loop 降级为科研叙事/需特异性实验（深度外推、迭代精化）举证。
5. **tokenizer 停止缺陷是实锤工程 bug，必须修，但非内容根因**——五席（GLM 以 H5"计量卫生"涵盖）；无席位把 ① 投为第一约束（最高 MiniMax 20%）。
6. **val_ppl 与任务分脱钩**——五席；val_ppl 度量模板拟合度，生成度量任务能力。

## 4. 分歧区 + 书记员裁决

**分歧 1｜Q1 第一约束**：③容量墙（MiniMax 40+25、Ling 48、K3 首轮 55）vs ②数据形状（mcode 50、K3 补跑 40）vs H6+H4 复合（GLM）。
**书记员裁决**：分层定罪，二者不互斥——
- **停止层**（撞 512/循环症状）第一约束 = **①tokenizer 停止机制**（E1-E6 实锤：训练端 5 子词稀释、推理端死代码）；⑥解码是放大器（T5 可绕过）。
- **内容层**（判据全败）第一约束 = **③容量墙与②数据形状同构不可分**：F4 无法区分"模板天花板"与"容量不可达"（120M 上两者表现同构），S1/S3/S5 形式完美语义全错是共同签名。GLM 的 H6+H4（训练制度）降为**放大项**：其依据"loss 仍在降"未计入 E1-E6 新事实——EOS 监督被 5 子词序列稀释且 im_end 停止为死代码，1ep 的边际收益预期应下调。

**分歧 2｜Q3 排序**：先修 tokenizer（K3/MiniMax/mcode）vs 先 2ep（Ling）vs 2ep 判决（GLM）。
**书记员裁决**：两者合并为同一跑次——修 tokenizer 必须重渲染 SFT 数据并重训 SFT 才生效（K3 亦指出新 token embedding 需训练），故"修 tokenizer"与"2ep 续训"非二选一，而是**一次 SFT v3 跑次的两层**；零成本前置为 rep=1.2 双口径重评（五席共识）。

## 5. 终审

**根因 Top1（分层）**：
- 停止层：tokenizer 未注册 `<|im_end|>` 为单 token 特殊 id（E1-E6 实锤链）→ 停止信号稀释 + eval 死代码 → 6-8/10 撞 512。
- 内容层：120M 参数共享有效容量打折 × SFT 语料模板化（F4 26 倍剂量零响应、S1/S3/S5 形式完美语义全错）→ 判据全败。
- 放大项：1ep + replay 35% 步数稀释。

**2h55m 窗口行动三件套（按序）**：
1. 【0-30min·零成本】双口径重评：2.0/2.1/2.2 三 ckpt + rep=1.2 + EOS 停止校验，落"循环率/内容分"分离读数（GLM H5 + 五席共识）。
2. 【30-90min·卫生修复】eval_m4.py 停止条件改 EOS(2) 优先 + 文本兜底增量检测 + rep=1.2 开关（K3 方案：复用 EOS，零重训风险）。
3. 【90min 起·挂起】SFT v3 判决实验：tokenizer v2（注册 `<|im_start|>`/`<|im_end|>` 单 token）+ 全量 SFT 数据重渲染 + **2ep + replay 减半（312k）**一把梭（合并 H6+H4+tokenizer 三变量，~6.5h NPU；窗口内完成决策与启动）；预注册判据沿用 GLM §3 表并新增"停止率"读数。判据：内容分动→制度/数据层有效；不动→容量墙定案，战略转 27B（与剂量响应终表§五一致）。

## 6. tokenizer 修复完整技术方案

- **阶段一（不重训，~30min，只修症状）**：eval 侧 EOS(2) 停止 + 文本兜底 + rep=1.2（zh 门专用，B 类算术慎用——GLM 风险提示）；拿真实读数。
- **阶段二（根治，需重训 SFT）**：① tokenizers `AddedToken` 注册 `<|im_start|>`/`<|im_end|>`（special=True，id 追加 32000/32001，不动现有 32000 词表）；② `train_sft_m4.py` 渲染改 token 级注入；③ 全量 SFT 数据（d15-d22 ~1.31M 条）重渲染（分钟级）；④ **从同一预训练基座 ckpt 重跑 SFT 2ep**（~6.5h NPU）；⑤ eval_m4.py 的 `im_end_id` 自动生效，加 `--dry-run` 断言非 None。
- **预训练基座不用重训**：E6 实锤预训练指令池已 chatml 剥壳，im_end 字面不在预训练分布——这是本方案成本有界的关键。
- **风险**：新 token embedding 随机初始化，依赖 SFT 教会（每样本 2 次出现 × 1.31M ≈ 2.6M 直接监督信号，充分）；旧 5 子词序列与新单 token 的分布迁移由 SFT 覆盖。
- **备选（K3 提案，成本最低）**：不注册新 token，训练渲染去掉 im_end 字面、completion 仅 EOS 收尾、eval 以 EOS 为唯一停止——放弃多轮边界语义标记，仅适合单轮 QA 形态。
