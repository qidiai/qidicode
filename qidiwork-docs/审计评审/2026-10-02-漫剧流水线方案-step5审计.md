# 《漫剧生产流水线方案 v1》独立审计报告

## 1. 问题清单（按严重度分级）

### P0（阻塞，不修必失败）

**P0-1 角色一致性技术方案完全缺失**
- **问题描述**：方案仅通过提示词拼接 `identity_block` 尝试锁定角色，未部署任何角色一致性技术栈。
- **理由**：Qwen-Image-2.1 作为文生图基础模型，仅靠提示词无法保证同一角色在 40+ 次独立生成中保持面部、发型、服装一致。漫剧是连续叙事载体，角色长相漂移会直接导致观众认知断裂，产品不成立。原文“角色锁定短语由脚本从角色卡自动拼接”过于乐观，属于对当前扩散模型能力的误判。
- **修改建议**：在 S3 前增加角色一致性预处理环节：a) 使用 10-20 张角色图训练 LoRA（kohya_ss 或 ComfyUI 原生训练）；b) 或引入 IP-Adapter FaceID / InstantID，以角色卡参考图为条件；c) 或在 ComfyUI 中使用 Reference-only 工作流。M3 必须产出角色 LoRA 或 Reference 工作流，而非仅 JSON 提示词。

### P1（重要，显著影响质量或进度）

**P1-1 1024² 方图裁切 9:16 缺乏构图约束与智能裁切策略**
- **问题描述**：方案仅说“背景模糊放大 + 前景居中”，未在分镜设计阶段约束竖屏构图，也未定义裁切算法。
- **理由**：动漫分镜常包含横构图对话、环境展示、多人站位。直接居中裁切 1024² → 9:16 会损失左右约 35% 画面，导致角色出画、道具丢失、视觉引导线断裂。模糊背景只能弥补黑边，无法弥补主体被裁。
- **修改建议**：a) 在 `storyboard.json` 中增加 `framing: "center | left | right | top | bottom"` 字段，分镜时指定主体方位；b) `compose.py` 实现基于 `framing` 的 crop，而非固定居中；c) 或在 S3 出图时即用竖屏安全区模板（即使出 1024²，主体也集中在中央 9:16 区域）。

**P1-2 `check_shots.py` 的 API 成本与 ¥0 目标矛盾，且缺乏准确率基线**
- **问题描述**：方案承诺样片 ¥0，但 `check_shots.py` 依赖“中转 agnes-2.5-pro-beta vision”扫图，未说明该 API 是否免费、限流如何；也未给出乱字/鬼脸检测的准确率/召回率数据。
- **理由**：若该 vision API 按次收费，40 张图扫检成本将突破 ¥0；且当前多模态模型对“手部畸形/文字乱码”的检测仍有误报，不能替代人工终审。将其作为“兜底”会导致流程卡在自动审核或漏放问题图。
- **修改建议**：a) 确认 agnes vision 的免费额度与计费，若收费则从样片流程移除或限制为抽检（如 10%）；b) 将 `check_shots.py` 降级为“辅助标记”，输出可疑分数供人工参考，不作为硬门槛；c) 建立人工验收清单（线条闭合/文字无乱码/手指数量/角色相似度），由制作人终审。

**P1-3 “中转免费池”作为 S1 唯一入口，缺乏降级与重试策略**
- **问题描述**：S1 剧本分镜完全依赖“中转免费池（GLM-5.3 / DeepSeek-V4.1-Flash）”，未提及服务不可用时的降级路径。
- **理由**：免费 API 池常存在速率限制、模型下线、网络抖动。S1 是流水线起点，一旦阻塞，后续全部停工。原文仅说“~10 min”，未定义 SLA。
- **修改建议**：a) `gen_storyboard.py` 增加多供应商 fallback（如本地 Ollama 小模型、或人工模板）；b) 关键分镜参数（镜头数、时长、台词长度）允许人工 YAML 覆盖，不完全依赖 LLM 输出；c) 对免费池调用增加指数退避与熔断，失败超过 3 次自动切换本地规则引擎。

**P1-4 中文路径在 Python + ffmpeg + Windows 环境下的编码风险**
- **问题描述**：项目工作区路径包含中文（`qidiwork-docs/漫剧/<项目名>/`），方案仅提到绕开 PS 5.1 的 GBK/BOM 坑，但未涉及 Python subprocess 调用 ffmpeg 时的路径编码。
- **理由**：Windows 中文代码页（GBK）与 Python UTF-8、ffmpeg static build 的 UTF-8/GBK 混用极易导致文件找不到、字幕烧录参数乱码、concat demuxer 路径解析失败。这是 Windows 本地流水线经典陷阱。
- **修改建议**：a) 所有中间文件与输出目录强制使用 ASCII 路径（如 `qidiwork-docs/manhua/proj1/`），仅在最终交付时复制到中文目录；b) `compose.py` 中所有 ffmpeg 调用使用 `subprocess.list` 参数（非 shell 字符串），并显式 `encoding='utf-8'`；c) 字幕文件使用 UTF-8 with BOM（或 ASS/SRT 格式），避免 ffmpeg 读取中文 srt 时乱码。

**P1-5 `gen_shots.py` 缺乏断点续传与失败重试**
- **问题描述**：M4 需批量生成 40 张图并“过夜”执行，方案未说明 `gen_shots.py` 是否支持断点续传、单图重试、ComfyUI 崩溃恢复。
- **理由**：过夜无人值守场景下，ComfyUI 可能因显存溢出、驱动重置、节点错误而中断。若无断点续传，一次崩溃会导致前几小时成果全部丢失，M4 里程碑必然滑期。
- **修改建议**：a) `gen_shots.py` 维护 `state.json`（或检查输出文件存在性），已成功落盘的 `shot_id` 自动跳过；b) 对单张图的 ComfyUI 提交/轮询增加 3 次重试与指数退避；c) 增加“心跳”检测，若 ComfyUI 连续 5 分钟无响应，自动重启 ComfyUI 进程（或至少发告警）并继续队列。

**P1-6 zoompan 运镜的工程质量缺失**
- **问题描述**：方案仅说“ffmpeg（zoompan + concat + 字幕）”，未定义 zoompan 的具体参数、输入预处理、抗抖动策略。
- **理由**：ffmpeg zoompan 滤镜存在已知的亚像素抖动（jitter）和非整数缩放模糊问题，尤其从 1024² 放大到 720x1280 再平移时，画面会出现不规则晃动，显著降低漫剧质感。此外，zoompan 对 dither、x/y 表达式支持有限，难以精确控制运镜速度。
- **修改建议**：a) 放弃单层 zoompan，改用“scale 放大 + crop + 逐帧 offset”方案，或使用 zoompan+scale 的组合并开启 supersampling；b) 在 `compose.py` 中为每镜头定义运镜曲线（linear / ease-in-out），通过 `sendcmd`/`fade` 动态控制；c) 先用 5 秒测试片段验证运镜平滑度，再批量合成。

**P1-7 音视频对轴与帧率量化误差**
- **问题描述**：方案说“配音先行定时长”，S4 用 ffprobe 实测时长回填 storyboard，但未说明视频片段如何与音频严格对齐，以及 concat 时如何处理帧率量化误差。
- **理由**：视频帧率是离散的（如 30fps，每帧 33.3ms），音频时长是浮点数。若简单用 `-t` 截断视频，会导致音视频长度不等；concat 时微小误差会逐镜头累积，30-60 秒片尾可能产生半秒以上声画不同步。此外，edge-tts 输出采样率（可能 24kHz）与视频容器标准（48kHz）不一致，直接封装会引发播放器兼容问题。
- **修改建议**：a) 在 `compose.py` 中，每镜头视频长度必须向上取整到帧边界（`ceil(audio_duration * fps) / fps`），并用 `-t` 精确截断；b) concat 使用 concat demuxer + re-encode，或确保所有中间片段时间基、帧率、像素格式严格一致；c) 音频统一重采样到 48kHz，使用 `aresample=48000`；d) 在 S5 后增加 ffprobe 校验，对比成片时长与 storyboard 累计时长误差 < 100ms。

### P2（建议）

**P2-1 音色分配策略与 edge-tts 角色数量上限**
- **问题描述**：edge-tts 中文优质音色有限（Yunxi/Xiaoxiao/Yunyang 等），方案未定义多角色时的音色分配矩阵与冲突解决规则。
- **理由**：若角色超过 5 人，可能出现音色重复、性别错配、年龄感不符；且 edge-tts 部分音色对旁白/角色混合支持差。
- **修改建议**：建立角色-音色注册表，限制主要角色数 ≤ 5；超出时合并配角或使用同一音色不同语速/音高参数区分；在 `character-cards` 中增加 `voice.fallback` 字段。

**P2-2 音效（SFX）与 BGM 混音（Ducking）缺失**
- **问题描述**：方案 S4 仅生成台词/旁白，S5 仅叠加可选 BGM，未提及音效（脚步声、环境声、转场音）及人声 ducking。
- **理由**：漫剧的沉浸感高度依赖音效与 BGM 动态平衡。无人声 ducking 时 BGM 会掩盖台词，无音效则画面显得干瘪。
- **修改建议**：a) 在 `storyboard.json` 中增加 `sfx` 字段（可选）；b) `compose.py` 使用 `sidechaincompress` 或 `volume` 表达式实现人声优先；c) 样片阶段至少加入转场音效（whoosh）与基础环境音。

**P2-3 字幕安全区与样式规范缺失**
- **问题描述**：方案未定义 720x1280 下字幕的字体、大小、位置、描边、安全区。
- **理由**：竖屏底部常有关键画面信息，字幕默认位置可能遮挡主体；不同播放器（抖音/B站/快手）对安全区要求不同，字幕出界会被裁切。
- **修改建议**：制定字幕规范：位置距底 ≥ 200px（避开 UI），字体使用思源黑体/阿里巴巴普惠体，白色 + 黑色描边，单行 ≤ 15 字；在 `compose.py` 中封装 `drawtext`/`ass` 滤镜模板。

**P2-4 视频编码参数未定义**
- **问题描述**：仅说“H.264 mp4”，未定义 CRF、preset、profile、level、码率、帧率、像素格式。
- **理由**：默认参数可能导致文件过大、兼容性差（如 High 10bit 在部分设备无法播放）、或压缩块效应影响线条画面。
- **修改建议**：固定为 `libx264, crf 23, preset medium, profile high, level 4.0, pix_fmt yuv420p, r 30`，音频 `aac 192k`；建立 ffmpeg 编码模板常量。

**P2-5 `storyboard.json` 缺少全局时间轴与转场定义**
- **问题描述**：schema 仅按 `shots` 数组顺序 concat，无全局开始时间、转场类型、转场时长。
- **理由**：纯硬切会显得廉价；且若需调整镜头顺序或插入空镜，缺乏时间轴视图难以快速计算总时长。
- **修改建议**：增加 `transitions` 字段（如 `{"type": "fade", "duration": 0.5}`）与全局 timeline 校验脚本，输出总时长与各镜头起止时间表。

**P2-6 Qwen-Image-2.1 int8 量化画质基线与验收标准缺失**
- **问题描述**：方案未定义“合格分镜图”的可量化标准，人工挑选过于主观。
- **理由**：int8 量化可能导致色彩断层、线条毛糙、文字乱码率上升。无基线则无法判断是模型问题还是提示词问题，调试效率低。
- **修改建议**：建立验收清单：角色相似度 ≥ 80%、无乱码文字、无六指/三眼等明显畸形、线条闭合、色彩与角色卡一致；使用 clip-score 或人工打分表记录。

**P2-7 模型与素材的商用许可证未核查**
- **问题描述**：方案未提及 Qwen-Image-2.1、edge-tts、BGM 库的商用许可限制。
- **理由**：Qwen-Image-2.1 可能有研究/商用边界；edge-tts 明确禁止商用（R3 已提 Azure 替代，但 BGM/模型许可证未覆盖）。样片虽可忽略，但方案应预留合规检查点，避免量产时返工。
- **修改建议**：在 S6 交付前增加 `license_check.md`，记录所有模型/API/素材的许可证与商用边界；样片阶段标记“仅内部验证”，不直接对外发布。

**P2-8 ComfyUI 工作流与 API Schema 未纳入版本控制**
- **问题描述**：方案说脚本进 git，但未提及 ComfyUI 的 workflow JSON、自定义节点、模型文件版本。
- **理由**：ComfyUI 节点或工作流变更会导致 `gen_shots.py` 复现失败，尤其“复用 qwen-image-lowvram 模式”若未固化 API JSON，环境迁移即崩。
- **修改建议**：将 ComfyUI workflow JSON、自定义节点 commit hash、模型文件 checksum 纳入 git 或 `manifest.json`，确保环境可复现。

**P2-9 备份与容灾策略缺失**
- **问题描述**：方案未提及 ComfyUI 崩溃、磁盘写满、临时目录清理策略。
- **理由**：过夜生成时磁盘满（`target/tmp/manhua/`）或 ComfyUI 输出目录无空间，会导致生成中断且无告警。
- **修改建议**：`gen_shots.py` 落盘前检查磁盘剩余空间（> 10GB）；建立临时目录自动清理策略；关键产物（storyboard/角色卡/成片）每日自动备份到第二目录。

- 建议：a) gen_storyboard.py增加多供应商fallback（如本地Ollama小模型、或人工模板）；b) 关键分镜参数（镜头数、时长、台词长度）允许人工YAML覆盖，不完全依赖LLM输出；c) 对免费池调用增加指数退避与熔断，失败超过3次自动切换本地规则引擎。

P1-4: 中文路径在Python+ffmpeg+Windows环境下的编码风险
- 描述：项目工作区路径包含中文（qidiwork-docs/漫剧/<项目名>/），方案仅提到绕开PS 5.1的GBK/BOM坑，但未涉及Python subprocess调用ffmpeg时的路径编码。
- 理由：Windows中文代码页（GBK）与Python UTF-8、ffmpeg static build的UTF-8/GBK混用极易导致文件找不到、字幕烧录参数乱码、concat demuxer路径解析失败。这是Windows本地流水线经典陷阱。
- 建议：a) 所有中间文件与输出目录强制使用ASCII路径（如qidiwork-docs/manhua/proj1/），仅在最终交付时复制到中文目录；b) compose.py中所有ffmpeg调用使用subprocess.list参数（非shell字符串），并显式encoding='utf-8'；c) 字幕文件使用UTF-8 with BOM（或ASS/SRT格式），避免ffmpeg读取中文srt时乱码。

P1-5: gen_shots.py缺乏断点续传与失败重试
- 描述：M4需批量生成40张图并"过夜"执行，方案未说明gen_shots.py是否支持断点续传、单图重试、ComfyUI崩溃恢复。
- 理由：过夜无人值守场景下，ComfyUI可能因显存溢出、驱动重置、节点错误而中断。若无断点续传，一次崩溃会导致前几小时成果全部丢失，M4里程碑必然滑期。
- 建议：a) gen_shots.py维护state.json（或检查输出文件存在性），已成功落盘的shot_id自动跳过；b) 对单张图的ComfyUI提交/轮询增加3次重试与指数退避；c) 增加"心跳"检测，若ComfyUI连续5分钟无响应，自动重启ComfyUI进程（或至少发告警）并继续队列。

P1-6: zoompan运镜的工程质量缺失
- 描述：方案仅说"ffmpeg（zoompan + concat + 字幕）"，未定义zoompan的具体参数、输入预处理、抗抖动策略。
- 理由：ffmpeg zoompan滤镜存在已知的亚像素抖动（jitter）和非整数缩放模糊问题，尤其从1024²放大到720x1280再平移时，画面会出现不规则晃动，显著降低漫剧质感。此外，zoompan对dither、x/y表达式支持有限，难以精确控制运镜速度。
- 建议：a) 放弃单层zoompan，改用"scale放大 + crop + 逐帧offset"方案，或使用zoompan+scale的组合并开启supersampling；b) 在compose.py中为每镜头定义运镜曲线（linear/ease-in-out），通过sendcmd/fade动态控制；c) 先用5秒测试片段验证运镜平滑度，再批量合成。

P1-7: 音视频对轴与帧率量化误差
- 描述：方案说"配音先行定时长"，S4用ffprobe实测时长回填storyboard，但未说明视频片段如何与音频严格对齐，以及concat时如何处理帧率量化误差。
- 理由：视频帧率是离散的（如30fps，每帧33.3ms），音频时长是浮点数。若简单用-t截断视频，会导致音视频长度不等；concat时微小误差会逐镜头累积，30-60秒片尾可能产生半秒以上声画不同步。此外，edge-tts输出采样率（可能24kHz）与视频容器标准（48kHz）不一致，直接封装会引发播放器兼容问题。
- 建议：a) 在compose.py中，每镜头视频长度必须向上取整到帧边界（ceil(audio_duration * fps) / fps），并用-t精确截断；b) concat使用concat demuxer+re-encode，或确保所有中间片段时间基、帧率、像素格式严格一致；c) 音频统一重采样到48kHz，使用-aresample 48000；d) 在S5后增加ffprobe校验，对比成片时长与storyboard累计时长误差<100ms。

P2-1: 音色分配策略与edge-tts角色数量上限
- 描述：edge-tts中文优质音色有限（Yunxi/Xiaoxiao/Yunyang等），方案未定义多角色时的音色分配矩阵与冲突解决规则。
- 理由：若角色超过5人，可能出现音色重复、性别错配、年龄感不符；且edge-tts部分音色对旁白/角色混合支持差。
- 建议：建立角色-音色注册表，限制主要角色数≤5；超出时合并配角或使用同一音色不同语速/音高参数区分；在character-cards中增加voice.fallback字段。

P2-2: 音效（SFX）与BGM混音（Ducking）缺失
- 描述：方案S4仅生成台词/旁白，S5仅叠加可选BGM，未提及音效（脚步声、环境声、转场音）及人声 ducking。
- 理由：漫剧的沉浸感高度依赖音效与BGM动态平衡。无人声 ducking 时BGM会掩盖台词，无音效则画面显得干瘪。
- 建议：a) 在storyboard.json中增加sfx字段（可选）；b) compose.py使用sidechaincompress或volume表达式实现人声优先；c) 样片阶段至少加入转场音效（whoosh）与基础环境音。

P2-3: 字幕安全区与样式规范缺失
- 描述：方案未定义720x1280下字幕的字体、大小、位置、描边、安全区。
- 理由：竖屏底部常有关键画面信息，字幕默认位置可能遮挡主体；不同播放器（抖音/B站/快手）对安全区要求不同，字幕出界会被裁切。
- 建议：制定字幕规范：位置距底≥200px（避开UI），字体使用思源黑体/阿里巴巴普惠体，白色+黑色描边，单行≤15字；在compose.py中封装drawtext/ass滤镜模板。

P2-4: 视频编码参数未定义
- 描述：仅说"H.264 mp4"，未定义CRF、preset、profile、level、码率、帧率、像素格式。
- 理由：默认参数可能导致文件过大、兼容性差（如High 10bit在部分设备无法播放）、或压缩块效应影响线条画面。
- 建议：固定为libx264, crf 23, preset medium, profile high, level 4.0, pix_fmt yuv420p, r 30, 音频aac 192k；建立ffmpeg编码模板常量。

P2-5: storyboard.json缺少全局时间轴与转场定义
- 描述：schema仅按shots数组顺序concat，无全局开始时间、转场类型、转场时长。
- 理由：纯硬切会显得廉价；且若需调整镜头顺序或插入空镜，缺乏时间轴视图难以快速计算总时长。
- 建议：增加transitions字段（如{"type": "fade", "duration": 0.5}）与全局timeline校验脚本，输出总时长与各镜头起止时间表。

P2-6: Qwen-Image-2.1 int8量化画质基线与验收标准缺失
- 描述：方案未定义"合格分镜图"的可量化标准，人工挑选过于主观。
- 理由：int8量化可能导致色彩断层、线条毛糙、文字乱码率上升。无基线则无法判断是模型问题还是提示词问题，调试效率低。
- 建议：建立验收清单：角色相似度≥80%、无乱码文字、无六指/三眼等明显畸形、线条闭合、色彩与角色卡一致；使用clip-score或人工打分表记录。

P2-7: 模型与素材的商用许可证未核查
- 描述：方案未提及Qwen-Image-2.1、edge-tts、BGM库的商用许可限制。
- 理由：Qwen-Image-2.1可能有研究/商用边界；edge-tts明确禁止商用（R3已提Azure替代，但BGM/模型许可证未覆盖）。样片虽可忽略，但方案应预留合规检查点，避免量产时返工。
- 建议：在S6交付前增加license_check.md，记录所有模型/API/素材的许可证与商用边界；样片阶段标记"仅内部验证"，不直接对外发布。

P2-8: ComfyUI工作流与API Schema未纳入版本控制
- 描述：方案说脚本进git，但未提及ComfyUI的workflow JSON、自定义节点、模型文件版本。
- 理由：ComfyUI节点或工作流变更会导致gen_shots.py复现失败，尤其"复用qwen-image-lowvram模式"若未固化API JSON，环境迁移即崩。
- 建议：将ComfyUI workflow JSON、自定义节点commit hash、模型文件checksum纳入git或manifest.json，确保环境可复现。

P2-9: 备份与容灾策略缺失
- 描述：方案未提及ComfyUI崩溃、磁盘写满、临时目录清理策略。
