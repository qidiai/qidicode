## ① 自由审查发现（严重度排序）

### S1-致命｜容器侧真模型冒烟缺失（新代码 14h 直跑）
Phase A 训练/验证脚本均为新代码，本机仅完成 mock 冒烟（tiny 随机模型、同接口）。mock 无法覆盖：transformers 5.18/qwen3_5 真实前向、48×GDN+16×full 混合注意力的 KV cache 路径、52G BF16 加载、单卡 58G 显存峰值、LoopNorm 在 60-63 层（3lin+1full）的实际接线、LoRA 注入点与梯度流、kill-resume 幂等。本项目历史已多次惩罚“新代码直跑长任务”模式。**14h 双臂实跑前必须有一次容器侧真模型冒烟**（≥10 步前向+反向+验证断言全路径）。

### S2-高｜裁定 1 延伸规则“单调放大”无操作化定义
C 线预注册：E3 Δ∈(0,2.0%) 且 E1→E3 Δ 单调放大 → 授权续跑。但三个点的“单调”在 bootstrap 噪声下不可判定：是点估计符号序列？CI 不重叠？趋势检验？无操作化则延伸规则不可执行，且引入审计不可重复性。需补判定算法。

### S3-高｜重分词必要性与 token 数重算
C 线“8192 词表 token 喂 248K 模型=分布外乱码流”论断**成立**：token id 虽合法，但 8192 词表的切分边界与 Qwen 预训练分布完全不一致，PPL 绝对值与 LoRA 适配目标均扭曲。反方“两臂同吃乱码流、相对差仍 informative”仅部分成立——相对差可测量，但 loop 对“乱码流”的重执行 pattern 与对“自然语言 pattern”的重执行可能非线性不同，外推回自然语言无效。因此重分词必要。但 C 线未要求按新分词重算 token 数：8192 词表 14M token 经 Qwen 248K tokenizer 后，中英混合 wiki 语料上 token 数通常缩水，英文 wiki 可能膨胀；若实际 token 数偏离 14M ±10%，则 28 卡时预算、3ep 训练量、E1/E2/E3 对比点全部偏移。

### S4-中｜裁定 4 “镜像 M3” 缺在档公式
C 线要求 LoopNorm 镜像 M3 T2 25.89 实现，但裁定书未附 M3 LoopNorm 确切公式（直通 RMSNorm？残差式？缩放系数？初始化分布？）。若 M3 实现未随请求包/裁定附档，“镜像”不可执行；且需与 M5.1 §2 LoopNorm(5120) 权威表交叉核对自洽。

### S5-中｜loop 臂 pass-2 dropout 不对称
主臂尾 4 层执行 2 passes，若 LoRA dropout（p=0.05）在 pass-1/pass-2 独立采样，则主臂比对照臂多一次 dropout 随机性，两臂差异不再纯为“loop 执行本身”；若共享 mask，则 pass-2 等效于确定性重算。规格书未明确 loop 内 dropout 行为。

### S6-中｜预算延伸与月额度冲突未预登记
试点 28 卡时 + 延伸 70-100 卡时 + R1/R2 2-4 卡时 ≈ 100-132 卡时；叠加 C 线双轨（120M T2/T0 + 白泽 1.5）占卡，月额度 400 卡时下需预登记延伸触发优先级与 R1/R2 排期冲突时的降级路径。

### S7-低｜R1/R2 三角归因的数据子集闭合风险
三角设计：R1（原数据+原 init）、R2（同数据+恒等 init）、台式机 P0 复测（identity init + mini 子集）。若 P0 复测的 mini 子集与 R1/R2 的 20K chunks（seed 42）不同源，则第三格无法与 R1/R2 合并定位 G1 反转，三角不闭合。
