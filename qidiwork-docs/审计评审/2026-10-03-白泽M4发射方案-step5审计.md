# 白泽 M4 发射方案 Step5 审计报告

**审计结论：当前不满足正式发射条件。** 存在 2 项 BLOCKER、4 项 HIGH；在基准去污染证据、发射顺序/门禁、遗忘门评估防护、PAD 注意力掩码、768 截断行为闭环前，不应启动正式 SFT。

## ① 自由审查发现（严重度排序）

- **[BLOCKER] 去污染“0 剔除”不能作为干净证据。** `prep_sft_data.py` 中 `--eval-prompts` 默认为空，且注释表明该参数用于“启用去污染”；材料未提供实际调用命令或日志。若未传该参数，“0 剔除”可能源于检查未运行。伪样本仅覆盖“抄袭 prompt / 正常中文”，未覆盖改变量名后的代码泄漏、部分函数泄漏、测试用例泄漏、规范解答泄漏等真实形态。词级 4-gram Jaccard 大于 0.5 的阈值也偏高，敏感性未验证。

- **[BLOCKER] 发射顺序与资源占用存在矛盾，pgrep 守卫不是发射门。** D 称设备 1 为“冒烟 → seed 队列”，但 E 称“seed43 已接棒设备 1”，同时 v3 又要“今晚重冒烟验门”。二者若共用设备 1，则顺序不成立。`seed_queue.sh` 仅用 `pgrep -f train_sft_m4` 等待，无法证明冒烟通过、遗忘门通过或产出锁定文件；字符串匹配还可能被无关进程误伤。

- **[HIGH] 遗忘门可被 NaN、空批或 PAD 污染假通过。** `eval_lm_ppl` 在 `n_batches=0` 时返回 ppl=1；使用 `CrossEntropyLoss(ignore_index=-100)` 时，若整批标签均为 -100，损失会变为 NaN，而代码无 NaN 断言，后续“大于阈值才 FAIL”的比较可能不触发。此外预训练 val chunks 若含 PAD，代码只忽略 -100，不忽略 PAD=0，PAD 位置会进入 LM 损失。

- **[HIGH] v3 批内局部 PAD 仍未解决无注意力掩码问题。** PAD 率从 81.6% 降到 9.5% 只降低污染面，但 C 明确“模型 forward 不支持 mask”。只要批内存在 PAD，非 PAD 位置仍可能通过注意力被污染。需实现 key padding mask、精确同长批或 packing，而不能以“PAD 率下降”结案。

- **[HIGH] 768 截断可能产生无标签样本，且超出预训练上下文。** `tokenize_sft` 在超长时直接截断 `input_ids` 与 `labels`；当 prompt 长度已达 `max_len` 时，`labels` 可能全为 -100，该样本 silently 不产生损失。p99=793 大于 768，且预训练 ctx=256，长样本既可能丢 EOS，也属于长度外推。

- **[HIGH] 评测执行环境不安全且 NPU 路径未实跑。** 自报 subprocess 非安全沙箱；HumanEval/MBPP 会执行模型生成代码，必须限制网络、文件、进程、超时与资源。`eval_m4` NPU 路径未实跑，可能导致正式评测结果与冒烟不一致。

- **[MEDIUM] 看门狗存在日志格式变化、无 alpha、挂死等假阴性。** `alpha_watch.sh` 依赖 `grep alpha= log | tail -1` 及后续解析；日志格式变化、轮转、进程挂死但 alpha 未更新时，看门狗可能永不触发。PID 获取方式未在内联片段中证明可靠。T3 已处决，但 seed 队列仍出现 `--variants T2,T3`，需确认守卫是否复盖。

- **[MEDIUM] 遗忘 val 固定前 1000 块，基线测量时机不明。** `load_forgetting_val` 在存在 `val` key 时返回 `vals[:1000]`，非随机/分层抽样；若 val 有序，可能不代表全分布。材料未内联基线调用点，无法证明 26.75 是在任何 SFT 更新前、用同一 code path/设备/子集测得。

- **[MEDIUM] 基座权重版本存在歧义。** A 称 T2 继续到 E15/早停，C 称 base=T2 best“E12 版 27.744，正式用今晚终盘”。若今晚终盘产生更优 T2，则应使用最终 best；若仍为 E12，也需给出最终 step、指标与权重哈希证明。

- **[MEDIUM] `extract_code` 回退逻辑脆弱。** 无围栏时从首个 `def/class/@` 起截取，可能丢失前置 import 或顶层语句；散文中的示例 `def` 也可能被误提取；第一个围栏块不一定是最终答案。需加单测与多围栏/导入场景。

- **[LOW] 数据与训练细节部分无法核实。** replay  token 比例约为 10.24M/(68M+10.24M)=13.1%，称“约 15%”需明确口径；`interleave_batches` 随机插入可能造成局部聚集。SHA256 去重是否在行尾归一后执行、CJK 大于等于 10% 质量门、5cae prompt 泄漏修复、T3 基座自动冻结 alpha 均未在内联代码中完整可见。另 `load_sft_data` 在对话以 user 结尾时会丢弃 trailing user，并改用前一个 assistant 作为目标，虽不致命但影响数据利用率。

## ③ rubric 未触发类说明

未发现或无证据触发以下风险类，**不列为 finding，但不等于已证明安全**：权重外泄、训练数据投毒、硬件安全损坏、CRLF 行尾导致内容损坏、通道监视器误报、软链缺失。其中行尾无损、通道误报已修、软链存在均为自报，需留日志/哈希备查。评测沙箱缺失使“生成代码执行安全”类风险不可排除。

## ④ 处置建议

### 必改
1. **补去污染闭环**：提供 `prep_sft_data.py`/`decontam_check.py` 实际命令，确认对 HumanEval/MBPP 的 prompt、规范解答、测试用例均去污染；做阈值敏感性分析并报告各阈值剔除数，否则不得宣称“0 剔除=干净”。
2. **冻结发射顺序**：在 v3 复冒烟通过遗忘门前，不得启动 seed43/44 占用同一设备或进入正式 SFT；用 PID/lock/门禁产物替代 `pgrep` 字符串等待。
3. **修遗忘门评估**：为 `eval_lm_ppl` 增加空批、NaN、`n_batches`、PAD 占比断言；预训练 val 若含 PAD 必须忽略或掩码；基线必须在更新前同一路径测量并记录子集哈希。
4. **落实注意力掩码或零 PAD**：实现 key padding mask，或采用精确同长批/packing；复冒烟需报告 mask 覆盖率和 PAD 率。
5. **修 768 截断**：对无 completion 标签或 EOS 被截断的样本跳过或拆分，并记录截断率、标签掩码率；明确 768 与预训练 ctx=256 的外推验证结果。
6. **修评测安全与基座版本**：生成代码执行放入无网络/限流/超时沙箱；完成 NPU dry-run；使用 T2 最终 best 并固定 step/指标/权重哈希。

### 建议
- 看门狗改结构化日志/JSON，增加解析失败告警、心跳超时和独立 PID 文件，并测试日志格式变化场景。
- 遗忘 val 改用固定哈希的随机/分层子集，或全量 val；正式报告同时给出 loss、ppl、批数与 PAD 数。
- 增强 `extract_code`：支持 import/顶层语句、多围栏选择、围栏内语言标记与生成文本中特殊 token 清理，并补单测。
- 提升发射门表现力：pass@1 大于等于 5% 过低，建议加绝对下限、置信区间与多次种子；中文 3 prompt 人工评建议扩样。
- 行尾归一后再做 SHA256；补 log 证明 kana、长度门、CJK 质量门、5cae 泄漏修复生效。
- 明确 replay 比例口径为“replay/(SFT+replay)”并审计实际 token 级占比。

### 可接受
- IM_START/IM_END 逐轮渲染、completion-only 标签设计、v1 多轮顺序修复方向正确。
- replay chunk 256 定长独立成批、零 PAD 的处理与代码一致。
- T3 在 alpha=2.2 处决、T2 按预注册差值 1.025 入选，在基座版本闭环前可接受。
- v3 长度分桶与批内局部 PAD 作为过渡优化可接受，但不能替代注意力掩码。
