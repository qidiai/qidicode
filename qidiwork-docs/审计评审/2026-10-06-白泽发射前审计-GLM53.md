## 1. RED 项（阻断）

### R-1【RED】pgrep 自匹配：eval 发射门与 A 轨推仓门在真实完赛夜永不通过

**机制证据链**（三段互证）：

1. **agent 以 `sh -c <全文>` 执行每条 cmd**——实证：out_3690 L8 `[ERROR] [Errno 7] Argument list too long: '/bin/sh'`（E2BIG 发生在 execve 层，报错主体是 /bin/sh，证明命令全文作为单个 argv 传入；1MB base64 链因此静默死，即已知雷）。因此执行中的 shell，其 `/proc/<pid>/cmdline` **包含命令全文**，包括 `pgrep -f 'train_sft_m4'` 这段模式文本本身。
2. **`pgrep -f` 按全 cmdline 匹配正则**——模式 `train_sft_m4` 会命中执行 shell 自身的 cmdline（pgrep 只排除自己，不排除父 shell）。
3. **作者本人知道这个雷**——同一探针 cmd#3620/#3660 里，对 agent.py 的检查用的是括号技巧 `pgrep -f '[a]gent[.]py'`（out_3660 L1，模式文本 `[a]gent[.]py` 不匹配自身），而 SFT/A 两处检查**没有**用同等防护——同一命令内防护不一致，恰是自匹配雷存在的反向佐证（没人会无缘无故写 `[a]gent[.]py`）。

**后果推演**：
- `send_eval_launch.py` cmds[2]（eval 发射）：门 `[ -f $BEST ] && [ -z "$(pgrep -f 'train_sft_m4')" ]`——pgrep 恒命中执行 shell → 恒非空 → **永远走 `EVAL_SKIPPED_GATE` 分支，评测不发射**。点火后 out 日志的可识别签名：`EVAL_SKIPPED_GATE`（可见失败，非静默）。
- cmds[0] 的 `GATE=` 同理恒 NOT_YET，且 `SFT_PROC=` 会显示 shell 自身 pid——**与 tail 里 `=== M4 SFT TRAINING DONE ===` 自相矛盾**（日志说完成、pgrep 说活着）→ 以日志为准，pgrep 读数作废。

**修复**（一行×4 处）：括号技巧 `train_[s]ft_m4` / `120m_v1 --variant[s]`；或改用语义门（`grep -c 'M4 SFT TRAINING DONE' /tmp/baize20_sft_v2.log`）。R-009（守卫须对称检验假阴性）：该门控从未对"目标已死"的负路径做过任何测试——全部 12 份探针 out 日志（3570-3720）中，pgrep 目标进程每次都活着，假阴性路径零覆盖。
