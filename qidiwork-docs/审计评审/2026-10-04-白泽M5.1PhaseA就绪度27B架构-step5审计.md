白泽 M5.1 Phase A 就绪度 v2 Step5 审计报告

## 一、自由审查发现（按严重度排序）

**1. [S1-致命] pp2 大额投入前缺失吞吐可行性闸门**
通报将 2-5× 吞吐惩罚仅作“记录在案”，未在 pp2 冻结/大额投入前设置实测吞吐闸门。Phase A 原预算 44-88 卡时/臂，若惩罚兑现将膨胀至 ~90-440 卡时/臂，直接撞穿双账号月额度 400 卡时。缓解路径（AscendC 融合核 workstream、降 seq/batch、换基座）均未评估。pp2 实现已开工，但“先测吞吐再投入”的闸门不存在。

**2. [S1-高] R-A 层型分布图与决策树滞后于 pp2 开工**
C 线要求“pp2 冻结切分点之前”出 64 层层型分布图，但通报明确“v3 由编码手实现中”，执行顺序与声称顺序冲突。更关键的是，尾 4 层三种情形（全线性/混合/全全注意力）的决策树、loop_start 移位准则、pass 边界状态语义（携带 vs 重置）均未预注册。若 60-63 为线性注意力，loop 语义质变，机制主张与专利文本直接受影响。

**3. [S2-高] 手工双卡流水线无框架护栏，正确性断言缺位**
无 deepspeed/peft 依赖意味着无框架级 pipeline 校验。材料未包含：双卡 pipeline 输出 vs 单卡逐层输出逐位一致断言、LoRA 梯度路径经流水线回传验证、激活 checkpointing 跨 stage 语义说明、recurrent state 层边界确认（split 点不切断 inter-pass 组件与尾层同卡）。实现正确性目前仅依赖编码手自觉。

**4. [S2-中] P3 v3 扫描判据不充分：峰值合格不等于长跑/吞吐合格**
v3 扫描计划仅明确“双卡峰值”，未纳入吞吐实测（卡时重算的唯一输入）与长跑稳定性（分配器碎片/HBM 缓涨）。55G 峰值判据 + batch{1,2,4}×seq{2048,4096} 网格无法排除“扫描期合格、长跑 OOM”或“峰值过判但吞吐崩至卡时爆雷”的假阴性。

**5. [S3-中] inter-pass 组件“层型无关”声明遗漏量纲重标定**
C 线确认组件为 hidden-state 级操作、不触碰层内注意力机制，属实；但忽略 max_r2=100/eps=1.0 等常量按 28M/全注意力/6144 假设推导，在 27B/5120/实测激活分布下须重新推导。M5.1 §2 已有此条，回执未强调，存在“结构无关但量纲相关”的认知缺口。

**6. [S3-中] VL 视觉塔剥离路径未评估 5.18 类构造风险**
text_config 嵌套结构下，transformers 5.18 的 Qwen3_5ForCausalLM 类可能强制构造 vision 路径。材料未验证“剥离 text backbone 单独加载”的可行路径，存在环境级 surprise 风险。

**7. [S3-低] 单卡余量 1.4G 算术链不闭合**
通报称权重外余量 ~10.4G，加 inter-pass 优化器态 ~1.9G 后余量 1.4G。10.4 - 1.9 = 8.5G，与 1.4G 不符，存在未列明扣除项或计算错误。

## 四、处置建议

### 必改（pp2 投入前置闸门）

- **G1 [S1]**：在 pp2 冻结切分点/大额投入前，完成 64 层层型分布图；预注册尾 4 层三情形决策树（全线性/混合/全全注意力）与 loop_start 移位准则；预注册 pass 边界状态语义（携带 vs 重置）并附零成本断言测试。未完成则暂停 pp2 切分冻结。
- **G2 [S1]**：v3 扫描必须同时输出**实测吞吐**（step time / tokens/s）与**长跑稳定性**（≥预设步数 HBM 监控，覆盖分配器碎片）。基于实测吞吐重算卡时预算；若 Phase A 任一线程超月额度 50%，强制触发缓解路径评估（AscendC 融合核/降 seq·batch/换基座）并重开会签。
- **G3 [S2]**：pp2 流水线代码必须附带正确性断言：双卡 pipeline 输出 vs 单卡逐层输出逐位一致（至少覆盖首 3 层 + 尾 4 层）；LoRA 梯度路径经流水线回传断言；激活 checkpointing 跨 stage 语义文档化；确认 split 点不切断 inter-pass 组件与尾层同卡。

### 建议

- **S1**：C 线补 inter-pass 组件量纲重标定评估（max_r2/eps 等在 27B/5120 激活分布下重新推导），并回写 M5.1 §2。
- **S2**：VL 视觉塔剥离前，验证 transformers 5.18 Qwen3_5ForCausallm 类是否支持 text-only 构造；若不支持，准备 vision tower 剥离补丁或加载路径回退方案。
- **S3**：澄清 1.4G 余量计算，列明全部扣除项（激活/CUDA context/临时缓冲等）。

### 可接受

- 5120 维度修订与 ~113M/0.43% 参数预算算术基本属实。
- P3 v3 手工 32+32 切分路线（零安装风险）同意。
- 词表未取在 Phase A 不受阻，Phase D 前闭环即可。
