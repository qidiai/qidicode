## 2. 机制还原（核心）

### 定位
`F:\代码\导入数据\闲置算力系统\worm_knowledge_engine\organism.py`（33,543 字节，2026-06-26 10:45:21）

### 架构
```
Organism 生物体 = 知识树(身体/记忆) + 蠕虫群(大脑) + 蚁群(感官) + 爬虫(手脚)
自主循环 = 心跳（不用人戳，自己活着）
睡眠做梦 = 夜间维护（不是关机，是整理记忆）
白天: 感知→思考→行动→观察→反思→再感知→...
夜晚: 做梦(重放经历)→巩固记忆→修剪废话→灵感(偶尔)
```

### 自回放触发条件（`_should_sleep()`，三者任一）
1. **强制**：`cycle_count % sleep_after_cycles(=20) == 0` —— 每 20 轮必须睡一次（config.py: `ORGANISM_SLEEP_AFTER = 20`）
2. **空闲**：`_idle_streak >= 5` —— 连续 5 轮无新任务
3. **目标全完成 + 饥饿度 < 0.3** —— 不饿且无事可做

入睡后连做 `ORGANISM_SLEEP_ROUNDS = 3` 轮梦再醒（`_sleep()→_dream()×3→_wake()`）；重放源池上限 `ORGANISM_HISTORY_MAX = 500` 条历史。

### 做梦算法（`_dream()`，每轮梦 5 步，全程记入 `dream_log`）
```python
# 1. 重放（REPLAY）— 从白天经历随机抽一条，重新走一遍激活
idx = hash(time + sleep_rounds) % len(history)
old = history[idx]
swarm.think({old.decision: 0.5}, rounds=2, decay=0.5)      # 重新激活该决策概念
if old.outcome > 0.5:                                        # 成功经历
    swarm.get(old.decision).reinforce(0.3)                   # 加强连接（巩固）

# 2. 巩固（CONSOLIDATION）— 三速记忆池代谢
for node in body.nodes if node.hit_count > 5:
    node.fast_pool *= 0.95                                   # 快池微衰减
    node.slow_pool[i] = 0.98*slow_pool[i] + 0.02*medium_pool[i]  # 中池→慢池搬运

# 3. 修剪（PRUNING）— 代谢式遗忘
if age > 3600s and node.hit_count < 2: node.is_dying = True  # 标记衰退
body.prune_junk(max_junk=50)                                 # 删 hits=0 杂条（施工/百科垃圾/代码碎片）

# 4. 灵感（INSPIRATION = 泛化跃迁雏形）— 梦境中共激活→新连接
a, b = random.sample(概念名, 2)
if 未连接 and wa.activation > 0.05 and wb.activation > 0.05:
    swarm.link(a, b, strength=min(wa.act, wb.act) * 0.3)     # 从此两概念有了新边

# 5. 消散 — 所有蠕虫 decay(rate=0.3)（"梦是模糊的"）
```

### 配套机制
- **自进化联动**：`self_evolve.py` 内置规则「睡眠周期调整」——`cycle_count>30` 且 dream phase 记录 `<2` 次 → `tune_sleep` 缩短睡眠周期（"很久没睡觉，缩短睡眠周期"），即做梦频率可自调
- **做梦刷盘**：`knowledge_tree.flush()` 注释"做梦/退出时调用，确保脏数据不丢"；`_replay_log()` 重放增量 JSONL 日志恢复未持久化修改（崩溃恢复）
- **WebUI**：`/api/dreams` 端点返回 `dream_log[-10:]`；前端 🌙 做梦面板（`templates.py`：`chat-dream` 紫色样式、历史记录里 `phase==='dream'` 显示"🌙 做梦: 事件列表"）
- **对话入口**：`dialogue.py` 响应"休息/sleep/睡觉/做梦"关键词
- **主循环历史**：每轮记录带 `phase: 'dream'|'awake'` + `dream_events`（`organism.py:586-634`）

## 5. 三个衔接评估

### 5.1 与 Cadence「做梦自回放」（自记录重放→泛化跃迁）的关系
- **概念同构**：F 盘 2026-06-26 版已是"经历重放→巩固→修剪→灵感新连接"的完整闭环，可视为 Cadence 做梦自回放的**先行原型**。
- **对应与差异**：
  - Cadence 的"自记录重放" ↔ F 盘版 history 重放；但 F 盘版重放源是**运行时自生成的 decision 历史**，不是离线语料记录；
  - "泛化跃迁" ↔ F 盘版 step4"灵感"（共激活→新连接）；但 F 盘版是**随机抽样 + 激活阈值门控**，非因果共现统计——这正是"效果不好"的机制层原因之一；
  - replay 剂量曲线（离线旧语料回放比例）↔ F 盘版睡眠调度（每 20 轮强制 + 空闲 5 轮 + 目标完成）——同类"睡眠调度"设计，剂量维度不同（语料比例 vs 轮次）。
- 注：当前 qidicode 仓库 tracked 文件中 `做梦/自回放/cadence/replay/睡眠` **全部零命中**（git grep 验证）——Cadence 做梦自回放目前是主理人口述设计，尚未落本仓库代码。

### 5.2 白泽复用/复活评估
- **可跑性**：高。纯 Python、轻依赖（numpy/playwright/flask/requests）、包内相对导入、有 `__main__.py` 入口；复活 ≈ 拷贝 `worm_knowledge_engine/` + `data/` 即可 demo。
- **真正瓶颈不是代码是数据**（见 §4）。
- **复活建议**：① 保留 `_should_sleep/_dream` 状态机骨架接入 Cadence；② 重放源换成 Cadence 的自记录流（解决"重放源是自生成历史、密度低"的问题）；③ **灵感步骤从随机抽样改为基于重放共现统计的连接**（解决随机碰撞无效问题）；④ 达标线：history ≥ 5000 条多样经历 + 活跃概念 ≥ 300，再谈泛化效果。

### 5.3 专利在先证据价值
- **在先时间戳链**：2026-06-26 同日 02:49（self_evolve 做梦触发）→ 02:59（config 睡眠参数）→ 03:02（/api/dreams 端点）→ 10:45（organism._dream 完整实现）→ 14:28（知识树做梦刷盘/日志重放）；2026-07-02/03 拷贝入启迪白泽。若外部类似"AI 睡眠/做梦回放/离线自回放泛化"工作公开日晚于 2026-06-26，本套即发明人在先研发证据。
- **风险与动作**：无 git 历史 → 证明力打折。建议：立即对两个 F 盘目录做 tar+SHA256+时间戳归档；并把 `organism.py::_dream()` 核心实现作为在先存档提交进当前仓库（新增存档文件，不影响现有代码）。F 盘原件保持只读未动。
