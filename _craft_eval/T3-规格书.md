## Part W3 — pdfcraft CLI 实测（标书场景）

CLI：`G:\程序开发\artcraft\bin\pdfcraft-0.6.0-windows-x64-portable\pdfcraft-cli.exe`

### 1. `--pick` 样本定位（写 `_craft_eval/out/w3/samples.json`）
对 F 盘全量 `glob('F:\\**\\*.pdf', recursive=True)` 容错扫描（pymupdf 打开，异常归 broken）：
- **S1 扫描件**：fitz 打开后首页文本 <20 字 且 page_count>100 且 size>10MB 的最大者
- **S2 普通招标件**：可正常打开、首页文本≥20 字、1MB<size<30MB，优先路径含"招标"字样，按大小排序取中位一份
- **S3 损坏件**：fitz 打开抛异常 且 size>1MB 且路径不含 `$RECYCLE` 的第一份
- 任一类别找不到 → 该样本记 `{"status":"missing"}` 如实输出；解析出的路径只写 samples.json（gitignored），**不写入任何将入库的文件**

### 2. `--encrypt` 加密/解密闭环（F 盘无真实加密件 → 自造）
- 用 pypdf（先 import 验证；不在位则用 pymupdf 的 save encryption）把 S2 复制加密为 `out/w3/s2_enc.pdf`，密码 `w3test`（AES-128 或 RC4 均可，记录用了哪种）
- 实测解密链路：先验证 `pdfcraft-cli info <s2_enc.pdf>` 不带密码会失败（记录 rc/stderr）→ 再按 `pdfcraft-cli tools` 输出的 doc_unprotect JSON Schema 用 `pdfcraft-cli run doc_unprotect in=... password=w3test out=...` 解密出 `out/w3/s2_dec.pdf` → fitz 验证明文页数与文本层与 S2 原件一致
- **先跑 `pdfcraft-cli tools` 看 doc_unprotect 的真实参数名**（可能叫 doc_unprotect/doc_decrypt，参数键名以 tools 输出为准），报告里贴 tools 摘录

### 3. `--bindery` 装订三连（用 S1+S2）
- **combine**：`pdfcraft-cli combine S1 S2 --out out/w3/combined.pdf` → fitz 验证：页数=S1+S2 之和、原书签条目保留（记录前后书签数）
- **watermark**：按 `pdfcraft-cli tools` 里 doc_watermark 的 JSON Schema 加文本水印 `投标文件W3测试`（参数键名实测为准）到 out/w3/wm.pdf → fitz 抽取某页文本验证水印字样存在
- **split/extract**：`pdfcraft-cli split combined.pdf --every 100 --out-dir out/w3/split/` 与 `extract --pages 1,2 --out out/w3/first2.pdf` → fitz 验证份数/页数

### 4. `--audit` 伪脱敏检测实测（W7b 门禁前置验证）
- 自造**伪脱敏样本**：fitz 对 S2 第 1 页用 `draw_rect` 画黑色矩形盖住一段文字（文本层保留）→ 存 out/w3/faux_redacted.pdf
- 自造**真脱敏对照**：fitz 用 `add_redact_annot` + `apply_redactions()` 真删文本层 → 存 out/w3/true_redacted.pdf
- `pdfcraft-cli audit <file>` 分别跑两个样本：伪样本应**检出**（记录 rc 与输出——audit 发现即 fail 语义，rc 非 0 属预期，如实记录）、真样本应通过
- 结论行写明：audit 能否可靠区分伪/真脱敏

### 5. `--robust` 损坏件鲁棒性（R5 退出码语义实测）
- 对 S3 依次跑 `pdfcraft-cli info / text / render`（render 输出到 out/w3/）：
  - 记录各命令 rc、stderr 前 200 字、耗时
  - 定性：优雅失败（rc=1 + 错误消息）/ panic（rc=101）/ 崩溃（rc 其他/无输出）——对照 v2 §五 R5 的退出码映射表
- 附带：`pdfcraft-cli` 对不存在路径的 info 也测一次（rc/stderr）

### 6. `--report` 汇总
`out/w3/w3_report.md`：每命令一行记录（命令行全参 / rc / 耗时 / 验证证据），全部数字带来源；开头声明"OCR 不在 pdfcraft 能力范围（中文扫描件归 rapidocr），S1 仅用于装订/鲁棒场景"。

### 3. `--w4` stdio 握手验证（w3_run.py 子命令）
对三个 craft MCP server 各做一次：
- subprocess.Popen，stdin 写 JSON-RPC：`initialize`（params: protocolVersion="2025-06-18", capabilities={}, clientInfo{name,version}）→ 读到含 `result.serverInfo` 的响应
- 写 `notifications/initialized` → 写 `tools/list` 请求 → 收 tools 数组
- 记录：serverInfo.name/version、tool 数量、tool 名称列表、总耗时；单步超时 30s，超时记录并 kill
- 完整往返 JSON 存 `out/w4/handshake_<name>.json`；汇总 `out/w4/w4_report.md`
- **W4 只验握手面（initialize+tools/list），不做文档操作闭环**（单 Session 生命周期管理属 W5 craft_bridge 范围）
