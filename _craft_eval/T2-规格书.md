## 功能规格

### Part A0 — convert→pdf 文本层探针（新发现，先做）
- 样本：3 份——**样本 1 = "指挥官已复现丢字"的那份安置小区类技术标文件**（真实身份不入库：运行期由 env `A0_SAMPLE1` 注入，未设置则 SKIPPED 如实记录）+ 从 W2 records 选 A 层 2 份（truth_norm 最大与中位的，路径运行期从 records 解析，seed=20261013）
- 每份：① `wordcraft-cli convert <docx> out/t2/pdf/a0_<n>.pdf`；② 三路文本抽取：wordcraft-cli `text`（基线）vs pymupdf 逐页拼接 vs pdfplumber（先 `import pdfplumber` 验证在位，不在则单路并注明）；③ 全部去空白后算：fitz 保留率 = len(norm(fitz_text))/len(norm(wc_text))、pdfplumber 同理
- 产物 `out/t2/convert_pdf_textprobe.md`：三路对比表 + 丢失样例片段（每份 ≥3 处，含上下文前后各 10 字）+ 结论行：`PDF文本层【完好|轻度丢失|重度丢失】`（阈值：≥99% 完好 / 95-99% 轻度 / <95% 重度）
- **此探针只量化不修复**；若判"丢失"，输出一行 R21 候选登记文案供指挥官采用

### Part A — 表格线判据补课（核心）
1. **选样**：读 `out/manifest.json`（W2 的 45 份 A/B/C），解析各 docx 的 `word/document.xml` 筛 `w:tbl` 存在者（双路审计实测 38 份），分层配额 A6/B2/C2，`random.Random(20261013).sample` 抽 10 份（各池先按路径排序）
2. **wordcraft 侧 PDF**：每份 `wordcraft-cli convert <docx> out/t2/pdf/wc_<idx>.pdf`（超时 300s；rc≠0 记 fail 跳过该份）
3. **WPS 侧 PDF**：`t2_wps_child.py` 子进程逐份导出：
   - 模式参考 doc_exporter.py:1095（`win32com.client.Dispatch('KWPS.Application')`，Visible=False，Documents.Open → ExportAsFixedFormat PDF → Close/Quit；WPS 打开密码参数不需要——这批无加密）
   - 输出 `out/t2/pdf/wps_<idx>.pdf`；每份开始/结束 append 一行进度到 `out/t2/pdf/wps_child.log`
   - **父进程看门狗**（t2_run.py 内）：启动 child（subprocess，隔离）后监视该 log，单份 300s 无新进度行 → `taskkill /PID <pid> /T /F` 杀树，该份记 `wps_timeout`，child 自重启续跑剩余份（参考标书软件 8-22 看门狗经验：主进程不碰 COM、子进程逐文件写进度）
   - Dispatch 抛异常 → 该批记 `wps_unavailable`，**降级**：该份仅做 wordcraft 单侧线段密度检测（coverage 记 null，点检表标"无对照"）
   - child 内所有写路径同样经断言限制在 `out/t2/pdf/` 下
4. **页对齐**（双侧 PDF 均有的份）：pymupdf 逐页 `get_text()` → 去空白 → 4-gram 集合 → wc 页 vs wps 页 Jaccard；每 wc 页取最优 wps 匹配，≥0.35 算对齐成功（A0 已证 wc-PDF 文本层可能丢字——n-gram 模糊匹配正是为此设计，阈值放宽）；对齐失败页如实记 `unaligned`
5. **选页**：每份取"对齐成功 且 wps 侧线段数最多"的 3 页（候选不足 3 取实际数）
6. **渲染对照**：双侧同页 pymupdf 192dpi PNG → `out/t2/pairs/<idx>/wc_p<N>.png` + `wps_p<N>.png`
7. **线段检测**（PIL，写死参数）：灰度化，阈值 <128 为暗；横向线=同一行连续暗像素 run ≥ 页宽 8%；纵向线=同列 run ≥ 页高 8%；输出每页 h/v 线段列表（中心坐标+长度）
8. **覆盖率**：WPS 每条线段在 wc 侧找匹配（同向；中心距 ≤2.5% 页尺寸；长度比 ≥0.6）→ `coverage = 匹配数 / WPS线段总数`；页 PASS=coverage≥0.90；文件 PASS=≥2/3 选页 PASS 且无 coverage<0.5 的页
9. **判据裁决**：`≥9/10 文件 PASS` → 表格线判据 PASS；wps_unavailable/wps_timeout 份不进分母、单列如实
10. **产物**：`out/t2/tableline_report.md`（点检表：文件×页 → WPS线段数/匹配数/coverage/裁决 + 每数字带来源字段[命令/PNG路径/检测参数]）+ `tableline_report.json`
11. **附注 spot check**：抽 2 页用 `wordcraft-cli render --page <N> --scale 2` 生成原生分页 PNG 存 `out/t2/pairs/<idx>/native_pN.png`，与 wc-PDF 渲染页并排，报告里注明"渲染一致性由指挥官视觉复核"

### Part B — 10 份字符级 diff 抽验
- 固定 3 份机制样本：records #2、#33、#34（txbx/delText/w:sym 三机制代表）+ 分层补齐 A4/B2/C1（seed=20261013，排除 truth_norm=0）= 10 份
- 每份：difflib `SequenceMatcher` truth.raw → craft text 的段级 diff；每个缺失/多出段用 XML 解析归因（在 w:txbxContent / w:delText / w:sym run 内？逐段判定）；输出"差异全部可归因 / 存在未解释差异（列段）"
- 产物 `out/t2/char_diff_report.md`：10 份逐一表格 + 汇总（可归因率）

### Part C — harness 修复
1. `truth.py`：`del_chars` = Σ(旧式 w:del 祖先下 w:t 长度) + Σ(w:delText 文本长度)；新增 `sym_count` = w:sym 元素计数；返回 dict 增两键，其余键不动
2. `metrics.py`：`completeness` truth_norm_chars==0 且 craft 空 → `ratio=None`（语义：N/A 空对空）；truth==0 且 craft 非空 → inf（维持）
3. `run_w2.py`：record 增 `del_chars`/`sym_count` 两字段（来自 truth 返回）；`_verdict`/报告逻辑不动（`_finite` 已排除 None，空文档自动出均值——预期效果：A 层 mean 直接=0.9993、n_measured=23）
4. `selftest.py` 新增：① w:delText fixture（底层 XML 注入新式修订删除）断言 del_chars>0；② w:sym fixture 断言 sym_count>0；③ metrics：truth=0&craft="" → ratio is None；truth=0&craft="x" → inf
5. **冻结**：sampling.py 全部、cli.py 全部、run_w2 的报告聚合/safe_write/verdict 逻辑

### Part D — 重跑 W2（修复后）
`python _craft_eval/run_w2.py --run`（seed 不变 → manifest 不变）：预期 A mean=0.9993、n_measured=23、B=1.0073、C=0.9998、45 ok、U+FFFD=0、#31-#34 的 del_chars>0、#9/#22 completeness=null。产出覆盖旧 report（预期内）。
