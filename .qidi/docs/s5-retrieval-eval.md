# 白泽 S5 记忆检索质量评估（2026-08-27，真实语料实测）

> 结论先行：**工程链路（路由）精准稳定；检索质量未达生产标准**。
> S5 是短文本对相似度模型，在真实记忆库（长文档）上弱于字符 bigram TF-IDF 词法基线。
> 架构已做到模型可插拔，换后端零链路改动。

## 测试设置

- 语料：真实记忆库 619 块（session 513 / workspace 104 / global 2），
  长度中位 **352 字**，p75=527，最长 1448 字
- 查询 16 条，三类：语义改写（10）/ 错别字（3）/ 精确关键词控制组（3）
- gold 判定：top-k 命中包含 gold 关键词的 chunk
- 全部走 8800 真实 API（与生产同路径）

## 引擎约束（源码级发现）

`baize_vector.py`:
- `_MAX_LEN = 96` —— **每段文本只取前 96 字**，超长直接丢弃（73% 的中位 chunk 内容不可见）
- `_CHAR_MOD = 4096` —— `ord(c)%4096` 字符哈希词表（不同汉字碰撞共享 ID）
- 参数量 ~2.42M；输出 1024 维 L2 归一化

## 结果

| 方法 | hit@1 | hit@5 | 说明 |
|---|---|---|---|
| S5 向量 | 3/16 | 5/16 | |
| FTS5（unicode61，OR 尽力） | 3/16 | 3/16 | 全部来自 ASCII 精确 token；中文 FTS ≈ 0 |
| RRF 融合（向量+FTS） | 4/16 | 7/16 | 融合确实增召回 |
| **字符 bigram TF-IDF 基线** | **8/16** | **12/16** | 无语义的词法基线，明显胜出 |

关键证据：
- **gold 可见性**：134 个 gold 关键词出现点仅 80 个在 96 字窗口内（54 个模型根本看不到）
- **窗口内可见也排不上**：SectColors 在位置 67（窗口内），唯一 gold chunk 仍排 #151 → 不只是截断问题
- **向量空间压缩**：随机块两两余弦中位 **0.782**（p95=0.889）——相关/不相关分数区间严重重叠，判别力不足
- **窗口均值池化救不回**：96 字窗×步长48 均值池化原型 hit@1/5 = 3/3，多查询大幅劣化
  （ATOMCODE #1→#34、水墨 #22→#104）——均值稀释主导语义
- **英文疑似 OOD**："water ink shader" top-1 给不相关英文块打 0.871

S5 实测有效场景（与成果包宣称一致）：
- 错别字 + 词面重叠充分："虎王运地图标注" → #1（云→运 仍命中）
- 跨语言："water ink shader for the game" → 水墨 #10（TF-IDF #73）
- 稀有精确 token：ATOMCODE_SIG_INVALID → #1

性能（台式机 CPU）：619 块 4.3s（144 items/s），单查询 ~130ms —— 性能完全够用。

## 为什么成果包基准（0.786/54对）与真实检索差距大

54 对基准是**短句 vs 短句**的 curated 相似度任务；记忆检索是**短查询 vs 长文档**的
rank-retrieval 任务——截断损耗 + 容量瓶颈 + 文体域差（口语问题 vs 结构化 markdown）叠加。

## 建议

1. **短期（生产）**：8800 后端换 bge-m3（同为 1024 维，`config.toml` 零改动，
   `dimensions=1024` 不变，qidi 会话启动全量重索引自动生效）。模型 ~2.2GB，
   台式机 CPU 索引 619 块预计 1-2 分钟。
2. **中期（研究方向）**：S5 补长文本能力——滑动窗口 + 注意力池化（而非均值），
   或扩容词表消除哈希碰撞，评测集换成 rank-retrieval 口径（本仓库基准脚本可直接复用）。
3. **保留价值**：S5 在错别字/网络用语/跨语言短对上确有优势，可作为查询改写或
   短文本专用组件，与通用模型互补。
