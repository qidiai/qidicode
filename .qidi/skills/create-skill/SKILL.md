# 创建技能

从用户那里交互式收集需求，并在磁盘上创建一个完全可用的 Grok 技能。

## 步骤 1：收集信息

一次只向用户提出以下问题**作为常规对话问题**（不要对自由文本输入使用结构化选项提示）：

1. **技能名称**——请用户输入名称。仅限小写字母（a-z）、数字（0-9）和连字符（-）。必须以字母或数字开头和结尾。长度必须为 2-64 个字符（例如 `deploy-k8s`）。继续之前先验证名称。
2. **范围**——向用户提供两个选项：
   - **项目级（推荐）**：`<repo-root>/.grok/skills/<name>/SKILL.md`——仅在此仓库中可用，可与队友共享
   - **用户级**：`~/.grok/skills/<name>/SKILL.md`——在所有项目中可用
   - 如果在 git 仓库内，默认为**项目级**；否则为**用户级**。
3. **它应该做什么**——请用户描述工作流程、粘贴一个他们反复使用的示例提示，或解释技能应该自动化的任务。

## 步骤 2：起草描述

编写 `description` 前置元数据值，包含：
- 技能做什么（1-2 句话）
- 触发短语和关键词，以便 Grok 知道何时自动调用它
- 斜杠命令名称（例如"在用户运行 /deploy-k8s 时使用"）

将起草的描述展示给用户，让他们批准或编辑。

## 步骤 3：创建目录

运行以下 bash 命令创建技能目录：

```bash
mkdir -p <SKILL_DIR>
```

其中 `<SKILL_DIR>` 是：
- 用户级范围：`~/.grok/skills/<name>`
- 项目级范围：`<repo-root>/.grok/skills/<name>`

如果技能需要辅助脚本，还请创建 `<SKILL_DIR>/scripts/`。
如果技能需要参考文档，还请创建 `<SKILL_DIR>/references/`。

## 步骤 4：编写 SKILL.md

使用 `search_replace` 并传入空的 `old_string` 来在 `<SKILL_DIR>/SKILL.md` 创建文件。

文件必须严格遵循以下格式：

```
---
name: <skill-name>
description: <来自步骤 2 的描述>
---

<markdown 正文，包含说明、步骤、代码块>
```

还使用相同的创建方法编写任何支持文件（脚本、参考文件）。

## 步骤 5：验证并确认

1. 运行 `cat <SKILL_DIR>/SKILL.md` 验证文件是否正确写入。
2. 告诉用户技能已准备就绪以及如何使用它：
   - 斜杠命令：`/<skill-name>`
   - TUI 菜单：`/skills <skill-name>`
   - 自动：当描述与用户意图匹配时，Grok 会自动调用它
3. 告诉用户技能应该在几秒内出现在斜杠菜单中（文件在磁盘上更改时技能会自动重新加载）。

## 指南

- 保持 SKILL.md 正文专注且可操作。它是代理的提示，而不是文档。
- `description` 字段至关重要。它控制自动调用。对触发词要具体。
- 优先引用现有 CLI 工具，而不是编写自定义脚本。
- 不要跳过创建目录。没有目录文件将无法保存。
- 创建文件时始终使用绝对路径，以避免写入错误位置。
