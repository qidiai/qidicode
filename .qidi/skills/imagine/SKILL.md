# Imagine

Grok Build 中两个图像工具调用的指导：

- `image_gen` - 根据文本提示词生成**新**图像。
- `image_edit` - 使用文本提示词和源图像修改**现有**图像。

在考虑或即将调用任一工具时应用此指导。

## 用代码而非图像工具构建准确的视觉素材

1. **图像模型在精确文本、数字和结构方面不可靠。** 它们可以处理短文本或简单布局，但经常会 garbled 文字、编造数字、绘制与数据不匹配的图表条形、指向无物的图表箭头，而且需要精确的内容越多，它们表现越差。详细的提示词不会让它变得可靠，`image_edit` 传递通常也无法修复。因此当结果需要特定文本、数据或结构正确时（来自真实数字的图表、带标签或技术图表、数学解释器、表格、带有真实副本的屏幕），用代码构建素材，你在其中控制确切内容。优先选择 HTML 和 CSS，它们比 Python 绘图提供更好的布局、排版和润色。当只有外观重要时（照片、插图、角色、场景、装饰艺术），图像工具是正确的选择。哪个适合取决于输出需要正确的内容，而不是请求的措辞。

## 验证离散准确性（循环）

当输出必须使特定文本、数字、数据或结构正确时，不要相信第一次结果——在循环中验证：

1. 生成结果（生成，或按照*用代码构建准确的视觉素材*，在代码中构建它）。
2. 检查实际输出——使用图像理解将生成的图像读回（或检查渲染的代码）——并确认每个单词、数字、标签和结构细节都与要求匹配，并且没有重叠、裁剪或超出画布。
3. 如果有任何错误，修复并重新验证：
   - 图像模型产生的 garbled 文本、编造的数字或损坏的布局？不要只是重新提示——它可能会再次 garbled。用代码重建。
   - 代码构建输出中的重叠或裁剪元素？使用自动布局（HTML/CSS）重新布局，而不是手动微调坐标。
   - 否则进行一次有针对性的编辑。
4. 只有在离散内容完全正确时才完成。如果无法做到准确，告诉用户而不是发送错误的东西。

## 核心原则

1. **你拥有提示词。** 如果用户提供了详细的提示词或要求你使用他们的，逐字使用。否则 crafted 最终提示词：将主题放在前面，为情绪、构图、光照和风格提供强有力的高层指导，而不过度指定每个细节，用自然散文而不是关键词标签编写，并以正面描述而不是使用负面提示词。对于编辑，仅描述更改。目标 2-5 句话。
2. **真实人物参考优先。** 永远不要对命名的真实人物或群体使用纯 `image_gen`，包括换脸、海报、卡通和电影或编辑描述。使用 `image_edit` 并附带真实参考，并且永远不要制作非自愿的、性化的或涉及未成年人的 likeness。参见真实人物与参考获取流程。
3. **先用搜索基础关联事实。** 如果请求的任何部分依赖于真实世界事实、身份、品牌或产品、地点、事件或顶部/最新/当前结果，请在生成前搜索网络并将实际验证的详细信息放入提示词中。不要依赖记忆，不要编写像"现任总统"这样的模糊占位符；编写验证过的名称。
4. **为了一致性重用基础图像。** 当同一角色、对象或场景必须在多张图像中出现时，先生成一张基础图像，然后在每次变化中将其用作 `image_edit` 的输入。不要为 recurring 主题从头重新运行 `image_gen`。
5. **优雅地处理失败。** 在审查或安全阻止时，停止；不要重试，不要改写提示词以逃避过滤器。告诉用户它被阻止了并提供不同的方向。如果参考薄弱或结果看起来偏离目标，要说出来并请求上传或重定向，而不是静默迭代。
6. **规划多步骤工作流。** 对步骤排序；仅并行化属于同一步骤的生成。
7. **最后审查。** 确认你打算的生成实际执行了并与要求匹配。
8. **不要假设工具行为。** 不要发明实际未提供的工具参数、返回值或环境功能；验证而不是猜测。

## 选择工具

| 情况 | 工具 |
| ---- | ---- |
| 新图像，无源图像 | `image_gen` |
| 编辑、重新设计、重新着色、添加、移除或扩展现有图像 | `image_edit` |
| 在保留构图的同时迭代先前结果 | `image_edit` |
| 命名的真实人物或群体 | `image_edit` 并附带真实参考，经过网络搜索后 |
| 通用的、发明的或无事实依据的主题，从头开始 | `image_gen` |

经验法则：**无源图像 -> `image_gen`；有源图像 -> `image_edit`。**

## `image_gen`

从文本提示词生成新图像。

输入：

- `prompt`（必需）- 所需图像的完整描述。
- `aspect_ratio` - 例如 `1:1`、`16:9`、`9:16`、`4:3`、`3:4` 或 `auto`。

用于通用或 invented 主题，或创建你稍后将编辑的基础图像。不适用于命名的真实人物；参见真实人物参考优先。

要生成多个变化，使用不同的提示词进行多次 `image_gen` 调用。该工具不暴露 `n` 或 `count` 参数。

## `image_edit`

根据提示词转换现有图像。

输入：

- `prompt`（必需）- 描述所需的转换，并注明应该保持不变的内容。
- `image`（必需）- 一个或多个源/参考图像，作为文件系统路径或 `data:image/...;base64,...` URL。为获得可靠结果，优先选择单个干净的参考。
- `aspect_ratio` - 可选；用于多图像编辑。单图像编辑保留输入图像的宽高比。

用于重新设计、重新着色、添加或移除元素、保留 likeness、转换风格、混合或迭代生成的结果。

要生成多个变化，进行多次 `image_edit` 调用。该工具不暴露 `n` 或 `count` 参数。

## 编写强提示词

大致按此顺序描述：**主题 -> 动作/姿势 -> 环境 -> 风格 -> 构图 -> 光照/情绪 -> 关键细节。**

- 要具体和 concrete；以最重要的元素开头。
- 说明要包含什么，而不是要排除什么。
- 每个提示词使用一个连贯的场景。
- 使用 `image_gen` 时，将 `aspect_ratio` 与用例匹配：`9:16` 用于手机/故事，`16:9` 用于横幅/视频帧，`1:1` 用于头像/图标。

## 真实人物与参考

1. 即使在似乎 obvious 时，也要先搜索网络以确认身份、角色、关系或事件。
2. 使用 `image_edit` 并附带单个强参考。用户上传的照片最好；否则使用高质量的 found 参考并注明来源。`image_edit` 可以接受多个参考，但一个干净的参考更可靠。
3. 如果没有合适的参考，请用户上传一个，而不是从薄弱的基础生成。

## 视频

> 下面的视频工具可能不存在——在调用前验证它们是否可用；如果不可用，用户无法使用 Imagine 进行视频生成。

视频从图像开始——没有文生视频工具。默认使用 `image_to_video`。

**按镜头思考。** 将视频构建为短镜头的计划序列，而不是一个长镜头：

1. **将故事规划为镜头** - 将想法分解为不同的镜头，每个节拍一个。
2. **倾向于频繁的短镜头** - 更喜欢更多的 6 秒镜头而不是更少的长镜头；更多的剪辑使其动态且有趣。
3. **使用 `image_gen` 创建每个镜头的源图像**（或当镜头必须组合参考时使用多图像 `image_edit`），保持角色和设置一致（核心原则 4）。
4. **使用 `image_to_video` 为每个镜头制作动画** - 源成为第 1 帧。

仅当用户要求或镜头真正需要多个参考时，才使用 `reference_to_video`——即便如此，也优先使用多图像 `image_edit` 组合这些参考，然后使用 `image_to_video` 为结果制作动画。

关键行为：

- **提示词 crafting：** 用清晰的相机移动，以现在时描述一个简短、生动的时刻，1-2 句话。
- **最少但有趣：** 将每个镜头保持在一个清晰主题和单一、简单的动作或相机移动上。避免复杂或多动作动画（模型处理得很差）；通过构图、光照和强烈的时刻使镜头有趣，而不是繁忙的运动。
- **复杂的源图像？** 复杂的帧（繁忙的几何形状、精细细节、 heavy 反射）在动画时会变形。如果必须使用它，保持主体固定，仅移动相机（慢速推入、环绕或视差），或将其分解为更紧凑、更简单的镜头。对于新镜头，先生成一个更简单、动画友好的基础图像，而不是动画化繁忙的一个。
- **`image_to_video` 从第 1 帧制作动画**，因此首先使用 `image_gen`/`image_edit` 布置预期的第一帧。
- **宽高比：** 在源图像上设置（`image_gen` `aspect_ratio`）；不要重新裁剪现有视频。
- **时长：** 仅 6 秒或 10 秒（优先 6 秒镜头）；四舍五入到最接近的值。
- **真实人物：** 参考优先 - 从验证过的参考图像驱动视频；永远在没有参考的情况下动画化命名人物。
- 除非被要求，否则不要循环同一片段。

**使用 FFmpeg 组装镜头**，使用流复制以避免质量损失：`ffmpeg -f concat ... -c copy` - 永远不要重新编码。保持每个镜头具有相同的分辨率和帧率，以便复制工作。
