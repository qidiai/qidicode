# 标书满分交付闭环（bid-perfect）

## 产物呈现（强制）

本技能任何产出交付文件（docx/xlsx/pptx/pdf/png 等）的任务：

1. 文件落盘成功后立即登记：
   `python ~/.qidi/skills/office-artifact/scripts/card.py add <产物路径> --skill bid-perfect --note <一句话说明>`
2. 任务最终回复前必须输出卡片总览：
   `python ~/.qidi/skills/office-artifact/scripts/card.py show`
3. 不许只回一行文件路径就结束；卡片失败则降级为 Markdown 表格列出全部产物。


## 解决什么问题

交付目标模糊 + 自批作业：agent 认为方案"达标"就停止，用户被迫反复催促"继续完善"。
本技能把交付条件**硬编码为三条件门槛**：v3 加分项全拿满 + 评分表全因素逐条对标最优
+ 可控差距清单清零，三者全满足才算"做到极致"才允许交付。v3 公式理论最高分不是边际
——我们的边际是所有打分点和所有细节都做到极致。用户不再需要催。

## 使用前提

- 标书已存在（初始稿或待优化稿），或用户提供了招标文件要求从零编写
- 本技能是**闭环控制器**：写作用 /bid-write 的方法论，审计用 /bid-review 的方法论，
  本技能只负责循环控制、达标判定、停止条件、记录留痕

## 核心规则（不可绕过）

1. **分数门槛**：`TARGET = 95`（满分区间 95-100）。审计预估分区间上界 ≥95 才算过线；
   区间上界 90-94 = 达标但非满分，**必须继续优化**；上界 <90 = 不达标，大改。
   **重要**：v3 公式理论最高 86 分（75+3+2+2+2+2，评委折扣2026-09-01废除），达到 v3 上限 ≠ 达到我们的边际。v3 上限只是
   "v3 可量化项拿满"，仍需继续审视评分表全因素 + 可控细节是否做到极致（见规则 6）。
2. **最大循环轮数**：`MAX_ROUNDS = 5`。防止无限循环烧 token：第 5 轮结束后仍未
   进满分区间，输出当前最优版本 + 未达满分的具体原因（哪几项加分未拿满），
   交用户决策（继续加轮或接受现状）。
3. **每轮审计必须独立**：不能拿上一轮的审计结论自我参照。每轮审计按 /bid-review
   七步流程完整重跑（文档解析→关键词命中→去AI化→论证句式→表格图片→数据一致性→
   预估打分），并在审计报告中标注轮次。
4. **优化必须定向**：每轮审计出分数后，列出"距满分的差距清单"（哪几项加分没拿、
   各值多少分），优化只针对差距清单执行，不做全文重写（保留已达标的章节）。
5. **无进展熔断**：连续 2 轮预估分区间上界无提升（涨幅 <1 分）**且**可控差距
   清单也已清零时，判定"剩余差距非当前方案可弥补"（通常为评委主观离散或方法论
   天花板），触发停止条件 4。**注意**：v3 分数无提升但可控差距清单仍有未清零项
   时**不触发熔断**——v3 不是边际，可控维度仍有改善空间就必须继续（见规则 6）。
6. **可控极致原则（2026-08-29 用户指令，优先级最高）**：
   **v3 不是边际**。v3 公式的理论最高分只是"v3 可量化加分项的算术上限"，达到
   v3 上限不等于可以停手。我们的真正边际 = 招标文件评分表所有因素逐条对标最优
   + v3 所有加分项拿满 + 所有可控细节清零，三者全满足才算"做到极致"。
   凡**可控维度**（行文结构、数据闭合、要点覆盖、图表实义、关键词自然分布、
   格式合规、口径自洽、术语统一、衔接自然）仍有实质改进空间的，必须继续打磨
   到位。区分两类差距：
   - **可控差距**：不虚构数据就能改善的（句式、结构、口径、衔接、术语统一）
     → 一律清零后才算"做到极致"；
   - **不可控差距**：评委主观离散、样本归因类指标、以及需要
     编造数据/虚构独家技术才能"改善"的项 → 永远不碰，如实告知用户。
   交付判定 = v3 加分项全拿满 **且** 评分表全因素逐条最优 **且** 可控差距清单
   清零（或逐项注明不可控原因）。**v3 到顶但可控差距未清零 = 不可交付**。

7. **表格格式硬规则（2026-08-30 用户指令，优先级最高）**：凡脚本批量生成/归位/
   修改表格之后，**必须调整表格格式，禁止直接交付**。"列宽均分"这个坑已踩过多次
   （R10 踩过 33 个超宽表、R33 前身 8 个均分表），一律按以下标准处理并纳入终审：
   - **禁均分**：3 列及以上表格禁止等宽列（各列差 <0.15cm 即判均分），必须按
     内容加权分配——列宽 = 版心 17cm ×（该列最长单元格显示宽度 ÷ 各列权重和），
     中文按 2 字符宽计，最小列宽保护 1.2cm；
   - **禁超宽**：表格总宽不得超过版心 17cm（超宽必压回）；
   - **固定布局**：tblLayout=fixed + tblW + tblGrid/gridCol + 逐 cell tcW 四处
     同步写宽，防止 Word/WPS 自动重算回均分；
   - **防合并**：相邻两个 tbl 之间必须插入空段落隔离（WPS/Word 打开相邻无段
     隔离的表格会自动"修复"合并甚至丢表——曾致 7 张表静默丢失）；
   - **终审必查**：审计脚本必须含列宽检查项（0 均分 0 超宽）+ 表数一致性检查
     （doc.tables 数与表题数一致）+ 相邻表检查（0 处），任一不过 = 不可交付。

8. **审计不可裁剪门禁（2026-08-30 用户指令，最高优先级）**：
   **"写了的流程不执行 = 白写"是本项目最大的教训**——bid-review Step 5 明确
   要求"每项工程量与清单 Excel 逐项核对（偏差 0%）"，执行时却擅自降级成
   "查关键词在不在文中"（查出现、不查对错），导致钢筋 581t（清单 3 倍）、
   8 组材料三处矛盾、伪闭合验算、里程碑日期四处矛盾全部漏检，还自称
   "极致达标交付"。为此固化以下铁律：
   - **审计脚本不得由执行者临场自选检查项**：必须使用标准门禁脚本
     `_final_gate.py`，检查域写死（数据真实性含旧错数清零+真值在场、日期
     一致性交叉比对、结构格式、表格六项、图题引、文字质量），43 项缺一不可；
   - **数据真实性必须解析清单 Excel 实测**（`_r37_scan_boq.py` 扫描 E.1 明细
     表生成 `_boq_baseline.json` 真值基线），禁止以"关键词出现次数"替代真值
     核对——查出现 ≠ 查对错；
   - **专业正确性人工核查项**（危大工程界定/规范引用/材质与清单一致）纳入
     交付前自查清单，不得以"无脚本可查"为由跳过；
   - **门禁 FAIL = 禁止交付**，退出码 1，不因"大体通过"放行；
   - 每次文档变更后重跑门禁，最终交付物必须附门禁 43/43 全过的运行记录。

## 执行流程

### 第 0 步：建状态文件

交付任务开始时建立 `_work/` 下的循环状态文件（progress.md），格式：

```markdown
# 满分交付闭环状态：{项目名}
TARGET=极致达标  MAX_ROUNDS=5  当前轮次=0
当前预估区间：未审计
三条件达标状态：[①v3加分项:未审计] [②评分表全因素:未审计] [③可控差距:未审计]
历史：[轮次1] 上界=82  差距=[关键词+3未拿, 去AI化+2未拿, 可控差距:术语不统一/衔接生硬]
```

### 第 1 步：初始审计（Round 1）

按 /bid-review 七步流程完整审计当前方案，得出：
- 预估分数区间（只报区间不报点值）
- 差距清单：逐项列"满分构成"中未拿到的加分项（见下方满分构成表）
- 生成审计报告 `audit_round_N.md`

### 第 2 步：定向优化（分两层执行）

#### 第 2a 步：主 Agent 制定差距清单

只针对差距清单优化，优化手法引用 /bid-write Step 5 写作规范：
- 关键词命中不足 → 每章结论段补三维度词；编制原则段引用评分标准原文
- 去AI化未达标 → 按红线清单逐项消除（段内编号/高频词/AI术语/模板句）
- 论证句式/表格图片 → 按对应规范补强（表格按需提供不设固定总数、每表每图承载真实信息/读图分析）
- 数据一致性 → 跑清单交叉验证，偏差清零
- 每轮优化后在 progress.md 记录改了什么、预期拿回多少分

#### 第 2b 步：派精修子代理逐段落地（2026-08-29 用户指令，优先级最高）

**禁止用脚本批量替换文档内容**。批量脚本无法判断语义上下文，会引入负值、断句、逻辑错误等新问题（庐江项目教训）。

**人工批注入口（2026-08-31 新增，与差距清单合流）**：用户在 WPS/Word 里对产物直接加批注后，先运行 `python ~/.qidi/skills/office-canvas/scripts/canvas.py collect <docx>` 读取批注整改清单（含定位+引用原文），与 AI 审计差距清单**同格式合并**后一起进入本步精修；改完用 `canvas.py verify` 检查响应。图片类反馈用 `canvas.py mark <png> --box x,y,w,h --label "N:说明"` 生成标注图作改图依据。结构/文本自查可用 `office-canvas/scripts/craft_verify.py`（render/inspect/text，详见该 skill）。

正确做法：
1. 主 Agent 把差距清单按"段落级别"拆解成任务项，每项包含：
   - 原文位置（章节/段落编号/行号范围）
   - 原文内容（直接引述，不概括）
   - 修改方向（改为什么样子，给 1~3 个示例句式）
   - 预期拿回分值
2. 派 **coding-default 或 general-purpose 子代理**执行逐段修改：
   - 子代理每次读 1~3 段原文
   - 逐字逐句改写，改完回读确认语义通顺
   - 不允许批量正则替换，不允许跳过原文直接生成
   - 每改完一段立即用 read_file 回读确认
3. 修改完成后，子代理输出"本轮精修清单"（改了哪些段、改了什么、原文→新文对照）
4. 主 Agent 检查精修清单，如有问题立即退回重改

**精修子代理的写入纪律**：
- DOCX 修改必须通过 `_build_docx.py` 管线（改 MD 源文件 → 重跑 build → 格式自检）
- 如果项目没有 MD 源文件，子代理直接对 DOCX XML 逐段落修改（用 python-docx 逐 run 操作）
- 任何修改前必须先 read_file 读原文，不允许凭空编造内容
- 修改后必须用格式自检器（_verify_format.py）跑一遍，FAIL 则修复后重试

**精修环节表格核实（2026-08-30 用户指令，与规则 7 配套，必做）**：

精修 ≠ 只改文字。**每轮精修结束后，必须核实表格状态，六项全过才算本轮完成**：

1. **表数一致**：`len(doc.tables)` 必须等于正文表题数（"表x-x"段落去重数）。
   不一致 = 有表被静默删除或表题丢失（庐江项目曾因此丢了 7 张表才被发现——
   当时只测了页数没查表数，教训深刻）；
2. **表题完整**：每个表上方有"表x-x ××表"标题段，编号连续、无重号、无跳号；
3. **归位正确**：每张表位于其内容对应的章节正文位置，严禁堆在文档末尾；
4. **列宽合规**：0 均分、0 超宽（算法见规则 7）；
5. **正文引用**：每个"表x-x"在正文中有"见表x-x"呼应；
6. **相邻隔离**：全文档 0 处 tbl 直连 tbl（防 WPS/Word 打开时自动合并丢表）。

核实时机：
- 本轮精修**涉及表格**（归位/增删/移动/格式）→ 改完立即核实；
- 本轮精修**只改文字** → 复审（第 3 步）前也要跑一遍表格核实——文字操作
  理论上不动表格，但"理论上不会"不等于"没发生"，表格核实成本极低（一个
  脚本几秒），漏检代价极高（丢表不可逆）。
- 六项任何一项 FAIL → 禁止进入下一轮复审，先修复再重核。

核实实现：用统一表格审计脚本（诊断 doc.tables 数、tblGrid 列宽、表题正则
扫描、相邻 tbl 检测、正文引用正则），输出六项 PASS/FAIL 清单。

- 每轮优化后在 progress.md 记录改了什么、拿回了哪几分、表格六项核实结果

### 第 3 步：复审（Round N+1）

**复审前置门禁**：先跑表格六项核实（表数一致/表题完整/归位正确/列宽合规/
正文引用/相邻隔离，见第 2b 步），任一 FAIL 不得进入本步审计——先修复表格
再复审，防止带着结构损伤打分（损伤文档的分数没有意义）。

重新完整审计（规则 3），对比上轮：
- 分数上界提升 → 继续下一轮或达标结束
- 分数上界不升但可控差距有改善 → **不算无进展**，继续优化（v3 不是边际）
- 分数上界不升且可控差距也无改善 → 熔断计数 +1
- **达标判定（三条件全满足才进入交付）**：
  ① v3 所有加分项已拿满（达到 v3 理论上限）
  ② 招标文件评分表所有因素逐条对标最优
  ③ 可控差距清单清零（或逐项注明不可控原因）
- 轮次 >5 → 停止条件 2，输出最优版本 + 剩余差距说明

### 第 4 步：交付输出

只有触发以下四条之一才准交付，且交付物必须附带最后一轮审计报告：

1. **极致达标（理想）**：v3 所有加分项拿满 **且** 评分表全因素逐条对标最优
   **且** 可控差距清单清零——三者全满足才算"做到极致"，才是我们的真正边际。
   v3 到顶但可控差距未清零 = 不可交付，必须继续。
2. **轮数上限**：5 轮用尽，输出最优版 + 剩余差距清单（用户决策）
3. **无进展熔断**：连续 2 轮 v3 无提升 **且** 可控差距也无改善（方法论天花板）
4. **用户主动叫停**：用户明确说停 / 换方向（优先级最高）

交付信息必须包含：最终预估区间、总轮数、每轮分数轨迹（80→84→86→86）、
v3 加分项是否全拿满、可控差距清单是否清零、最后一轮审计报告路径、
仍未拿满的加分项清单（如有）、不可控差距逐项说明（如有）。

## 满分构成对照表（v3 打分公式分解）

| 加分项 | 分值 | 达标条件 | 差距时优化方向 |
|---|---|---|---|
| 基准分 | 75 | — | — |
| 三维度关键词合计 ≥5 次 | +3 | 每章结论段各 1 次 + 编制原则段引用原文 | 补结论段关键词/引用评分标准 |
| 三维度关键词合计 1~4 次 | +1 | — | 升级到 ≥5 次 |
| 去AI化达标 | +2 | 段内编号 <20/高频词 <0.5‰/AI术语 0 | 按红线清单逐项消除 |
| 论证句式达标 | +2 | 数据用论证句式嵌入非括号标注 | 改写数据呈现方式 |
| 图表实义达标 | +2 | 表格图片按需提供（**不设固定总数**），每表每图承载真实信息、被正文引用 + 读图分析 | 补实义图表/删凑数表/加读图段 |
| 四大闭合链全闭合 | +2 | 工期/设备/劳动力/物资链偏差清零 | 跑交叉验证，逐链修复 |
| **v3 可量化项上限** | **86** | — | 此为评委折扣废除后（2026-09-01庐江实证，见bid-review Step 5.5）的加分项算术上限，非交付边际；仍需评分表全因素+可控细节做到极致 |

> **v3 不是边际（2026-08-29 用户指令，优先级最高）**：v3 公式理论最高 86 分
> （75+3+2+2+2+2，评委折扣废除后的算术上限），这只是 **v3 可量化加分项的算术上限**，不是我们的交付边际。
> 达到 v3 上限 ≠ 可以停手。我们的真正边际是三条全部满足：
>
> 1. **招标文件评分表所有因素逐条对标最优**：评分表原文的每一个评分因素，
>    逐条检查是否做到该因素能做到的最好（覆盖最全、论证最实、针对性最强），
>    而非只对 v3 的 5 个加分项负责；
> 2. **v3 所有加分项拿满**：关键词、去AI化、论证句式、图表实义、四大闭合链——
>    v3 能给的每一分都拿到，这只是"v3 项满分"而非"方案满分"；
> 3. **所有可控细节清零**：行文结构、口径自洽、术语统一、格式合规、衔接自然、
>    图表实义（每张图每张表都承载真实信息，非凑数）——凡不虚构数据就能改善的，
>    一律做到极致。
>
> 三者全满足才算"做到极致"，才是交付线。v3 达到上限后仍需继续审视：评分表每
> 个因素是否都做到最优？可控细节是否还有改善空间？有空间就继续优化，**不因
> v3 到顶而停手**。
>
> **计数类指标是体检信号，不是评分规则**：评委"综合考虑、酌情赋分"，不会数
> 表格。禁止因数量差 1 就机械加减分、禁止凑数加空表废图；主评分锚 = 项目招标
> 文件评分表原文的逐因素整体研判。详见 bid-review Step 6.5 使用边界。

## 与其他技能的协作

- **/bid-write**：第 2 步优化时加载其方法论（写作规范/闭合链构造/去AI化红线）
- **/bid-review**：第 1/3 步审计时加载其七步流程与打分公式
- **/check-work**：可用验证子代理独立复核每轮优化后的文档（交叉验证独立审计）
- **独立审计子代理**：每轮审计建议派 explore 子代理重读成稿文档（不带上一轮
  上下文偏见），主 agent 只汇总分数
- **精修子代理（coding-default / general-purpose）**：第 2b 步逐段落地修改。
  专用于差距清单中需要"语义判断+逐字改写"的项（去AI化、标题统一、空节补内容、
  数据对齐等）。批量机械替换（如表头重写、格式统一）仍由主 Agent 脚本执行。

## 记录留痕

每轮结束后，progress.md 更新：
- 轮次、预估区间、与上轮差值
- 本轮改动摘要（改了哪些章节/拿回了哪几分）
- 下一轮差距清单

交付后 progress.md 与全部 audit_round_*.md 归档到 `_archive/{date}/bid-perfect/`。

## 示例对话

用户：「写XX项目施工组织设计，目标是满分标准」
→ 建状态文件 → Round 1 审计（比如 80）→ 差距清单 [去AI化+2, 图表实义+2] →
  定向优化 → Round 2 审计（84）→ 差距 [闭合链+2] → 优化 →
  Round 3 审计（86，v3 上限）→ **v3 到顶但不停手**：可控差距清单仍有

  + 最终可控差距清单=清零 + 不可控差距=评委主观离散说明）。
