# 标书满分交付闭环（bid-perfect）

## 解决什么问题

交付目标模糊 + 自批作业：agent 认为方案"达标"就停止，用户被迫反复催促"继续完善"。
本技能把交付条件**硬编码为分数门槛**：审计预估分未进满分区间（95-100）就不算完成，
必须继续"审计→思考→优化→复审"循环。用户不再需要催。

## 使用前提

- 标书已存在（初始稿或待优化稿），或用户提供了招标文件要求从零编写
- 本技能是**闭环控制器**：写作用 /bid-write 的方法论，审计用 /bid-review 的方法论，
  本技能只负责循环控制、达标判定、停止条件、记录留痕

## 核心规则（不可绕过）

1. **分数门槛**：`TARGET = 95`（满分区间 95-100）。审计预估分区间上界 ≥95 才算过线；
   区间上界 90-94 = 达标但非满分，**必须继续优化**；上界 <90 = 不达标，大改。
2. **最大循环轮数**：`MAX_ROUNDS = 5`。防止无限循环烧 token：第 5 轮结束后仍未
   进满分区间，输出当前最优版本 + 未达满分的具体原因（哪几项加分未拿满），
   交用户决策（继续加轮或接受现状）。
3. **每轮审计必须独立**：不能拿上一轮的审计结论自我参照。每轮审计按 /bid-review
   七步流程完整重跑（文档解析→关键词命中→去AI化→论证句式→表格图片→数据一致性→
   预估打分），并在审计报告中标注轮次。
4. **优化必须定向**：每轮审计出分数后，列出"距满分的差距清单"（哪几项加分没拿、
   各值多少分），优化只针对差距清单执行，不做全文重写（保留已达标的章节）。
5. **无进展熔断**：连续 2 轮预估分区间上界无提升（涨幅 <1 分），判定"剩余差距
   非当前方案可弥补"（通常为评委主观折扣或方法论天花板），触发停止条件 4。

## 执行流程

### 第 0 步：建状态文件

交付任务开始时建立 `_work/` 下的循环状态文件（progress.md），格式：

```markdown
# 满分交付闭环状态：{项目名}
TARGET=95  MAX_ROUNDS=5  当前轮次=0
当前预估区间：未审计
历史：[轮次1] 上界=82  差距=[关键词+3未拿, 去AI化+2未拿]
```

### 第 1 步：初始审计（Round 1）

按 /bid-review 七步流程完整审计当前方案，得出：
- 预估分数区间（只报区间不报点值）
- 差距清单：逐项列"满分构成"中未拿到的加分项（见下方满分构成表）
- 生成审计报告 `audit_round_N.md`

### 第 2 步：定向优化

只针对差距清单优化，优化手法引用 /bid-write Step 5 写作规范：
- 关键词命中不足 → 每章结论段补三维度词；编制原则段引用评分标准原文
- 去AI化未达标 → 按红线清单逐项消除（段内编号/高频词/AI术语/模板句）
- 论证句式/表格图片 → 按对应规范补强（30~44 表/9~12 图/读图分析）
- 数据一致性 → 跑清单交叉验证，偏差清零
- 每轮优化后在 progress.md 记录改了什么、预期拿回多少分

### 第 3 步：复审（Round N+1）

重新完整审计（规则 3），对比上轮：
- 分数上界提升 → 继续下一轮或达标结束
- 分数上界不升 → 熔断计数 +1
- **达标判定**：区间上界 ≥95 → 进入交付
- 轮次 >5 → 停止条件 2，输出最优版本 + 剩余差距说明

### 第 4 步：交付输出

只有触发以下四条之一才准交付，且交付物必须附带最后一轮审计报告：

1. **满分达标**：预估区间上界 ≥95（理想）
2. **轮数上限**：5 轮用尽，输出最优版 + 剩余差距清单（用户决策）
3. **无进展熔断**：连续 2 轮无提升（方法论天花板）
4. **用户主动叫停**：用户明确说停 / 换方向（优先级最高）

交付信息必须包含：最终预估区间、总轮数、每轮分数轨迹（82→87→93→96）、
最后一轮审计报告路径、仍未拿满的加分项清单（如有）。

## 满分构成对照表（v3 打分公式分解）

| 加分项 | 分值 | 达标条件 | 差距时优化方向 |
|---|---|---|---|
| 基准分 | 75 | — | — |
| 三维度关键词合计 ≥5 次 | +3 | 每章结论段各 1 次 + 编制原则段引用原文 | 补结论段关键词/引用评分标准 |
| 三维度关键词合计 1~4 次 | +1 | — | 升级到 ≥5 次 |
| 去AI化达标 | +2 | 段内编号 <20/高频词 <0.5‰/AI术语 0 | 按红线清单逐项消除 |
| 论证句式达标 | +2 | 数据用论证句式嵌入非括号标注 | 改写数据呈现方式 |
| 表格图片密度达标 | +2 | 30~44 表 + 9~12 图 + 读图分析 | 补表格/补图/加读图段 |
| 四大闭合链全闭合 | +2 | 工期/设备/劳动力/物资链偏差清零 | 跑交叉验证，逐链修复 |
| 评委主观折扣 | −2~−6 | 村庄改造 −6 / 房建市政 −2 | 硬损失，靠关键词+表图密度补 |
| **理论满分** | **85~89** | — | — |

> **注意（诚实告知用户）**：v3 公式理论最高 89 分（75+3+2+2+2+2−2）。若用户目标
> 是 95-100，实际追求的是**以 v3 预估满分（85-89）为"内部满分线"**，同时叠加
> 多份高分样本校准特征（巢湖学院 84.87 分样本特征全复现：8 次"结合本工程特点"、
> 44 表 12 图、三大维度词高频）。技能会以**相对满分**（拿到所有可得加分项）为
> 交付线，即 TARGET 相对线 = 理论满分。TARGET=95 在 v3 绝对刻度上不可达，
> 需在 Round 1 审计时向用户说明并确认（默认按相对满分执行）。

## 与其他技能的协作

- **/bid-write**：第 2 步优化时加载其方法论（写作规范/闭合链构造/去AI化红线）
- **/bid-review**：第 1/3 步审计时加载其七步流程与打分公式
- **/check-work**：可用验证子代理独立复核每轮优化后的文档（交叉验证独立审计）
- **独立审计子代理**：每轮审计建议派 explore 子代理重读成稿文档（不带上一轮
  上下文偏见），主 agent 只汇总分数

## 记录留痕

每轮结束后，progress.md 更新：
- 轮次、预估区间、与上轮差值
- 本轮改动摘要（改了哪些章节/拿回了哪几分）
- 下一轮差距清单

交付后 progress.md 与全部 audit_round_*.md 归档到 `_archive/{date}/bid-perfect/`。

## 示例对话

用户：「写XX项目施工组织设计，目标是满分标准」
→ 建状态文件 → Round 1 审计（比如 82）→ 差距清单 [关键词+3, 表图密度+2] →
  定向优化 → Round 2 审计（87）→ 差距 [去AI化+2, 闭合链+2] → 优化 →
  Round 3 审计（93）→ 差距 [评委折扣−6 硬损，剩余闭合链+2] → 优化 →
  Round 4 审计（85-89 区间上界=89=理论满分）→ **达标交付**（附分数轨迹
  82→87→89→89 + 四轮审计报告 + 剩余差距=评委折扣硬损说明）。
