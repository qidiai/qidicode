# 高分方案反推（第一方修正版）

## 定位与纪律（先读，硬约束）

- **视角**：事后解剖高分卷（学习输入端）——与 bid-review（事前预打分）分工：
  事前预估找 /bid-review，事后复盘反推找本技能。
- **Step 0 硬门禁（防脏入库）**：反推对象**必须先声明真实评标得分及其来源**。
  无得分声明 → 全部结论只可表述为"待验证假设"，**禁止产出可入库写作规则**
  ——反推假"高分"会把失分特征当规则（教训在案：中垾坝镇卷曾被预估91-95，实测78.25）。
- **三级证据分层**（引用 bid-review Step 6.8）：硬事实（可复算统计量）可直接陈述；
  推断必须标注依据与置信度；未见方案禁止归因断言。
- **计数指标≠评分规则**（bid-review Step 6.5 纪律同款）：全部指标只作"体检信号"
  与"分水岭对照"，禁止写达标线、禁止"达到X‰即得分"类表述。
- **每条可入库规则必须标注** `[来源:样本名+实测分]`。
- **条件分级类特征标"可选特征"**（84.87真值卷实测分级表述≈0，不构成高分必要项）。

## 输入

| 材料 | 用途 | 必需 |
|:--|:--|:--:|
| 被反推方案文本（docx提取txt/纯txt/PDF提取txt） | 量化指标 | ✅ |
| **实测得分 + 得分来源**（评标结果一览表/评标报告） | Step 0 门禁 | ✅（缺失则降级假设模式） |
| 对应招标文件（评分办法章节） | Step 8 逐条锚定 | 建议 |

## 流程（Step 0 + 8步；①-⑦脚本量化，⑧AI定性）

### Step 0：得分来源声明（硬门禁）

```
python scripts/reverse_metrics.py <方案.txt> --strip-normal \
    --score 84.87 --score-source "评标结果一览表" \
    --site-keywords "泮山苑,10#,Ⅰ区,Ⅱ区,Ⅲ区" -o <项目>/metrics.json
```
无 `--score` → 输出 `mode: hypothesis_only`，后续报告措辞全部按"待验证假设"。

### Step ①：标题树提取（脚本，数字式主线）

数字式层级为主：H1=第X章、H2=X.X、H3=X.X.X、列举=①②③；公文式（一、/（一））
仅作 fallback。统计章/节/子节数 + `【对应评审因素N】`标注数
（84.87卷9处仍漏标因素8/10——标注不全也是失分点）。

### Step ②：编号重置率（脚本）

圈号①-⑨分布——每个 H3/节内必须从①重置，跨节连续递增=编号违规（人工抽查）。

### Step ③：因果链密度（脚本）

"——"出现密度（‰）。**分水岭：84.87卷0.82‰ vs 78.25卷0.23‰（3.5倍差）**。
五类句式模板（人工归类样本，例句自 84.87 校准样本）：
参数→原因 / 约束→决策 / 做法→原理 / 差异→理由 / **原则→边界**
（第五类以实测证据为准，非"区间→原理"）。

### Step ④：数据注入密度（脚本）

量化数据点密度‰ + 阈值参数密度‰。
**反转证伪：78.25卷数据密度(23.1‰)反而高于84.87卷(15.9‰)——
"数字多少"不是得分变量，"数字嵌在哪"才是**（嵌因果链论述里 vs 堆表格里）。

### Step ⑤：验收闭环 + 网状引用（脚本）

验收动作总数（验收/检验/检测/试验/复核/查验/旁站/见证取样）+ 不合格处置数
+ `详见X.X`跨章引用数。**分水岭：详见引用 84.87卷12处 vs 78.25卷4处（3倍）**。

### Step ⑥：禁用词与管理惯用语（脚本）

我方/我们/尽力/争取/综上所述/值得注意=0 ✓；"闭环"按管理惯用语计数
（84.87卷7次仍最高分——语境豁免实证，判定归 bid-review A5 豁免表）。

### Step ⑦：难点三件套（脚本）

`难点N：`（问题定义）→ `应对措施：`（体系化方案）→ `（详见X.X）`（跨章引用）。
**最大结构分水岭：84.87卷 5/5/12 vs 78.25卷 0/2/4**。

### Step ⑧：评分办法逐条锚定 + 分水岭对照表（AI）

1. 读对应招标文件评分办法，将本卷章节逐条锚定评分项（同 bid-write Step 2 对照表口径）；
2. 解读脚本输出的 `ridge_table`（84.87/78.25双参照），标出本卷的高分独有特征与
   反转指标位次；
3. 产出反推报告（结构见下），每条入库级结论带 `[来源:样本名+实测分]`。

## 输出报告结构

```
1. Step 0 声明（mode / 得分 / 来源）
2. 标题树规则（H1-H3骨架 + 评审因素标注覆盖 + 拆解标准归类）
3. 因果链句式库（密度 + 五类样本 + 原文例句）
4. 数据注入规则（密度 + 反转指标解读）
5. 验收闭环与网状引用
6. 难点三件套结构
7. 分水岭对照表（vs 84.87/78.25双参照，硬事实）
8. 可入库规则清单（仅 mode=verified 时产出；hypothesis_only 模式此节改为
   "待验证假设清单"）
9. 三级证据分层声明（硬事实/推断+置信度/未知）
```

## 与生态的衔接

- 反推产出的入库规则 → 喂给 bid-write（写作规范）与 plan_library（知识库）
- 事前预打分与整改 → /bid-review（含 A5 语境豁免后的去AI化读数）
- 评审专家视角挑错 → 青天类人施组审查流程（外部检材，用其机制思想）

## 验证基准

对 84.87 真值卷复跑须复现量级：因果链≈0.8‰、详见引用≈12、难点三件套 5/5/12、
验收动作>150、"闭环"=7、我方/我们/综上所述=0（允许提取误差，方向与量级必须一致）。
