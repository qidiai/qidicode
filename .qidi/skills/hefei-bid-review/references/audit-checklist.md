# 技术标审核清单

## 一、结构完整性检查

### 1.1 评审因素覆盖
- [ ] 10 项评审因素是否全部覆盖（逐项确认章节存在）
- [ ] 每章是否标注对应评审因素编号（如"【对应评审因素N】"）
- [ ] 评分索引表是否存在（含评审因素→章节→响应要点→页码）
- [ ] 评分索引表页码是否与成稿实际页码一致

### 1.2 图表检查
- [ ] 横道图（进度计划图）是否存在
- [ ] 总平面布置图是否存在
- [ ] 网络图（关键线路图）是否存在
- [ ] 工艺流程图是否覆盖关键工序
- [ ] 组织机构图是否存在
- [ ] 图片宽度是否合理（不超过版心，建议 12-13cm）

### 1.3 编号检查
- [ ] 章节编号连续无缺号（1→2→3...→10）
- [ ] 子节编号连续无跳号（1.1→1.2→1.3）
- [ ] 表格编号连续（表1→表2→...→表N）
- [ ] 图编号连续（图1→图2→...→图N）
- [ ] 无编号重复

### 1.4 空标题检查
- [ ] 逐段检查：标题后是否有正文或引导语
- [ ] 有表格的标题后是否补"主要XX详见下表"引导语
- [ ] 空标题数量应为 0

## 二、格式合规检查

> 具体参数以招标文件原文为准，以下为常见标准。

| 项目 | 常见要求 | 检查方法 |
|---|---|---|
| 纸张 | A4 | python-docx sections.page_size |

### 废标红线检查
- [ ] 封面无"XXX"/"××"/空括号等占位符
- [ ] 投标人名称正确（明标须填写，暗标须留空或用规定格式）
- [ ] 日期已填写
- [ ] 无其他投标单位名称/人员姓名（暗标）
- [ ] 页眉页脚无任何标识（暗标：不得含单位名/徽标/可识别水印）
- [ ] 元数据已清理（暗标须检查 docProps/core.xml）
- [ ] 签章位置标注（明标须"盖单位章"）

## 三、内容均衡性审计

### 3.1 章节字数统计

对每章统计**正文字数**（不含表格内文字），判定标准：

| 评级 | 正文字数 | 处理 |
|---|---|---|
| 优秀 | ≥1500字 | 保持 |
| 良好 | 800-1500字 | 可优化 |
| 一般 | 500-800字 | 建议补写 |
| 薄弱 | <500字 | **必须补写** |

> AI 对薄弱章节会判"响应不充分"，该因素可能被某位评委选中关注而打低分。

### 3.2 各因素内容深度检查

**因素1 工程概况**：
- [ ] 项目规模（面积/栋数/层数）与招标文件一致
- [ ] 改造内容分类清晰（拆除/装饰/机电/外立面等）
- [ ] 分栋口径逐栋列出
- [ ] 施工重点难点分析（非空标题）

**因素2 主要施工方法**：
- [ ] 各分部工艺齐全（拆除/结构/装饰/机电/外立面等）
- [ ] 关键工序含量化参数（温度/压力/用量/配合比等）
- [ ] 工序衔接逻辑合理
- [ ] 季节性施工措施（如项目工期含冬季/雨季）

**因素3 物资计划**：
- [ ] 材料清单（分类：装饰/机电/洁具消防/门窗室外）
- [ ] 参考品牌响应表（逐项对照招标文件参考品牌）
- [ ] 供需分析（用量×损耗率=需求量）
- [ ] 分批进场计划（与横道图进度节点联动）
- [ ] 仓储方案（场地受限时的堆场安排）
- [ ] 进退场计划

**因素4 机械设备**：
- [ ] 设备清单（机械+检测测量设备）
- [ ] 配置论证（台数×能力≥工程量，含富余系数）
- [ ] 进出场计划（与进度联动）
- [ ] 校园/特殊环境约束对机械选型的影响
- [ ] 故障应急/备用方案

**因素5 劳动力**：
- [ ] 分区/分栋配工表
- [ ] 高峰人数论证（各工种人数×栋数+管理）
- [ ] 劳动力动态调配机制
- [ ] 劳动力曲线（文字或图形描述）
- [ ] 高峰期保障措施（食宿/交通/工资）

**因素6 质量措施**：
- [ ] 质保体系（组织架构+责任链）
- [ ] 三检制（自检/互检/专检）流程
- [ ] 质量通病防治（针对本项目工序：涂料开裂/环氧空鼓/防水渗漏等）
- [ ] 成品保护措施
- [ ] 隐蔽工程验收制度

**因素7 安全措施**：
- [ ] 危大工程识别清单表（逐类排查 37 号令口径：基坑≥3m/模板支撑≥5m/起重吊装/脚手架≥24m/拆除/暗挖等；表格列：类别/对应本项目部位/规模参数/是否超规模/是否需专家论证/对应方案章节）
- [ ] 危大针对性方案逐项独立成节：支护/搭设方式依据地勘或图纸选定并写明理由；与招标文件/图纸硬约束一致（超12米深基坑放坡条件不足时禁止出现"放坡开挖"）
- [ ] 危大关键控制参数量化：坑边堆载限值(kN/㎡)、监测点位与间距、预警值/报警值(mm)、监测频次
- [ ] 危大保障闭环：专项方案审批→总监审查→超规模专家论证→交底签字→验收挂牌→出险处置（详见 references/weida-gongcheng-checklist.md）
- [ ] 其他安全措施：高处作业/临时用电/零星拆除等（整体拆除工程已归上方危大识别清单）
- [ ] 安全管理体系
- [ ] 专项安全措施（针对项目环境：校园/厂区/交通等）
- [ ] 应急预案
- [ ] 安全费用投入计划

**因素8 工期措施**：
- [ ] 总工期论证（关键线路天数分解）
- [ ] 横道图+网络图双图
- [ ] 分栋/分区交付节点表
- [ ] 赶工措施（资源调配/延长工时/夜间施工）
- [ ] 工期违约金条款响应

**因素9 文明施工**：
- [ ] 文明施工费用计划
- [ ] 围挡/标牌/场地硬化具体方案
- [ ] 噪声控制（分贝限值+时段管控）
- [ ] 扬尘控制（PM10指标+措施）
- [ ] 与总平面图的呼应
- [ ] 特殊环境措施（校园时段/居民区夜间等）

**因素10 总平面布置**：
- [ ] 总平面图（含图例/指北针）
- [ ] 布置说明（逐项引用图例编号）
- [ ] 分阶段平面调整方案
- [ ] 临时设施配置表
- [ ] 交通组织/消防通道

## 四、AI 可读性检查

- [ ] 每章标题是否包含评审因素关键词（便于 AI 匹配）
- [ ] 评审因素编号是否显式标注
- [ ] 量化测算是否用文字写出完整逻辑链（"N台×X能力×Y天=Z≥需求W，富余R%"）
- [ ] 关键数据在正文中至少出现 2 次
- [ ] 无大段抄规范原文（招标文件要求"无需重复编制"）
- [ ] 无重复套话（"为...提供有力保障"等句式不超过 3 次）
- [ ] 无空标题（标题后必须有正文或引导语）

| # | 扣分项 | AI 是否可识别 | 影响 |
|---|---|---|---|
| 1 | 评审因素缺项或薄弱 | ✅ | 该因素掉档 |
| 2 | 数据与清单矛盾 | ✅ | 针对性扣分 |
| 3 | 模板化套话重复 | ✅ | 语言精练度扣分 |
| 4 | 空标题 | ✅ | 内容缺失扣分 |
| 5 | 超页 | ✅ | 格式违规掉档 |
| 6 | 占位符未替换 | ✅ | 编制不完整扣分 |
| 7 | 品牌未逐项响应 | ✅ | 针对性扣分 |
| 8 | 工期逻辑不闭合 | ✅ | 可行性扣分 |
| 8.5 | 危大工程识别缺失/方案与图纸矛盾（如超12米深基坑放坡条件不足却写放坡开挖） | ✅ | **权重最高章节直接丢分** |
| 8.6 | 措施段"重态度轻控制"（加强管理/严格控制等，无量化参数） | ✅ | 措施可验证度扣分 |

> 品牌响应核对的自动化方式：`audit_bid.py` 第三参数传入招标品牌对照文件（每行"类别|品牌1、品牌2、品牌3"，从招标文件品牌参考表逐类转录），脚本逐类输出命中/未响应清单及品牌级命中参考数。注意粒度分工：脚本为**类别级**（每类 ≥1 品牌命中即通过）；品牌级逐项核对（选用品牌是否在推荐范围+正文出现 ≥1 次）仍按 data-verification-guide.md 第三节人工执行。

## 六、雷达风险自查清单（合公信〔2026〕46号第26-30条，2026-09 新增）

平台雷达监测比对含历史投标文件在内的交易数据（第27条），分析报告及时推送智慧监管系统，作为涉嫌围串标初步认定的重要依据（第26、28、30条）；招标人可在招标文件中约定雷达结果的应用方式及处置措施（第29条）。AI 辅助编标场景重点排查：

- [ ] 同错（第26条(二)）：错别字/口径错/单位错是否构成跨投标人同错特征——AI 生成内容的错误特征必须差异化
- [ ] 雷同（第26条(一)）：应由投标人自行编制的内容是否与其他投标人高度相似（共用 AI 工具/模板产出的段落须差异化变换）
- [ ] DNA链一致（第26条(三)）：引用的互联网素材/数据来源是否跨投标人异常一致——数据来源做项目定制化
- [ ] 特有标识外流（第26条(四)）：本单位特有业绩/标准/编号/标识是否可能出现在其他投标人文件（含历史投标文件）——只写本单位真实资料；本单位复用自身历史标书不直接构成异常
- [ ] 报价（第26条(五)）：报价组成独立编制，无跨投标人规律性趋同
- [ ] 操作纪律（第26条(六)(七)(九)）：编制/上传/解密一企一机；计价软件加密锁不借用；保证金从本单位基本账户转出
- [ ] 人员（第26条(八)）：投标联系人/拟派项目管理人员不与其他投标人重叠
- [ ] 招标文件雷达条款：是否约定雷达结果应用方式及处置措施，响应措辞是否对齐

> 定位：投标人自备 AI 工具辅助编标未被合公信〔2026〕46号禁止（办法规制大模型开发应用方），但多家标书出现"同错/雷同"特征将触发雷达线索，须对 AI 产出做差异化审校并对内容真实性负责。

## 七、表间横向闭环自查（AI 评分拉通查所有表，一处对不上=方案不可行）

> 与 data-verification-guide.md（方案↔清单↔招标文件纵向核对）互补：本节查**方案内部表↔表横向闭环**。

闭环场景逐项核查：
- [ ] 工程量 ↔ 工期 ↔ 劳动力：各阶段工程量 ÷ 人均工效 ÷ 阶段工天 = 配工人数；劳动力表、进度计划表、工程量引用三方一致
- [ ] 设备配置 ↔ 工程量：设备台数 × 单台产能 × 工作天数 ≥ 对应工程量（不足则增加设备或延长工期）
- [ ] 材料计划 ↔ 工程量：材料总用量 = 工程量 × 单耗（含损耗率）；分批进场与进度节点联动
- [ ] 劳动力曲线 ↔ 进度计划：曲线随阶段起伏（基础/主体/装饰不同人数），高峰人数含储备系数（1.1~1.2）
- [ ] 每个跨表数字有计算过程（"4台×日切100㎡×45天=18000㎡≥14936㎡"式文字链）
- [ ] 危大措施量与措施清单对应（支护桩/降水井等在措施项目中有体现）

工具辅助：`scripts/audit_bid.py` 第 16 节自动扫描配置类表格并标记需人工复核的闭环点。

> 实操提醒：AI 评审模型会自动校准数值矛盾——编造或算不平的数字是"方案不可行"判定的首要来源。
