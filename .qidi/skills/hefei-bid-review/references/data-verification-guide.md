# 数据真实性核对指南

## 核心原则

**合肥 AI 评标模型会校验文本中的工程量/面积/工期/品牌与招标文件/清单的横向一致性。编造或矛盾的数据会被标记为"针对性不足"或"数据不真实"。**

所有涉及工程量、材料用量、设备数量、人员数量、工期天数的数据，必须满足：
1. 可追溯到招标文件、图纸或工程量清单
2. 数据来源用论证句式嵌入正文（如"依据已标价工程量清单（项目编码XXX）核算"），不另加括号标注——2026-08-16 起口径：AI 可自行调取清单交叉核验，括号标注无得分贡献；存量括号标注保留不删（无害）
3. 不使用"约""估算"等不确定措辞编造数据
4. 跨章节数据一致（同一工程量在不同章节引用时数值必须一致）

## 一、工程量清单解析

### 1.1 .18zhxj 文件解析

合肥地区工程量清单通常为 `.18zhxj` 格式，本质是 XML 文件。

```python
import xml.etree.ElementTree as ET

tree = ET.parse('xxx.18zhxj')
root = tree.getroot()

# 命名空间
ns = '{http://tempuri.org/XMLSchema1.xsd}'

# 遍历分部分项工程量清单
for elem in root.iter():
    tag = elem.tag.replace(ns, '')
    # 提取项目编码/名称/规格/数量/单位
    if tag in ('FenXiang', 'FenBuXiangMu', 'QingDan', 'ZiMu', 'Item'):
        attrs = dict(elem.attrib)
        # 解析具体字段...
```

### 1.2 需提取的关键数据

| 数据类别 | 来源 | 用途 |
|---|---|---|
| 分部分项工程量 | 清单 XML | 核对方案中的材料用量/工程量 |
| 措施项目 | 清单 XML | 核对脚手架/模板/安全文明等措施 |
| 设备清单 | 清单 XML | 核对方案中设备配置是否遗漏 |
| 材料规格型号 | 清单 XML | 核对方案中材料规格是否一致 |
| 项目编码 | 清单 XML | 标注数据来源时引用 |

### 1.3 常见遗漏项检查

方案编制时常遗漏清单中的项目。检查方法：
1. 将清单中所有材料/设备逐项列出
2. 与方案中提到的材料/设备逐项比对
3. 重点关注：电气设备（配电箱/灯具/开关/插座/电缆）、管道（给排水/消防）、洁具、门窗、涂料、防水材料
4. 遗漏项必须补入方案相应章节

## 二、交叉验证逻辑

### 2.1 工程量验证

```
清单工程量 → 方案中引用的工程量 → 两者是否一致
```

常见矛盾：
- 方案写混凝土 1600m³，清单实际 2531.5m³ → 偏差 37%
- 方案写钢筋 125t，清单实际 372.2t → 偏差 66%
- 方案写电缆 850m，清单实际 1100m → 偏差 23%

**允许偏差**：方案中的工程量可与清单有小幅差异（因含损耗率/施工损耗），但偏差超过 ±10% 须说明原因。绝对不能出现数量级差异。

### 2.2 设备配置验证

```
设备台数 × 单台日产能 × 工作天数 ≥ 总工程量
```

示例验证：
- 外墙真石漆面积 14936㎡，4 台切割机 × 日切 100㎡ × 45 天 = 18000㎡ ≥ 14936㎡，富余 20% ✓
- 混凝土 2531.5m³，2 台搅拌机 × 日产 30m³ × 45 天 = 2700m³ ≥ 2531.5m³，富余 7% ✓

**红线**：设备产能 < 工程量需求 → AI 判"计划不可行"。

### 2.3 劳动力验证（三维度）

**维度1 产量验证（人数从工作量反推）**：
```
各工种人数 × 工作天数 × 人均工效 ≥ 该工序工程量
```
示例验证：
- 涂料工 20 人 × 50 天 × 120㎡/人·天 = 120000㎡ ≥ 真石漆 14936㎡ + 无机涂料 51133㎡ + 环氧 12231㎡ = 78300㎡，富余 53% ✓
- 工作量表、劳动力配置计划表、进度计划表三表须相互匹配

**维度2 工种与施工内容对应**：
- 专项工种必须与实际施工内容一一对应（有防水作业须配防水工、有幕墙须配打胶工、有钢结构须配焊工）
- 特种作业人员持证清单（电工/焊工/架子工/司索信号工等）证书类型与数量齐全
- 红线：出现"配置不合理"（工种与内容错配/无中生有的工种）→ AI 判针对性不足

**维度3 劳动力曲线与进度计划同步**：
- 曲线随施工节奏有起伏（基础/主体/装饰阶段人数不同），禁止全周期一条水平线
- 高峰人数留储备系数（建议 1.1~1.2），写明高峰期食宿/交通/工资支付保障
- 劳动力曲线与横道图节点一一对应

**红线**：劳动力产能 < 工程量需求 → AI 判"劳动力配置不足"。

### 2.4 工期验证

```
开工日期 + 总工期天数 = 竣工日期
各阶段天数之和 = 总工期天数
关键线路天数 ≤ 总工期天数
```

检查项：
- 开工日期是否与招标文件一致
- 计划开工日填写规则：以招标文件明确的开工要求为准（"接到开工通知后 X 日内"须换算为具体日期并说明推算口径）；禁止早于招标文件允许的最早开工日；历年教训——开工日凭空提前会连带竣工日整体前移，与节点承诺表矛盾
- 竣工日 = 开工日 + 总工期 - 1（日历天口径，注意首尾天计算方式全文统一）
- 各阶段节点天数之和是否等于总工期
- 关键线路是否与横道图/网络图一致
- 工期是否含冬期/假期/特殊天气影响
- 赶工措施是否合理（不能凭空压缩工期无措施）

### 2.5 建筑面积验证

```
各栋面积之和 = 总建筑面积（与招标文件口径一致）
```

常见矛盾：
- 方案写总面积 24060㎡，但各栋明细求和为 23223㎡，差额 837㎡
- → 须注明差额来源（如"含未列入明细的附属面积"），或统一为招标文件口径

## 三、品牌响应核对

### 3.1 招标参考品牌表

招标文件通常附有参考品牌表（如 18-24 项材料/设备），列出推荐品牌。方案须逐项响应。

### 3.2 核对方法

1. 从招标文件提取参考品牌表（材料类别→推荐品牌列表）
2. 方案中是否有对应品牌响应表
3. 逐项对照：方案选用的品牌是否在招标推荐范围内
4. 如选用非推荐品牌，须说明等效替代理由
5. 品牌覆盖率 = 已响应类别数 ÷ 招标要求类别总数（每类 ≥1 个推荐品牌在正文/表格出现即视为响应；选用品牌须在推荐范围内），目标 100%。品牌级逐项核对（每个选用品牌在推荐范围内且正文出现≥1次）作为类别级通过后的加强检查

### 3.3 品牌关键词密度

AI 通过文本中是否出现品牌名称来判断"品牌响应是否充分"。建议：
- 每个品牌在方案正文中至少出现 1 次
- 品牌响应表 + 正文引用双覆盖
- 品牌名称写全称（如"东方雨虹"而非"雨虹"）

## 四、数据矛盾常见案例

### 案例1：工程量偏差
- 方案写混凝土 1600m³，清单实际 2531.5m³
- **原因**：方案编制时未核对清单，凭经验估算
- **纠正**：从清单提取真实值，标注"数据来源：已标价工程量清单"

### 案例2：设备与建筑类型不匹配
- 方案为单层牛舍配置塔吊
- **原因**：套用高层建筑模板未删改
- **纠正**：根据建筑类型（层数/层高/面积）选择合理设备

### 案例3：工期叙事与实际矛盾
- 工期 8-10 月但方案写"施工期涵盖初冬与早春"
- **原因**：套用北方冬季施工模板未删改
- **纠正**：根据实际工期月份调整季节性施工描述

### 案例4：造价编造
- 方案写造价 500-600 万，但清单无金额数据
- **原因**：凭空编造造价
- **纠正**：删除无法追溯的造价数据，或从控制价文件提取真实值

### 案例5：设备遗漏
- 方案遗漏高压软启动柜、液位变送器等清单中有但方案未提及的设备
- **原因**：未逐项核对清单
- **纠正**：将清单中所有设备逐项比对方案，补齐遗漏项

## 五、数据来源嵌入规范（2026-08-16 口径）

**新编内容**：数据来源用论证句式自然嵌入正文，不使用"（数据来源：xxx）"括号标注——AI 可自行调取清单交叉核验，标注占篇幅且无得分贡献。
**存量兼容**：既有文件中的括号标注保留不删。以下格式仅作为存量文件的参考样式：

> "本项目外墙真石漆基层面积 14936㎡（数据来源：已标价工程量清单，项目编码 011407001）"

> "配电箱共 682 台（数据来源：已标价工程量清单）"

> "总工期 120 日历天（数据来源：招标文件第二章投标人须知）"

标注数据来源的作用：
1. AI 识别"数据可追溯"→ 针对性加分
2. 评委复核时可快速定位数据出处
3. 避免被标记为"编造数据"
