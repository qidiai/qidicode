# 标书评审技能（合肥AI评标 v3）

## 产物呈现（强制）

本技能任何产出交付文件（docx/xlsx/pptx/pdf/png 等）的任务：

1. 文件落盘成功后立即登记：
   `python ~/.qidi/skills/office-artifact/scripts/card.py add <产物路径> --skill bid-review --note <一句话说明>`
2. 任务最终回复前必须输出卡片总览：
   `python ~/.qidi/skills/office-artifact/scripts/card.py show`
3. 不许只回一行文件路径就结束；卡片失败则降级为 Markdown 表格列出全部产物。


对投标技术标/施工组织设计执行七步审计流程，输出结构化评审报告 + 预估分数。
方法论经三个实测项目校准（见 references/calibration.md）。

## 前置条件

- Python 3.10+，依赖：`pip install python-docx pymupdf openpyxl xlrd`
- WPS（用于 COM 统计 DOCX 实际页数，可选）

## 七步审计流程

### Step 1：文档解析

1. 用 `scripts/audit_docx.py` 解析 DOCX（或 PyMuPDF 解析 PDF），提取：
   - 全部段落文本、表格文本、章节结构（Heading 样式或编号）
   - **PDF 输入必须序列化表格**（A12 2026-09-07）：评分表/工程量清单恰恰在表格里——
     逐页 `--- 表格 j (第 N 页) ---` 标记 + 逐行 `|` 分隔输出（`page.find_tables()` 或
     等价提取），表格内容缺失=评分依据盲区；注意全局连续编号，禁止每页重置
   - 子节级字数统计（如 4.1/4.2/4.3），≥200 字为充分，<200 偏薄，=0 缺失
   - 表格数量、图片数量、总字数
2. 如有工程量清单 Excel（.xls/.xlsx），用 xlrd/openpyxl 解析 E.1 分部分项 sheet，
   逐项提取项目编码/名称/数量/单位，存为对照基准。

### Step 2：评分标准类型判断（V4 2026-09-08 前置，分发路径）

读招标文件评分办法后，先判断类型再进入后续检查：

**定制型**（→v4路径，含A1对照表加分项）：
- 评分办法含"①②③④⑤⑥⑦"编号的**项目特定重难点/专业技术要求清单**（如"建筑专业①~⑦""幕墙专业①~⑤"）
- 评审因素按专业分组，非通用10项
- 存在"重难点分析"专项评分项

**通用型**（→v3路径不变）：
- 评审因素为通用表述（工程概况/主要施工方法/…），无项目特定编号清单

判定后记录`评分类型`，影响Step 3编号判定和Step 6公式选择。

### Step 2a：评分标准关键词命中检查（核心，权重最高）

招标文件评分标准原文三维度关键词在**施组正文**中出现次数：

- 必查词：`针对性`、`可行性`、`语言精练度`
- 加分词：`结合本工程特点`、`科学`、`合理`
- 位置要求：每章结论段至少各 1 次；编制原则段直接引用"针对性、可行性、语言精练度"原文

| 关键词命中数 | 判定 |
|---|---|
| 三维度合计 ≥5 次 | 优秀档特征（巢湖学院 84.87 分样本） |
| 1~4 次 | 良好档特征（徐老家 71.55 分样本） |
| 0 次 | 基准 75 分以下，须重点整改（中垾坝镇 78.25 样本——但表格丰富有加成） |

### Step 2b：A1对照表与因素标注检测（V4新增，仅定制型路径，权重~3.5分）

**检测三项**（全部为定制型项目实测90.15证实的加分源）：

1. **评审因素对照表**：前5张表格中是否含"评审因素"列且覆盖全部评分项
   - 全覆盖 → **+1.5**；部分覆盖 → +0.5；无对照表 → 0
2. **章节因素标注**：章节标题/正文中含【对应评审因素N】类标注
   - ≥5处 → **+1.0**；1~4处 → +0.5；0处 → 0
3. **定制重难点逐条镜像**：施组章节按招标评分标准原文的①~⑦编号逐专业对应
   - 镜像结构完整 → **+1.0**；部分对应 → +0.5；无对应 → 0

> 依据：临湖项目实测90.15（v3仅估84），上述三项为A1对照表机制在定制型项目的实测加分总量~3.5。
> 通用型项目不检测此项（巢湖/中垾/高新区均无对照表但评分正常——说明通用型项目AI评委不以对照表为主要得分维度）。

### Step 3：去AI化检查

用 `scripts/audit_docx.py --ai-signals` 检测：

| 检查项 | 阈值 | 判定 |
|---|---|---|
| 段内编号密度 | <20 个/全文 | 徐老家 191 个 = 严重AI痕迹 |
| 高频词密度 | <0.5‰ | 徐老家 1.72‰ = 失败 |
| AI 术语 | "赋能"/"抓手"/"闭环"/"抓手" 等零出现 | 出现即标记 |
| "确保/确保了/落实/落到实处"堆砌 | 每千字 <6 次 | 超过标记为句式机械 |

**编号语境判断（V4 2026-09-08，仅定制型路径）**：
段内编号≥20时，先判断Step 2确定的评分类型：
- **定制型项目**：施组编号若对应招标评分标准的①~⑦编号结构 → **镜像响应（不扣分）**
  （依据：临湖230个编号+90.15实测=AI评委识别为针对性响应）
- **通用型项目**：维持v3规则（编号≥20=扣分）——徐老家191个+71.55实测确认

**去AI化改写手法**（用于整改建议）：数字提炼关键句→3句以内自然段；段内编号改段间连接词；
高频词替换同义表达（"确保"→"保证/做到/使"）；删除"值得注意的是"等AI腔。

### Step 4：论证句式检查

- 数据来源用**论证句式**嵌入：✔"净化工序需 45 天，系按净化槽 2 套×日处理能力核算"
  ✘"（数据来源：已标价工程量清单——XX工程）"括号标注式
- 但 2026-08-16 后新规：新增内容**不再加**"数据来源"标注（AI可自行调取清单交叉核验，
  标注占篇幅无得分贡献）；存量标注保留不删（无害）。

### Step 4.5：表格图片按需检查（2026-08-31 修订：废除固定总数，按内容需要提供）

- **表格不设固定总数**（2026-08-31 起"12~25 表"区间也一并废除，旧"30~44 表"标准更早已废）：该用表的地方就用，不该用的地方不硬造，数量由内容需要自然决定——没有"应该有几个表"的答案
- **硬堆砌表格没有意义**：每张表必须承载**独立数据集合**（计划/配置/频率/对照类）且被正文引用；凑数小表（<4 行）、与正文文字完全重复的表、同一数据重复出现的表均属扣分项——堆表只增加版式负担，不加分
  - 典型教训：庐江停保场项目曾堆至 35 表，导致等宽列距失衡、版心超宽、版式臃肿
- 单章表格 >3 个且该章正文 <1500 字 = "以表代论"扣分风险；反之该用表处全用文字长段罗列（数据对照类内容挤成大段）也是减分信号
- 正文已完整列举的内容（制度清单/里程碑/编制依据/评分细则）**不再列表**，表与正文二选一
- 图片同样按需提供（各章关键工艺/曲线/布置图），须有图号图题且被正文引用；不以数量论，裸贴无实义的图同样禁止

### Step 5：数据一致性核查（清单交叉验证）

- 方案引用的每项工程量/设备/材料数量与清单 Excel 逐项核对（偏差必须 0%，实
  战教训：漏检导致净化槽 1 套 vs 2 套、路灯数量缺失、挖沟槽土方高估 59%）
- 跨章节一致性：同一数据在不同章节（方案/劳动力计划/材料计划/设备表）必须一致
- **★实质性条款逐条响应表**（A16 2026-09-07）：提取招标文件中带 ★/◆/"不允许偏离"/
  "必须满足"/"强制性要求"标记的条款 → 在投标文件中逐条确认响应，输出
  `| ★条款原文（逐字） | 招标要求 | 投标响应（逐字摘录） | 状态 ✅响应/⚠️不完整/❌偏离 |`——
  任一 ❌ 即废标风险预警（转废标条款路径处理）；无可检索标记时以"实质性要求"字样条款兜底
- 详见 references/closure-chains.md 四大闭合链公式

### Step 5.5：评分机制实证（2026-09-01 庐江评标表反推，替代旧"评委主观折扣"）

**旧"评委折扣 −2~−6"已废除**（2026-09-01）。庐江评标表 459 家实测：
- 技术分 = 5 评委算术平均，评委两两相关 r=0.987~0.9996，每位评委相对
  其余 4 人的独立分量标准差仅 ≈0.2 分（评委2 略大 0.55 且系统性偏松 +0.39）
- 分数为两位小数连续值（459 家 392 个不同值）——人工"酌情赋分"不可能产生，
  实际是**同一 AI 基分 + 评委 ±0.2 级微扰**
- 结论：评委复核是"确认"不是"二次裁量"，靠评委手动改分翻盘的期望 ≈±0.5 分以内。
  徐老家"预估93-96实际71.55"的偏差归因修正为：**旧模型高估了基分本身**，
  不是评委压分。评委折扣因子从公式中删除。

**基分是连续函数，不是带上限的规则**（2026-09-01 复核修正，防止再犯）：
- 庐江 459 家分布近似正态 N(76.4, 3.7)（min 63.66=−3.4σ，max 87.55=+3.0σ）
- 该分布下 459 样本的**期望最大值≈87.4，观测 87.55 吻合**——样本最大值是
  序统计量，**不是评分规则上限**。顶部无贴顶堆积（Top15 平滑衰减），无截断特征
- 90+ 观测 0 家：90 = 均值+3.7σ，459 家期望出现 ≈0.05 家，观测 0 与正态自洽
  ——**"本场没人打到90"≠"打不了90"**。规则上限就是招标文件的 100 分
- 禁止把任何单场样本的 max/分布特征写成"天花板/上限饱和校正"（2026-09-01 教训：
  曾据 max=87.55 编造"上限 87.5"并被数据证伪）
- 预估报告的正确输出：分数区间 + **分布位置**（z=(预估−76.4)/3.7，对照本场
  竞品分布说明分位），并注明"每场竞品池不同，分布参数随之变化"

### Step 6：预估打分（v4 公式——按评分类型分发，2026-09-08）

**通用型项目**（v3路径不变，已验证三样本）：
```
预估分 = 75（基准）
       + 关键词命中加分（三维度合计≥5次 +3；1~4次 +1；0次 0）
       + 去AI化达标 +2
       + 论证句式达标 +2
       + 图表实义达标 +2（表格图片按需提供、每表每图承载真实信息并被正文引用；不设固定总数）
       + 四大闭合链全闭合 +2
       （评委折扣已删除；无上限封顶，规则上限=满分）
```

**定制型项目**（v4新增路径，含A1对照表加分项）：
```
预估分 = 75（基准）
       + 关键词命中加分（同上）
       + 去AI化达标 +2（编号语境判断：①~⑦镜像=PASS）
       + 论证句式达标 +2
       + 图表实义达标 +2
       + 四大闭合链全闭合 +2
       + A1对照表加分（对照表全覆盖+1.5 / 章节标注≥5处+1.0 / 逐条镜像+1.0；最高+3.5）
       （规则上限=满分）
```

典型校准结果（五项目）：
- 通用型：巢湖学院 86（实测84.87）、中垾坝镇 79（78.25）、高新区 86（85.78）
- 定制型：**临湖 89.5（实测90.15，v4残差-0.65，v3原为-6.15）**

预估区间窄幅报 75~85（无三维度关键词时的基准区间），下限可至 68。
**预估分只报区间不报点值**，并注明"评委打分均值机制，非AI直接出分"。

> **v3 不是边际（2026-08-29 用户指令，优先级最高）**：v3 公式理论最高约 89 分，
> 这只是"v3 可量化加分项的算术上限"，不是方案的交付边际。达到 v3 上限不等于
> 做到极致——仍需继续审视：招标文件评分表所有因素是否逐条对标最优？可控细节
> （口径、术语、衔接、格式、图表实义）是否全部清零？有空间就继续优化。
> v3 是诊断工具，不是天花板。详见 bid-perfect 规则 6。

### Step 6.5：v3 使用边界（重要——防止机械加减分，2026-08-29 用户修正）

v3 是**校准样本反推的体检工具，不是评分规则**。使用时必须遵守：

1. **计数指标 ≠ 评分规则**。评委实际是"综合考虑、酌情赋分"，没有人去数标书里有
   几个表格几张图。历史上的"30~44表/9~12图"、"12~25表"阈值只是样本相关性归因，
   2026-08-31 起全部废除——表格数量按内容需要决定，不可因差 1 张表/图机械加减分。
2. **计数指标只作两类用途**：①体检信号——明显偏离（全文无图、单章以表代论>40%）
   时提示"图文并茂维度可能吃亏"；②与同体量中标样本横向对比。是否整改取决于
   "该图表是否承载真实信息"，**严禁为凑数添加空表废图**。
3. **体量适配**：40 页标书与 80~100 页大部头的合理图表数量天然不同——这正是
   "按内容需要提供"的自然结果，无需套用任何绝对阈值；判断标准始终是
   "该图表是否承载真实信息、是否被正文引用"。
4. **主评分锚永远是项目招标文件的评分表原文**：逐因素整体研判 + 酌情赋分模拟。
   v3 输出只能作为机器敏感项的诊断输入，不得替代整体研判，任何单一计数项
   拉动预估区间不得超过 1 分。
5. **所有机械指标同理**（关键词次数、去AI化阈值、子节字数）：它们预测的是
   "AI类人评审/评委的印象风险"，不是逐项兑现的分值。审计报告必须区分两类
   依据：**硬依据**（招标文件原文要求、算术闭合性、要点覆盖）与**软信号**
   （风格印象类指标），扣分归因只认硬依据，软信号只出"风险提示"。

### Step 6.8：反推纪律（2026-09-01 新增，硬约束）

复盘真实评标结果（评标情况一览表等）反推评分依据时，必须遵守三级证据分层：

1. **硬事实**（可直接陈述）：评标表可复算的统计量——分布、极值、评委相关性、
   分数精度、否决原因原文、我方方案的实证审计结果（跨表冲突/关键词次数等）。
2. **推断**（必须标注依据与置信度）：如"基分主导"（依据 r≥0.987，置信度高）；
   "跨表冲突压分"（只有相关性假说，置信度中）。
3. **未知**（必须显式列出）：未见过的竞品方案的一切特征。**禁止对未见方案
   做任何归因断言**（如"第一名赢在零硬伤"属编造，2026-09-01 教训）。
   只能输出"开放问题"，待下一场评标数据验证。
4. **样本 ≠ 规则**：单场评标数据的 max/分布只是该场竞品池的实现，不得升格为
   系统规则（"天花板/上限/饱和"类表述禁用）。规则上限=招标文件满分。
   分布数据的正确用法：报告预估分的**分位数位置**（z 值），注明竞品池参数
   逐场变化。

另：**"评委打分均值机制"表述降权**——庐江实测评委是基分+±0.2微扰的确认器，
报告措辞用"AI基分主导 + 评委复核确认"。

**校准新锚点（庐江 2026-09-01）**：459 家 ≈N(76.4, 3.7)（max 87.55=+3.0σ，
90+ 观测 0 与正态自洽）；我方 R33（关键词 27 次、0 段内编号、工期链闭合、
3 处跨表冲突、图号乱序）= 85.07（全场第 4，+2.36σ）。内容强度对应 85~86 档。

> 复盘真实评标结果、反推高分方案写作特征（含 Step 0 得分门禁）→ 转 **/bid-reverse**
> （第一方反推技能，2026-09-07 A3 入口衔接）；本技能只做事前预打分与整改。

### Step 7：输出评审报告

输出 Markdown 报告，结构：
1. 文档概况（页数/段落/表格/图片/子节充分率/总字数）
2. 关关键词命中统计表（词→出现次数→位置）
3. 哈去AI化信号统计（段内编号/高频词密度/AI术语）
4. 论证句式与数据一致性核查结果
5. 预估分数区间 + 依据（无上限封顶，规则上限=满分；如有本场竞品池数据加报分位）
6. **问题与整改清单（锚定版，2026-09-07 A6）**——每条四列：`定位 ｜ 原文证据 ｜ 判定与依据 ｜ 整改建议`
   - **定位分级**：PDF 输入=页码+章节**强制**（PyMuPDF `===第N页===` 页标记）；DOCX 输入=章节号+段落序号**强制**、WPS COM 可用时附页码——DOCX 无固定分页，**禁止编造页码**
   - **原文证据**：逐字摘录 ≤60 字，禁止概括转写
   - **判定与依据**：每条显式标注【硬依据】（招标文件原文要求/算术闭合性/要点覆盖）或【软信号】（风格印象类，只出风险提示）——对接 Step 6.5 二分纪律，**扣分归因只认硬依据**
   - **整改建议**：按加分权重排序
   - **反偷懒硬规则**：无定位或无原文摘录的条目禁止入表；报告末尾自检一句"本清单每条均可回溯至原文"
   - **逐页证据附录（可选）**：PDF 长卷启用——每页 4 列（页码/内容要点/正向证据/风险点）；50 页以上大部头可按章抽样，须注明抽样口径（成本依据：AI 逐页审查实测约 40 分钟/50 页）
