# 标书方案编写技能（bid-creation SOP）

## 产物呈现（强制）

本技能任何产出交付文件（docx/xlsx/pptx/pdf/png 等）的任务：

**产物落位约定（2026-09-25 增补，用户指定）**：方案文件（开工包、章节 md、附表、附图、装配脚本、终版 docx/pdf 等全部产物与可复现脚本）**统一放在项目文件夹**（即招标文件所在目录）下的 `施工组织设计\` 子目录，**不放工作区 `投标方案\`**。开工即建该目录，全部产物就地落盘，项目资料与方案产物同处一地、随项目归档。

1. 文件落盘成功后立即登记：
   `python ~/.qidi/skills/office-artifact/scripts/card.py add <产物路径> --skill bid-write --note <一句话说明>`
2. 任务最终回复前必须输出卡片总览：
   `python ~/.qidi/skills/office-artifact/scripts/card.py show`
3. 不许只回一行文件路径就结束；卡片失败则降级为 Markdown 表格列出全部产物。


按八步流程产出一份锚定评分点、数据闭合、去AI化的投标技术标。
写作铁律：**每章结论段显式出现"针对性、可行性、语言精练度"三维度关键词**
（合肥AI评标是关键词匹配+语义辅助混合模型，关键词缺失=被判未响应评分维度）。

## Step 1：关键要求提取

从招标文件（PDF/DOCX，用 PyMuPDF/python-docx 解析）提取五类硬性要求：

| 类别 | 提取内容 |
|---|---|
| 资质 | 施工总承包等级、安全生产许可证、专项资质 |
| 人员 | 项目经理（注册建造师等级+B证）、技术负责人职称、八大员配置 |
| 业绩 | 近N年同类工程个数/面积/金额门槛 |
| 财务 | 审计报告、注册资本、营收要求 |
| 设备 | 主要机械设备种类与数量要求 |
| AI评审约定 | 招标文件约定的AI"类人"评审流程（合公信〔2026〕46号第20条：评委须按约定流程评审、科学设置评审关注度——因项目而异，写作措辞须对齐） |
| 雷达条款 | 雷达监测结果的应用方式及处置措施约定（第29条），是否启用围串标雷达排查 |

提取不到的项标记 `[待补：xxx]`，不杜撰。本地规则 + 语义提取双通道交叉验证。

## Step 2：章节规划（锚定评分点）

1. 解析招标文件评分办法，列出：评分项 → 分值 → 对应章节映射表
2. 解析评分档次（优/良/一般/差对应分数区间），**写作对标最高档描述**
3. 字数标准：**高分值章节（≥10分）正文 ≥5000 字；其他章节 ≥3000 字；
   每个子节（x.y 级）≥200 字**（AI按子节级评估内容深度）
4. 章节顺序：首页直接进入实质内容；技术标 1.1 项目基本情况只写项目本身
   （名称/编号/招标人/资金/地点/工期/质量/类型+针对性描述），
   **不堆砌招标文件的审批机关/评标办法/资质要求**（属商务文件内容，占篇幅无分）

## Step 3：地域特征适配

按项目所在地加载地域施工特征（完整词典见 references/regional-features.md）：
东北→冬季施工、南方→雨季台风、高原→健康保障、城区→扬尘噪声、沿海→防腐蚀等。
服务类/采购类标书不加地域施工特征。

## Step 4：四大闭合链数据构造（数据自洽是评审硬伤检查点）

写方案时按公式**正向构造**数据（公式详见 references/closure-chains.md）：

```
工期：工程量 ÷ 日工效 = 需天数（逐工序核算，平行归并后 ≤ 招标工期）
设备：台数 × 日产能 × 有效天数 ≥ 工程量（设备表写明确退场值，禁用"同上"）
劳动力：各工种工日合计 与 报价人工费口径偏差 ≤ ±5%
        （表述用"与一览表基准完全一致"，技术标评审时报价未开不可核验）
物资：清单量 × (1 + 损耗率) = 需用量（损耗率注明定额依据）
```

工程量数据一律以已标价工程量清单为准，**不加"（数据来源：xxx清单）"标注**
（AI评审可自行调取清单核验，标注无得分贡献只占篇幅）。

## Step 5：写作规范（得分关键）

### 必须做
- 每章结论段至少各 1 次显式出现：`针对性`、`可行性`、`语言精练度`
- 编制原则段直接引用招标文件评分标准原文"针对性、可行性、语言精练度"
- 多用"结合本工程特点"引出针对性描述（巢湖学院样本 8 次，84.87 分）
- 表格 30~44 个、插图 9~12 张（有图号图题、被正文引用）
- 数据用论证句式嵌入："净化工序需 45 天，系按净化槽 2 套×日处理能力核算"
- 每图配 50~100 字读图分析（不能"以图代论"裸贴）

### 严禁做（去AI化红线）
- 段内编号（段中塞 ①②③/(1)(2) 式罗列）——全文 <20 处
- "确保/落实/保证"高频堆砌——密度 <0.5‰
- AI 术语零出现：赋能/抓手/闭环/颗粒度/底层逻辑/组合拳/打法
- 通用模板句："值得注意的是""综上所述"开头堆叠、空泛口号段
- 段落结构：论点+数据+工艺细节，3~5 句自然段，不用"首先其次最后"机械连接

## Step 5.5：防雷达自查（围串标红线，合公信〔2026〕46号第26-30条）

合肥平台对含历史投标文件在内的交易数据（第27条）运行雷达监测，分析报告作为涉嫌围串标初步认定的重要依据（第26、30条）。成稿后逐项自查，AI 辅助编标场景三项重点：

| 风险 | 条款 | 自查动作 |
|---|---|---|
| 同错 | 第26条(二) | 多家标书不得在同一处犯同样的错（错别字/口径/单位）——AI 生成内容的错误特征必须差异化 |
| 雷同 | 第26条(一) | 应自行编制内容不得跨投标人高度相似——同一工具产出的段落须差异化变换（句式/结构/素材） |
| DNA链一致 | 第26条(三) | 引用的互联网素材来源不得跨投标人异常一致——数据来源做项目定制化 |
| 特有标识外流 | 第26条(四) | 本单位特有业绩/标准/编号/标识不得流入其他投标人文件（含历史投标文件）；本单位复用自身历史标书不直接构成异常，特有标识严禁外流 |

操作纪律（第26条(六)(七)(九)）：标书编制/上传/解密一企一机；计价软件加密锁不借用；保证金从本单位基本账户转出；项目班子人员不与其他投标人重叠。

> 定位：投标人自备 AI 工具辅助编标未被合公信〔2026〕46号禁止（办法规制大模型开发应用方），但多家标书出现"同错/雷同"特征将触发雷达监测线索——须对 AI 产出做差异化审校并对内容真实性负责。

## Step 6：占位符系统

需投标人线下确认的信息用占位符标记，生成后醒目提醒用户替换：

- `[资质占位符：安全生产许可证编号]`
- `[人员占位符：项目经理注册建造师证书编号]`
- `[业绩占位符：近3年同类工程合同]`
- `[财务占位符：2025年度审计报告]`

**暗标模式不插入任何占位符和投标人信息**（暗标暴露身份=废标）。

## Step 7：商务标结构（如需）

投标函 + 商务偏离表 + 技术偏离表 + 评分索引表 + 资格审查索引表。
评分索引表格式：评分项 → 分值 → 对应章节 → 响应状态（完全响应/正偏离）。

## Step 8：Word 导出

用 `scripts/md2docx.py`（Markdown → DOCX，v3.0：markdown 解析层 + 自研标书渲染层）：

```bash
python scripts/md2docx.py 方案.md --project "XX项目施工总承包" \
    --bidder "XX建设工程有限公司" -o 投标文件.docx
```

常用可选参数（不改变旧调用）：
`--anonymous` 暗标（清文档属性）｜`--body-font 仿宋`｜`--line-spacing {22,28}`｜
`--table-style {grid,three-line}`｜`--margin 上,下,左,右`（cm）｜`--download-images`｜`--no-cover`

- 封面：项目名 26pt 居中 + 副标题"投标文件"18pt + 投标人 + 日期 + TOC 自动目录域
- **行内标记解析**：`**加粗**` 等由 markdown 解析器拆 run（直接塞入会显示星号，实测踩坑）
- 表格：**默认全框线（`--table-style three-line` 可切三线表），长表 `cantSplit` + 表头跨页重复**
- 页数控制：**WPS COM `ComputeStatistics(2)` 为本机准绳（Word COM 本机不稳）**
- **改动即自测（硬纪律）**：凡改动 `scripts/md2docx.py`，提交前必跑
  `python .qidi/skills/bid-write/scripts/md2docx_selftest.py`（11 份 unit + 1 份
  integration golden + A0/A1/A2/A3/A4 全断言 + 泄漏残留扫描）；**FAIL 即停**，
  不得带失败断言提交或交付。

## 自检

成稿后运行 `/bid-review` 技能审计（关键词命中/去AI化/闭合链/雷达风险/预估分），
预估 ≥80 且 Step 5.5 防雷达自查零风险项再交付。

## 文件卫生纪律（2026-09-19 增补）

编写/整改方案过程中：过程脚本（提取、修复、图表生成等一次性脚本）统一放 `<项目根>/_work/`，禁止散落项目根与交付目录；交付物（docx/pdf/图表 png）放固定输出目录。任务结束运行 `python "%USERPROFILE%\.qidi\scripts\workspace_hygiene.py" <项目根>（cmd）／python "$env:USERPROFILE\.qidi\scripts\workspace_hygiene.py" <项目根>（PowerShell）` 预览并加 `--execute` 清理（先归档至 `<项目根>/_trash/*.zip` 可恢复）；脚本内置白名单保护交付物、清单源文件与审计报告，预览发现误伤立即终止不得执行。
