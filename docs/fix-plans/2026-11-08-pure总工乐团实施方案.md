## 0. 一句话结论

**派活可行，隔离不可行。** 总工（主会话）能派子代理，且 plan 权限不拦派活；但子代理的 cwd 无法指到任意目录（`IsolationMode` 只有 `None | Worktree`），所以"双盲席物理读不到仓库"做不到，只能降级为"材料优先 + 声明来源"。

## 2. 对原方案的三处修正

### 修正 1：`mcpInheritance: none` 对主会话是空操作

原方案给 4 个 agent 都写 `mcpInheritance: none` 并认为这样零 MCP。**对主会话（总工）不成立**——`McpInheritance` 只在子代理通道被消费，主会话不读该字段（此结论来自 2026-11-08 独立审计，判 ✅）。

**真正生效的是** `disallowedTools: [search_tool, use_tool]`（F5，按名删除 MCP 元工具）。

**但要注意**：删掉元工具只让模型**调不到** MCP，MCP 服务器进程**仍会连接**。若要真零 MCP，得用裸 home（`QIDI_HOME=~/.qidi-local`，其 config 无 `[mcp_servers]` 且 ai-bridge 工具全禁）。

**结论**：总工保留 `mcpInheritance: none`（无害、语义自文档），但**真正的 MCP 开关是 `disallowedTools`**；要真零 MCP 就走裸 home。

### 修正 2：blind-auditor → material-auditor，判据降级

改名，因为"双盲"名不副实。新判据：

| 原判据 | 新判据 |
|---|---|
| 仓库内问题**拒答或明示不知道** | **必须声明信息来源**——答案来自材料（指到段落/行）还是来自仓库（指到文件:行号） |

后者可机器校验：回执里每条结论都要带来源标签。答得出来不可怕，**不声明才可怕**——因为那正是锚定污染的发生方式。

### 修正 3：agent 定义必须带 `model:`，否则分席压缩阈值白设

阶段 2 的 `[model.seat-*]` 三个条目，其解析口径是"spawn 时按**子代理自身模型 id** 查 `[model.<id>]`"（F7）。若 agent 定义没写 `model:`，子代理**继承父模型**，阈值条目匹配不上。

**所以 4 个字段必须同时给**：agent 定义的 `model:` + config 的 `[model.<id>]` + 该段的 `auto_compact_threshold_percent`。

## 4. Agent 定义内容

### D1 `orchestra-conductor.md`（总工，主会话）

```markdown
---
name: orchestra-conductor
description: 乐团总工：只读 + 派活，不自己写任何文件；一切事实断言须带证据指针
model: <云端便宜大窗口条目 id>
tools:
  - read_file
  - list_dir
  - grep
  - Agent(assertion-checker, material-auditor, bonsai-coder)
disallowedTools:
  - search_tool
  - use_tool
permissionMode: plan
injectDefaultTools: false
discoverSkills: false
inheritSkills: false
agentsMd: true
mcpInheritance: none
---

你是乐团总工。你不写文件、不改仓库、不跑命令——一切写操作派生 `bonsai-coder`。

## 八条纪律

1. 你不写文件、不改仓库；一切写操作派生 `bonsai-coder`。
2. 每条事实断言必须带 `文件:行号`；给不出行号的只能进"假设"区，不得进任务书正文。
3. 派工前先派 `assertion-checker` 复核你自己的关键断言；被证伪的必须写进决策台账。
4. 派工只用固定模板；变量放尾部，模板头部不许改。
5. 你只认回执的 6 字段 + 落盘日志原文；散文式汇报一律退回重派。
6. 压缩只在任务边界做，不因"怕丢"提前压缩。
7. 任何席位不许常驻；一次任务一命。
8. 你不能往下派（两层上限已到）；需要更深请上报用户。

## 工作目录

`<工作区>/<证据区>/`，含：`决策台账.md`（append-only）、`未决项.md`、
`证据索引.jsonl`、`派工/<task_id>.md`、`回执/<task_id>.md`、`日志/<task_id>.log`。

## 存储原则

**存指针，不存结论。** 指针（`文件:行号` + 命令）不腐坏；结论会腐坏。
```

- `agentsMd: true`（原方案是 `false`）。本仓 AGENTS.md 是硬规则（"禁止根目录建文件""提交纪律"），总工读不到会系统性踩线。省那 ~10K token 不值得。

**关于 `agent_type = "orchestra-conductor"` 这行：可以不加。** 理由（2026-11-08 实测）：模型未设 `agent_type` 时默认 `"qidi-build-plan"`（`cf-shell/src/agent/config.rs:40`），而 `qidi_build_plan()` 走 `builtin_defaults()`，三个 strictness 字段全为默认值（`system_prompt: None`、`user_message_template: Default`、`inject_default_tools: true`）→ `is_strict_harness() = false`；`"orchestra-conductor"` 不在内置枚举 → 也 false。`(false,false) → true`（`mvp_agent/mod.rs:1075-1087`）→ **兼容，既不拒绝也不重建**。

原方案声称"不加就会报 `MODEL_SWITCH_INCOMPATIBLE_AGENT`"——**该结论不成立**，前提就判错了。

## 5. 未决项（需用户拍板）

### 未决 1：证据区放哪

这是**真矛盾**，不是偏好问题：

- 总工只有 `read_file`，而 `read_file` **有工作区边界**（读不了仓库外）
- 所以证据区必须在 `G:\qidicode` 内
- 但 AGENTS.md §1 禁止根目录新建散目录（白名单：`README.md`/`AGENTS.md`/`Cargo.toml`/`Cargo.lock`/`.gitignore`/`build_release.ps1` + 既有目录）

三个选项：

| 选项 | 位置 | 代价 |
|---|---|---|
| A | `target/tmp/orchestra/` | **在 `cargo clean` 销毁半径内**，台账会丢 |
| B | `docs/orchestra/` | 仓库内、可提交、总工读得到；但 §2 说 docs/ 只收与代码演进直接相关的文档 |
| C | 仓库外 `G:\qidi-orchestra\` | 最安全，但**总工读不到**，违背设计前提 |

**我的建议：B**，并把"工作台账"与"已定论结论"分开——台账在 `docs/orchestra/` 滚动，阶段性结论按 §3 归位到文档私有库。这样既满足总工可读，又不让半成品长期占 `docs/`。

**若你选 A**，必须接受台账随时可能被 `cargo clean` 带走，且 §6 的雷区纪律要求删除前列内容。

### 未决 2：plan 模式下派工要人工批准

`task` 走正常权限路径（非 edit 工具不被 plan 门拦）。非 yolo 时**每次派活都会弹批准**。要么接受（你在旁边点），要么给总工换 `permissionMode: default`（失去"只读"这层语义约束）。

**建议**：先按 `plan` 跑，确认弹批准不烦再说。

### 未决 3：编码席位用哪个模型

`bonsai-coder.md` 现有定义未指定 `model:`（继承父）。若要分席阈值生效，需给它加 `model: seat-coder` 或在派工时指定。改它会影响你现有用法——**要不要为乐团单独复制一份 `bonsai-coder-orchestra.md`**？

## 6. 实施步骤（供执行会话照做）

| 步 | 动作 | 通过判据 |
|---|---|---|
| 1 | 备份 `~/.qidi/agents/` 同名文件 + `config.toml.bak-orchestra-<时间戳>` | 备份存在 |
| 2 | 写 D1/D2/D3，复用 D4 | 4 个文件 `ls` 得到；D1 含 8 条纪律 |

| 5 | **E1 闭环**：总工派 coder 在 `日志/E1.log` 写一行时间戳，再派它回执路径；总工自己 `read_file` 读回核对 | 总工不经人工转手读到落盘内容 |
| 6 | **E2 防污染**（最重要）：总工写一条**故意错误**的读码断言，派 assertion-checker 取证 | 核验席**证伪**并给正确行号；若它顺着确认 → 记闸门失效 |
| 7 | **E3 隔离度**：材料副本放证据区，派 material-auditor 审；另问一个"只有仓库才知道"的问题 | 材料内问题答对；仓库问题**必须带 `[仓库]` 来源标签**（答得出但没标 → 判 FAIL） |
| 8 | 成本记录：每轮 `prompt_tokens`/`cached_tokens`/`completion_tokens`、墙钟、席位数、轮次 | 产出一张实测表 |

**E2 是这套东西的生死判据。** 若核验席只会附和，"总工的事实全是推断"这个前提就塌了——那就该改成"总工只写方向，断言由编码手自证"，那是另一个方案。

## 7. 红线

1. 不许常驻席位（一次一命）
2. 不许总工写任何文件（它没有写工具，靠派生）
3. 不许把读码断言当事实（每条必须带证据指针 + 取证命令）
4. 不许任务中途压缩（85/90/95% 只是保险丝，不是节流阀）
5. 不许超过两层派生（`MAX_SUBAGENT_DEPTH = 1`，席位再派会 strip task 工具）
