## 2. 批次 A

### A1. M1 估算常数修正

- **现状**：`estimate_tokens_aware` 的 ASCII 为 `ascii_len / 4`，CJK 为 `ceil(cjk * 3 / 5)`。
- **目标**：ASCII 改为 `10 / 34`（即 3.4 字符/token，向下取整），CJK 改为 `4 / 5`（即 0.8 token/字，向上取整）。`other_bytes` 不变。
- **边界**：`BYTES_PER_TOKEN`、`estimate_tokens`、`estimate_chars` **一律不动**。它们被 read_file 截断、web_fetch 预算、工具定义和 base64 计数共用。
- **任务书要点**：
  1. 修改 `estimate_tokens_aware` 内部比率，更新文档注释中的公式与说明。
  2. 断言面按文件归属分账：`cf-chat-state/src/actor/state.rs`（内嵌 `#[cfg(test)] mod tests`）**10 处** + `cf-chat-state/src/actor/tests.rs` **11 处** = 21 处（**不是**全在 state.rs）；另 **cf-shell 两处**也在本任务范围内——`cf-shell/src/inspect/mod.rs` 的注释算式 + 断言**方向翻转**（M1-fix-plan §3.3），以及 `cf-shell/src/session/helpers/session_recap.rs` 的 filler **改构造**（按新速率反推字符数，**不是改期望值**，M1-fix-plan §3.4）。完整已定位面为 **28 处 / 5 文件**（`lib.rs` 5(+1 新增) + `state.rs` 10 + `tests.rs` 11 + `inspect` 1 + `session_recap` 1），余下按 M1-fix-plan §3 清单与 §3.0 机械重算规则收口。
  3. 新增校准夹具测试：聚合比落在 `[0.97, 1.01]`，MAPE ≤ 18%。夹具数据取自 `docs/token-optimization/tokenizer-calibration-and-plan.md`。
  4. 注意 `CJK_TOKEN_NUMERATOR` 与 `CJK_TOKEN_DENOMINATOR` 的常量名与现有调用处保持一致，若改值则同步更新注释。
- **验收**：§1 批次 A 门禁表所列**五项**全部通过——`cargo test -p cf-token-estimation`、`cargo test -p cf-chat-state --lib`、`cargo test -p cf-shell --lib`（C 盘热 target + `CARGO_PROFILE_TEST_DEBUG=0` + 按名称跳过既有环境失败项，清单见 AGENTS.md §12）、`cargo test -p cf-sampler`、`cargo check --workspace` 0 errors；出包后同会话 `/context` 百分比上升，压缩触发点提前到约 85%。
- **风险**：中低。只改余量，不改故障路径。

### A2. R11-A use_tool 并行截断：先仪表化，不急于修

- **现状**：并行 use_tool 时第一个调用的参数被截断。根因推测为 relay 在 SSE 重帧时吞字节，仓内链路已排除（见 R11 文档）。
- **任务**：
  1. `crates/codegen/cf-shell/src/.../tool_calls.rs` 中解析失败的 WARN 日志补充原始参数（封顶 2KB）、tool_name 与 call_id。
  2. `chat_completions.rs` 流末输出 debug 日志，逐 index 记录 `(id, name, args_len)`。
  3. 新增回归测试：第二个调用缺省 index，而 args delta 带 index 1，钉住累加器行为。
- **不做**：本批不修 relay 侧。relay 修复另起仓库提交，待日志确认后再派。
- **验收**：测试通过；日志字段可在一次复现中直接看到截断位置。
- **风险**：低。只增加可观测性，不改变解析逻辑。

## 3. 批次 B

### B1. R11-B spawn 参数静默回退改为显式告警

- **现状**：`spawn_subagent` 的 `model` 或 `capability_mode` 值非法时，解析器静默回退到会话默认模型，用户无感知。
- **任务**：对非法值输出 `tracing::warn!`，文案为 "spawn_subagent: invalid model value, falling back to session default"。**保留回退行为**，只把静默变显式。
- **测试**：构造非法 model 值，断言 warn 被记录，且回退到默认模型。
- **长期项（不在本批）**：spawn 参数走 structured output，从源头消除转义差异。记入后续设计稿。

### B2. R11-C resolve 测试隔离

- **现状**：`isolate_auth_sources`（`cli_models.rs:105`）只隔离 auth 路径与 9 个 EnvGuard，未隔离 config.toml 的模型目录（OnceLock 缓存）。新增 `[model.kimi-k3-moonshot]` 后，8 个 resolve 测试失败。
- **推荐方案（案 2）**：测试语义翻转，显式构造含 moonshot 的配置并断言 ModelCredentials 返回。不修改生产代码。
- **备选（案 1）**：`isolate_auth_sources` 补 `QIDI_HOME` 隔离。需先评估是否有测试依赖真实 home，**本批不采用，除非案 2 不可行**。
- **验收**：`cargo test -p cf-shell --lib cli_models` 全绿。
