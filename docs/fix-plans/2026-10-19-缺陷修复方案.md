## 批次 4（功能恢复：Dashboard 指定派发子代理类型 + 实时状态）——已确认（2026-10-19 用户确认范围）

### 现状调查结论（代码级，2026-10-19）

TUI 的子代理派发/监控机器**都在**：
- **Agent Dashboard**（`/dashboard`、`Ctrl+\`）：派发输入栏 + 模型选择（`dispatch_model`，sticky）+ prompt 模式 + worktree armed（`Ctrl+W`）+ 工作目录选择器；行内实时活动（`Running: cargo build`、子代理行的运行中工具、后台任务状态）；attach/stop/group/reorder、peek-reply、权限/问题跟进。

**确定的缺口**：Dashboard 的 `[+ New Agent]`/dispatch 只消费 `pending_model`/`pending_mode`（`dispatch/dashboard.rs:614-650`），**全仓无代理类型选择器**——用户无法在 TUI 手工指定派哪个类型的子代理（类型只能由主会话模型自己调 `spawn_subagent` 时决定）。

### F8 规格：Dashboard 派发增加代理类型选择（设计 A，端到端 `_meta` 通道）

**接线图（侦察实证）**：
- TUI 派发创建 top-level 会话走 `Effect::CreateSession`（`app/actions.rs:1319`）→ 执行处 `app/effects/mod.rs:119-175` 构造 `NewSessionRequest._meta`（现有 `modelId`/`sessionId`/chat 标志，**无 agent 通道**）。
- shell 侧 session/new 读 `_meta`：`cf-shell/src/agent/mvp_agent/acp_agent.rs:838-848`（`sessionId`/`modelId`/`yoloMode`/auto 模式），同样**无 agent 通道**。
- 代理解析链已存在：命名代理经发现链解析（`.qidi/agents/`、`~/.qidi/agents/`、内置——`cf-shell/src/agent/config.rs:1658` 注释）；headless `--agent` 即走 `apply_agent_flag` → `config.agent.name = Some(name)`（`cf-pager/src/headless.rs:322/909`）。**TUI 多会话场景不能用 config 级绑定（进程共享会互相污染），必须走 per-session `_meta`。**

**改动点**：
1. **cf-pager（UI 状态）**：`DashboardState` 增 `dispatch_agent_type: Option<String>`（语义仿 `dispatch_model`：sticky、随派发消费、`/` 斜杠或快捷键可改）；选择器列表数据源复用 agents 模态的发现结果（内置 `general-purpose`/`explore`/`plan` + `~/.qidi/agents/*.md` 自定义代理如 coding-default/office-bid；默认 `general-purpose`）。
2. **cf-pager（派发链路）**：`dispatch_dashboard_create_new_agent_with_detail`（`dispatch/dashboard.rs:614`）与 `dispatch_dashboard_dispatch` 的 new-session 臂把所选类型随 `model_id` 一并下传；`Effect::CreateSession`（及 `CreateWorktreeSession`，`actions.rs:1336+`）增 `agent_name: Option<String>` 字段；执行处（`effects/mod.rs:139` 附近）写入 `_meta["agentName"]`（空串不写，与 modelId 的 filter 处理一致）。
3. **cf-shell（会话创建）**：`acp_agent.rs` session/new 读 `_meta.agentName`（仿 `custom_model_id` 读法+非空 filter）；有值则经同一发现链解析代理定义并绑定到本会话（覆盖 `config.agent.name` 默认）；解析失败（未知代理名）返回明确 `invalid_params` 错误，**不静默回退**。
4. **行标签**：新会话的 dashboard/tasks-pane 行需显示 agent 类型标签（如 `explore`）——确认 top-level 行的标签构造处（`views/dashboard/row.rs` 的 top-level 行，非 SubagentInfo 行）并把 session 的 agent 名纳入。
5. **`[+ New Agent]` 详情视图**：进入时展示/可改已选类型（与模型选择同层呈现）。

**范围收紧（重要）**：**v1 只做 agent type，不做 persona**——用户指南明确 persona 语义仅作用于 subagent（"Scope: Subagents only"），top-level 会话挂 persona 无定义；如后续要"以子代理身份派发"（parent 下挂 child）再议，那会改变会话生命周期语义，属独立需求。
