# qidicode R11 修复方案（三修复——台式机同步版）

> 2026-10-18。本方案对应 dp（DeepSeek 编码手）任务链的三个基建修复——**R11 批中断待续**，方案完整存档供台式机侧同步评审/续做。

## 修复 A：use_tool 并行调用参数截断（生产正确性 bug）

### 现象（台式机实测 100% 复现）
同一消息块并行发起多个 use_tool 调用：**第一个**调用的 JSON 参数被截断（`missing field 'tool_name'` + `EOF while parsing an object`）；第二个正常；**串行完全正常**。MCP Concise 模式下所有 MCP 调用都走 use_tool——放大爆炸半径。

### 根因分析（step-5 深挖的结论——仓内代码链全部洗清）
- **到达 tool_calls.rs 的参数字符串已经是残的**（两个报错都是下游症状）：`prepare_tool_call` 解析失败（tool_calls.rs:822-826）→ repair 修复不了残缺（helpers/tool_input_parsing.rs:29-32 需要 ≥2 完整对象）→ 兜底 `{"raw": ...}`（:882）→ parse 报 missing field
- **仓内嫌疑全部排除（行号免责）**：chat_completions 累加器（BTreeMap index 分桶+纯追加+:735-969 回归测试）/messages.rs/Responses/SSE 分帧/执行循环（串行 prepare）/use_tool 分发（B-12 门控作用在已解析输入）/ToolCallDelta serde（四象限测试）/xAI buffered（只喂 UI）
- **最大嫌疑：relay/prov 的 SSE 重帧**（luyou/codely 中转把上游 SSE 重组帧时在第一个并行 tool_call 的 arguments delta 帧边界系统性吞字节——100% 解释全部现象）

### 修复方案
1. **仓内 instrumentation（立即做）**：tool_calls.rs:876 的 WARN 补**原始参数**（封顶 2KB）+tool_name+call_id——下次复现自己开口，不用再猜
2. **chat_completions.rs 流末 debug 日志**：逐 index 的 (id, name, args_len)——归因从"带日志复现猜"降为"读一行日志"
3. **怪癖回归测试**：第二调用 index 缺失（默认 0）而 args delta 带 index 1 的场景钉住
4. **relay 侧修复**（定位到后）：qidi-relay 仓另起 commit

## 修复 B：spawn 序列化器静默容错

### 现象（笔记本本会话 10+ 次实测）
spawn_subagent 的 model 字段值为非法（裸值/JSON 转义损坏——**GLM/DeepSeek 系的 JSON 转义风格差异**：漏引号/裸枚举值）→ qidi 解析器**静默忽略→回退继承主会话模型**——不报错不警告——用户看到"编码手路由到错误模型"但不知道"模型输出的 JSON 坏了"。

### 修复方案
- **解析器显式警告**：对非法 model/capability_mode 值 tracing::warn（"spawn_subagent: invalid model value, falling back to session default"）——回退行为保留（不破坏兼容）但从静默变显式
- **长期**：spawn 工具参数走 structured output（模型侧强制 JSON 合规——彻底消灭转义差异）

## 修复 C：resolve 测试隔离缺陷

### 现象（笔记本 10-17 实测）
config.toml 新加 `[model.kimi-k3-moonshot]` 条目后，cf-shell 8 个 resolve 系测试挂——**isolate_auth_sources（cli_models.rs:105）只隔离 auth 路径+9 个 EnvGuard，config.toml 的模型目录（OnceLock 缓存）读取未隔离**——resolve 读到 moonshot 条目返回 ModelCredentials 而非测试期望。

### 修复方案（两案）
- **案 1**：isolate_auth_sources 补 QIDI_HOME=EnvGuard（temp dir）——**先评估影响面**（其他测试可能依赖真实 home——如破坏换窄隔离）
- **案 2**：测试语义翻转（显式构造含 moonshot 的 cfg+断言 ModelCredentials 返回）——**推荐**（不改生产代码、测试更真实）

## 三个修复的优先级
**A（并行截断）> B（spawn 警告）> C（测试隔离）**——A 是生产正确性 bug（100% 复现+MCP 核心路径）；B 是可观测性（不阻断但有坑）；C 是测试基建（阻塞 CI 但可绕）。
