## 0. 结论摘要

六工序流水线的**骨架不吸收**（六角色分权重构、四态门禁体系、记录三轨台账、init-pipeline 入驻流程）——AGENTS.md §9 实践在角色分权与成本经济学上已比它细，AGENTS.md 本身是比一次性调研更优的"项目知识完成态"（数月实测勘误迭代 vs 一次性调研）。

吸收其**机械纪律**进 dev-orchestra 技能正文（改动 1–7），四条总原则：

1. **纪律优先于结构**——只吸收证据核验、送检前置、回溯标注这类可机械执行的条款，不新增角色、不新增文件；
2. **一句话级成本**——所有新增规格书字段均按一句话设计（定性/扩展成本/被否方案/回溯标注）；
3. **按任务规模分级**——唯一的重门（阶段 1.5 规格送检）有明确豁免判据，小任务不付流程税；
4. **不双写**——技能正文为唯一落点，AGENTS.md 不复制新增内容（防双源漂移；AGENTS.md 仍由 §0 维护协议独家裁决）。

## 1. 前置对比结论（摘要，自含）

| 维度 | six-stage-pipeline | 乐团模式现状 |
|---|---|---|
| 质检主体 | 独立 Eval（做判分离，"批卷的得是另一个 AI"） | 指挥官亲审 + §9 双席交叉审计（首席/巡查/第二席） |
| 反幻觉 | 全断言证据链（三类证据 + L0 前置核验 + 禁语清单） | 数字溯源 + 口径交叉（限数字/度量域） |
| 回环 | 门禁四态（过/警/回环/转人工），回环 2 轮上限 | ACCEPT / REJECT / SPEC GAP，返工 3 轮上限 |
| 知识沉淀 | biz/sys/reports 三轨 append-only 台账 + 沉淀评估收尾门 | AGENTS.md 活文档 + memory + rubrics 错题本（被动触发） |

一句话本质判断：**它把反幻觉、证据传递、沉淀触发做成了机械门禁（我们的弱项，本次吸收）；我们把成本经济学、度量口径治理、环境实测深度做到了它没有的水平（保持项，不吸收它任何结构）**。

### 改动 5：阶段 3 证据核验前置门

- **插入位置**：阶段 3 审计清单置顶新增第 0 项；审计报告模板加一行
- **新文本**：
  > 0. **证据核验（前置，先于以下一切判断）**：核对编码手报告与 diff 的证据面——引用的 `文件:行号`/符号逐条抽查存在性（**改动面引用全查，行为描述抽查下限 = min(3, 实际行为描述数)**——审计 F4），所贴命令输出抽 1–2 条与实际复跑比对；**报告引用总数为 0 → 直接 FAIL（零引用报告本身违反派工契约，防空转即 PASS）**；发现虚构或无证据断言 → **整批驳回记「证据缺失」**，不进入逐项审计。"应该/一般来说/通常"式表述一律视为无证据。

  > **外派审计防火墙**：向 §9 审计席派发审计任务书时，只给：规格书全文 + diff/文件清单 + 验收命令——**不给编码手的自我解释与过程讨论（防被说服）**。指挥官亲审不受此限（裁决者需要全信息）。

### 改动 7：审计四态 + 沉淀评估收尾门

- **插入位置**：审计结论行 + 阶段 5 新增第 4 步 + 战报格式
- **新文本**：
  - 结论行改四态：`结论: ACCEPT / WARN / REJECT(需返工) / SPEC GAP`
  - WARN 定义（**正向穷举，未列即禁**——审计 F3）：**WARN 仅限风格、命名、可读性、文档性偏离**，记录理由后放行、不进返工单、必须列入战报；其余任何维度 FAIL（含**范围一致性/越界改动**、正确性、安全、验收失败、证据核验、实质性规范问题）一律 REJECT。
  - 维度→总论映射（审计报告模板补一行说明）：硬维度（证据核验 / 范围一致性 / 正确性 / 安全 / 质检 / 数字溯源 / 口径交叉）任一 FAIL ⇒ REJECT；纯风格类 FAIL ⇒ WARN（记录理由）或 REJECT，由指挥官裁量并在报告注明。
  - 阶段 5 新增第 4 步：
    > 4. **沉淀评估（收尾必判）**：本次任务是否命中——重复出现的编码/审计动线 → 新技能或技能条款（走 /create-skill）；新发现的存量规律/坑 → AGENTS.md 对应节（按 §0 维护协议；涉推送纪律等生产语义变更先经用户确认）或 docs/audit-rubrics/RUBRICS.md（**查重合并，不另开新条**）；通用设计取舍 → docs/<主题>。均不命中：战报记一句「沉淀评估：无可复用项」，不强行沉淀。
  - 战报格式新增：`### 沉淀评估` 一节（命中项及去向 / 无可复用项）
- **吸收源**：门禁四态之"警告"（R05 §2：Eval L2 建议项/reviewer Suggestion → 记录理由后放行）；沉淀评估 = R05 §5.3（"收尾必做……命中任一即沉淀"）+ feature-dev SKILL.md 收尾第 4 条（"均不命中：在 [RELEASE] 记一句「沉淀评估：无可复用项」，不强行沉淀"）——v1 曾把后句误归于 R05 §5.3，审计 F6 勘误
- **理由**：WARN 给 L2 级问题一条**不阻塞路径**（现状只有"放过"或"整轮返工"两端）；沉淀评估把 AGENTS.md 维护协议/rubrics 合入从"被动触发"变"收尾必判"，命中才动手，多数任务就是记一句话。
- **衔接边界**：沉淀动作仍受 §0 裁决顺序约束（实测事实 > 本文件 > 会话习惯），本改动只加**触发点**，不改裁决权与用户确认权。
