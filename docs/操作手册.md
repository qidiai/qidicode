# QIDI Code 操作手册（中文）

> 本手册面向不熟悉英文 / 不熟悉命令行工具的日常使用者。
> 所有命令都在 **PowerShell** 中执行（Windows 的黑色命令窗口）。

---

## 一、这是什么？

**QIDI Code** 是一个基于 Rust 构建的「终端 AI 编码助手」，可以帮你写代码、改代码、查代码、跑测试。
本项目就是它的完整源代码仓库。你在代码里看到的大量 `cf-xxx` 目录，是它的各个功能模块（crate）。

| 术语 | 意思 |
|---|---|
| **workspace / 工作区** | 整个 `G:\qidicode` 文件夹，包含几十个子模块 |
| **crate** | 一个功能模块（比如 `cf-shell` 是主交互逻辑，`cf-pager` 是界面） |
| **target** | 编译产物目录（程序运行时会生成，可以随时删除重建） |
| **git / 提交** | 给代码「拍快照」，方便以后回滚或查看历史 |

## 二、常用命令速查

### 2.1 构建（把源代码变成可运行的程序）

```powershell
cargo build
```

- 成功后程序在：`target\debug\qidi.exe`
- **首次或大改后构建较慢（几分钟）**，之后只编译改动的部分，很快。
- 想构建「发布版」（更快更小，但构建更慢）：

```powershell
cargo build --release
```

### 2.2 运行 QIDI Code

```powershell
cargo run
```

或直接运行编译好的程序：

```powershell
.\target\debug\qidi.exe
```

### 2.3 检查代码（不生成程序，只查错）

```powershell
cargo check
```

- 比 `cargo build` 快，适合改完代码先查有没有错误。
- 想连「测试代码」一起检查（推荐，能发现更多问题）：

```powershell
cargo check --all-targets -j 2
```

`-j 2` 是限制同时编译 2 个模块，避免电脑内存不够导致编译崩溃。电脑好可以去掉。

### 2.4 运行测试

```powershell
cargo test
```

- 运行所有模块的测试。
- 只想测某一个模块，比如 `cf-shell`：

```powershell
cargo test -p cf-shell
```

### 2.5 清理（删除编译缓存，释放硬盘空间）

```powershell
cargo clean
```

- 会把 `target` 里的编译结果全部删掉，**下次构建会重新全部编译（很慢）**。
- 只想清理「增量缓存」（释放约 30 GB，但保留已编译的库）：

```powershell
Remove-Item target\debug\incremental -Recurse -Force
```

## 三、日常开发流程

给代码做了修改后，按这个顺序操作最稳妥：

1. **改代码**（用编辑器或让 QIDI Code 帮你改）
2. **检查错误**：`cargo check --all-targets -j 2` —— 看到 `error` 就说明有问题，`warning` 是提醒不阻塞
3. **看改了哪些文件**：`git status`
4. **提交保存**：

```powershell
git add .
git commit -m "这里写这次改了什么（用中文也行）"
```

5. 如果后悔了，查看历史：`git log --oneline`

> ⚠️ 注意：`git add .` 会把**所有**改动一起提交。如果只想提交某些文件，把 `.` 换成文件名。

## 四、Git 常用操作（中文对照）

| 你想做的事 | 命令 |
|---|---|
| 看当前有哪些改动 | `git status` |
| 看某个文件改了什么 | `git diff` |
| 提交本次改动 | `git add .` 然后 `git commit -m "说明"` |
| 看提交历史 | `git log --oneline` |
| 撤销最后一次提交（未推送到服务器时） | `git reset --soft HEAD~1` |
| 删除一个文件（同时从 git 移除） | `git rm 文件名` |
| 把文件改名 | `git mv 旧名 新名` |

## 五、常见问题

### 5.1 编译很慢怎么办？
- 多用 `cargo check` 而不是 `cargo build`（前者快很多）。
- 不要频繁 `cargo clean`（清一次要重编很久）。
- 如果内存不足导致编译报错（`STATUS_STACK_BUFFER_OVERRUN`），用 `-j 2` 限制并行度。

### 5.2 报错里有大量 `LF will be replaced by CRLF` 的警告？
- 这是 Windows 换行符格式提示，**无害**，可以无视。

### 5.3 `target` 目录占了大量硬盘空间？
- 先试 `Remove-Item target\debug\incremental -Recurse -Force`（删增量缓存，最快见效）。
- 还不够再 `cargo clean`（全删，重建慢）。

### 5.4 想重新完整编译，避免旧缓存干扰？
```powershell
cargo clean
cargo build
```

## 六、项目目录速览

| 路径 | 是什么 |
|---|---|
| `crates/codegen/` | 核心功能模块（`cf-shell` 主逻辑、`cf-pager` 界面、`cf-sampler` AI 请求等） |
| `crates/common/` | 公共基础库 |
| `crates/build/` | 构建辅助 |
| `tools/` | 独立小工具（`finance-agent` 记账助手、`media-gen-agent` 媒体生成） |
| `docs/` | 文档（本手册在这里） |
| `target/` | 编译产物（可删） |

### 常用配置文件

- **主配置**：`~\.qidi\config.toml`（模型、API 密钥、界面设置）
- **MCP 服务器**：`.mcp.json`（项目根目录，连接 AI 辅助工具）
- **代码格式规范**：`rustfmt.toml`、`clippy.toml`（一般不用动）
