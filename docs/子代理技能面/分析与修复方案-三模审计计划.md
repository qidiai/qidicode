# 子代理技能面缺口：根因分析 · 修复方案 · 三模审计计划

> 2026-10-16 · 触发：实测子代理不能调用技能（DeepSeek 子代理 72 次调用深挖）· 状态：待实施

## 一、根因分析（行级）

### 缺口 1：激活层——技能调用工具没进 QIDI 默认工具集
- `cf-agent/src/config.rs:270 default_qidi_build_toolset()`：只有**安装型** `DeploySkillTool`（注释自述"the sanctioned channel for installing a user skill"——设计意图里它只是安装通道）
- 技能调用工具 `OpenCodeSkillTool`（id=`"skill"`，ToolKind::Skill）**只接在 `opencode_toolset()`（config.rs:529）**，QIDI 构建从未接入
- 而放行层早就就绪：`SubagentCapabilityMode::allowed_tool_kinds()`（task/types.rs:214-308）各模式都含 `ToolKind::Skill`；`cf-workspace/capability.rs:135` 把 Skill 列为 always-allowed meta 工具
- **定性：门开着、货没上架。设计应支持、实现未接通**

### 缺口 2：可见层——子代理技能清单注入为 0
- 会话启动走 `session_setup.rs:71 inject_baseline_skill_reminder()` → `apply_pending_skill_update()` → 有"新技能"才 wrap 注入
- announcement_state 是**跨会话/跨受众共享账本**：411 条全"已宣告"（4 个 session 文件同值，继承态）→ 子代理启动时"无新可宣" → **连一条清单块都拿不到**
- **定性：announcement 账本的"宣告一次"假设只对单一受众成立；primary/subagent 多受众把假设打破了**

### 缺口 3（非缺陷）：内容层本就可用
- `read_file` 出 workspace 边界被拒，但 `run_terminal_command`+`Get-Content -Encoding UTF8` 可读任意 SKILL.md——兜底已验证

## 二、修复方案（F1-F3）

### F1 激活层接线（小）
1. `default_qidi_build_toolset()` tools vec 追加技能调用工具（优先复用 `OpenCodeSkillTool`；若其对 opencode 会话管线有硬依赖，则抽 qidi 原生 `SkillTool` 薄壳复用同一核心）
2. 能力层零改动（Skill kind 已放行）
3. 测试：工具集含技能工具断言 + 子代理集成测试激活一个无副作用技能（如 `help`）拿到正文
4. 工作量：0.5 小时级（编码手）

### F2 可见层注入（中）
1. 子代理会话（audience=subagent）**无条件注入基线清单**，绕过共享 announcement 账本（或账本按 audience 分账）
2. 注入内容用 **Essential 投影**（复用极简 Phase 1 的 listing 投影，~29 条 ≈3-5KB）——**不注全量 411**（114KB 上下文税不可接受）
3. 配置旋钮：`[skills] subagent_listing = "essential"|"full"|"none"`（缺省 essential）
4. 测试：子代理 prompt_context 含清单块且为投影集；主会话行为不变；账本不被子代理污染
5. 工作量：2-3 小时级（编码手）+ 回归

### F3 安全网（小，可选）
1. 子代理可激活技能默认= Essential 白名单；GPU/OCR/起服务类技能（qwen-image-lowvram、pdf-to-word-ocr、seal-extractor 等）对子代理**排除或转 Ask 批准**
2. 测试：越权激活被拒断言

### 执行序
F1+F2 一并派单（同 crate 不同文件可并行或合并一人），F3 视用户意见；每项修复带测试；完成后进三模审计。

## 四、优化建议（修复之外）

1. **清单瘦身**：子代理清单用 name+description-only（去绝对路径）→ token 再减半
2. **任务书点名技能**（乐团语义）：spawn 任务书带 per-task 技能白名单——当前 workaround（指挥官把 SKILL.md 要点写进任务书）今晚已验证有效，修复落地后升级为"点名+激活"双层
3. **Essential 单一事实源**：F2 的投影必须复用 listing.rs 既有投影，勿造第二套白名单（防双源漂移）
4. **GPU/资源类技能的 approval 门**：即便 F3 默认排除，也建议全局加"起服务类技能需显式批准"安全网
5. **账本分账**：announcement ledger 按 audience 分账是长期正解（本次 F2 的最小实现是旁路，分账是根治）
6. **审计通道固化**：三模审计走 CLI headless `-m` 通道（今晚 3 席全部实证），spawn 直调仅用于 DeepSeek slug——写入常规演练

### 🔴 B-1（双席独立发现，F2 阻塞）：注入缝在生产子代理流程不可达
F2 改的 inject_baseline_skill_reminder 生产调用方仅两个：initialize（← SessionCommand::Initialize，唯一发送点 agent_ops.rs:3658，仅 ACP 主会话 new_session）与 handle_rebuild_agent_for_definition（模型切换）。**子代理 spawn（handle_request.rs:1076→spawn_session_on_thread）只发 CopyFile+Prompt，从发 Initialize**——conversation 由 spawn.rs:934-980 install_system_prompt+replace_conversation 直接装配。F2 净生产效果 = 0。测试假阳性成因：6 个测试全部 actor 方法直驱，绕过 SessionCommand 命令层（O-1 结构盲区）。

### 根因勘误（双席一致裁决，R-002 案例）
- ❌ 证伪：本文档 §一缺口 2 的"子代理继承 411 条已宣告账本"叙事——子代理 persisted_announcement_state=None（handle_request.rs:1140），**不继承账本**
- ✅ 真因主：调用链断点（B-1）；真因次：**finalize 预填账本**（registry/types.rs:1117-1125：seed(startup_skills)→take_pending 丢弃 effects 但 announced_names 被 format_announcement 填满 startup 全量）→ seed 门 nnounced_names.is_empty() 不成立 → pending 不设 → drain 无货
- 改动者存疑"pending/listing 语义链"：部分正确（次因），未击中主因

### F2 返工要点（融合两席清单，返工单已派）
1. 注入缝搬至子代理真实初始化点（spawn.rs:934-980 install_system_prompt 后/conversation 装配点，盖 New/Forked/Resumed 三类）
