# 审计准则库（Rubric Library）——qidicode 的错题本

> **本文件是活文档**（对齐 AGENTS.md §0 维护协议）。裁决顺序：**实测事实 > 代码 > 本文件 > 会话习惯**；本文件与 AGENTS.md §0 冲突时**以 AGENTS.md 为准**。
> 消费方式：**注入制**——仅由 audit-rubrics 技能在审计规格中注入适用条目；编码手**不要求、不建议预读**（该文件对编码手可见，注入制是**降低**而非消除 gaming 暴露面）。
> **清单是下限，不是上限**——发现清单外的新问题永远优先于对照清单。

## 使用协议

| 项 | 规则 |
|---|---|
| 触发标签词表（受控） | `默认值` / `门控` / `安全网` / `文档` / `测试卫生` / `并发`；重命名须留 alias；扩展需走维护协议 |
| ID 治理 | 一经分配**不可变、不回收、不重编号**；归档保留 ID；晋升（promote）后在原位置留 redirect 标记 |
| 注入预算 | 每次审计**注入 ≤5 条**（真闸门）；清单上限 50 条，超出即须归档 |
| 归档判据（出口闸） | 同类审计连续 3 次适用而未被引用（fired 统计）→ 移入 `## 归档` |
| 入口闸 | 新增条目**先查重合并**（同主题合并进已有条目，不另开新条）；每 5 轮审计盘点一次清单健康度 |
| 防锚定流程 | **先自由审查（发现先落盘）→ 后对照清单**；审计报告**必含"rubric 未触发类说明"一节**；规格模板的"适用条目：R-xxx"必填行**后置到模板末尾** |
| 证据纪律 | 一律引 **commit hash**；行号标注"时效见 commit" |
| promote | 条目成为普适规则时 **move 进 AGENTS.md**（原处留 `R-xxx → promoted to AGENTS.md §Y` redirect，不留副本）；AGENTS.md 侧保留 R 编号作锚 |
| 审计报告落位 | 一律 `qidiwork-docs/审计评审/YYYY-MM-DD-主题.md`；**禁止落 `target/`**（cargo clean 销毁半径） |
| 更新触发 | 返工/审计闭环后合成 durable 教训；commit 信息注明 `rubric: <来源>` |

## 活跃条目（14）

### R-001 【默认值】改公共默认值须全仓核断言点
- **触发**：审计任何"修改公共默认值"的 diff
- **规则**：实现改动之外，必须 `git grep` 该默认值的**全部断言点**（跨 crate、跨测试文件），逐处核对——不止改实现和最显眼的一个测试
- **证据**：`d81a137`（T1 改 `min_score` 默认只同步 `cf-shell/src/config/tests.rs:327`，漏 `acp_session_tests` 两个孪生测试）；修复见 `f98978f`

### R-002 【文档】"无生产调用方"类断言必须全链验证
- **触发**：审计中出现"某路径无调用方/latent/不可达"的判断
- **规则**：必须全仓 grep + 跨 crate 追 Effect/调用链后才可下结论；双模型分歧时以代码证据裁决
- **证据**：Step5 曾判 gc"无调用方（latent）"，K3 在 `cf-shell/.../spawn.rs:700-717` 找到**每会话启动即跑**（armed）——914a930 排雷的前提

### R-003 【测试卫生】新增/修改的关键断言必须带消息
- **触发**：审计新增/修改的测试断言
- **规则**：`assert!(cond, "上下文: {a} vs {b}")`——裸断言失败时无法自证身份；**存量豁免**=本文件建立日（2026-09-26）之前的 commit 不追责
- **证据**：`memory_config_tests.rs:57-61` 现行裸断言（时效见 `f98978f`）——排障时曾因无消息初判失败断言身份错误

### R-004 【安全网】best-effort 失败必须升级可见
- **触发**：审计任何"备份/快照/守卫"类 best-effort 逻辑
- **规则**：失败路径不得仅 debug 后照常执行危险动作——须 `warn!` + 行为降级（跳过受保护的危险操作）
- **证据**：Fv2 pre 快照失败原仅 debug 且照常删除 session 日志；修复见 `914a930`（M2：warn + 跳过 `clean_processed_sessions`，`acp_session_impl/memory_dream.rs:442-501`）

### R-005 【测试卫生】防"改测试凑通过"
- **触发**：审计任何对**已有测试**的改动
- **规则**：显式检查断言被放宽/删除/加 `#[ignore]`/期望值"迁就现实"；区分"修正测试（默认变更的正当连带）"与"迁就 bug（作弊）"——要求改动者给出连带正当性论证
- **证据**：`f98978f` 的 0.41→0.35 属默认覆盖语义的正当修复；机制上必须可区分（本会话 Step5 第五轮逐条判定过合法性）

### R-006 【文档】文档/注释的事实陈述逐条对照代码
- **触发**：审计写入 AGENTS.md/README/规格/注释的事实性内容
- **规则**：每条可验证声称逐条对照代码核实；文件头附维护协议（快照≠法律）
- **证据**：AGENTS.md 初版两处硬错误（"pre-commit 钩子"不存在、quant-platform 路径失真）被双审计抓出；修订见 `11b2c60`

### R-007 【默认值】常量/默认/遥测数字与机制侧同源
- **触发**：审计新写或改动的常量、默认值、遥测上报数字
- **规则**：引用机制侧的配置/枚举（如 `MemoryWatcherConfig::default().stale_claim_secs`），**禁止复制数字字面量**
- **证据**：doctor `STALE_CLAIM_SECS=60` 硬编码漂移（修复见 `fd07263` F3）；遥测 `half_life_days` fallback 30→7（`d81a137` T4，K3 于 `spawn.rs:784` 亲验与 `types.rs:2220-2227` 同源）

### R-008 【并发】注释声称的顺序 ≠ 执行顺序
- **触发**：审计声称顺序/原子性/回滚语义的注释或文档
- **规则**：凡声称"先 A 后 B / 失败则回滚"，必须对照真实执行模型（effect spawn 顺序 / await / 锁范围）验证
- **证据**：E′ `router.rs` 注释曾声称"persist 失败先回滚再 switch"，实际两 effect 并发无门控；修复见 `583dc51`

### R-009 【门控】新守卫须对称检验假阴性
- **触发**：审计新增的任何 guard/门控/前置条件
- **规则**：堵住误报的同时，必须检验是否引入**漏报**（时序窗口、未初始化降级、子视图/穿透路径）
- **证据**：B′ 门控（`583dc51`）堵了 /flush 误触，却引入 `available_commands` 未达窗 + 子代理视图漏报两类假阴性；修复见 `fd07263`

### R-010 【默认值】改默认值须为旧分支重建单测
- **触发**：审计改默认值的 diff（与 R-001 配对，比它深一层）
- **规则**：为被新默认遮蔽的**旧默认/回退分支**保留（或新建）直接单测，不能只改默认路径断言
- **证据**：T1 后 `None` 回退分支失去全部直接单测，靠集成测试间接覆盖；契约测试补于 `f98978f`

### R-011 【测试卫生】新测试的外部二进制依赖必须可跳过
- **触发**：审计新增测试的依赖清单
- **规则**：依赖 git/网络/外部二进制的测试必须探测缺失并 skip，不得让无该环境的机器测试失败
- **证据**：Fv2 测试曾硬依赖 git；修复见 `914a930`（M5：`ensure_hermetic_git_on_path` + skip 守卫）

### R-012 【文档】返工 commit 必须进审计队列
- **触发**：每轮返工/修复提交后
- **规则**：审计范围声明覆盖 **commit 区间**而非单点——未经审计的返工 commit 不得视为已验证基线
- **证据**：`fd07263` 曾未经审计进入基线（讽刺的是它修的正是审计自己的发现）——Step5 第七轮亲历教训

### R-013 【文档】同名概念跨层分叉必须标注层级
- **触发**：审计文档/规格中出现的同词异义概念
- **规则**：同一名称在不同层有不同语义时（CLI 别名 vs 枚举值），文档必须显式标注各自层级
- **证据**：`/effort max`（采样层 CLI 别名=xhigh）vs 技能 frontmatter `Effort::Max`（独立枚举值）；AGENTS.md §7 已写入（`11b2c60`）

### R-014 【文档】审计规格强制"声称-判定表"格式
- **触发**：编写任何审计规格/报告时
- **规则**：逐条 per-claim 列【✅属实 / ❌不实（附证据）/ ⚠️无法核实（标注采信级别）】——表格化是抓硬错误的主要手段
- **证据**：本会话八轮审计的全部硬错误（两处 AGENTS.md 错误、TOCTOU、gc 地雷、T1 连带测试）均由该格式抓出
