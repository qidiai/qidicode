# 审计准则库（Rubric Library）——qidicode 的错题本

> **本文件是活文档**（对齐 AGENTS.md §0 维护协议）。裁决顺序：**实测事实 > 代码 > 本文件 > 会话习惯**；本文件与 AGENTS.md §0 冲突时**以 AGENTS.md 为准**。
> 消费方式：**注入制**——仅由 audit-rubrics 技能在审计规格中注入适用条目；编码手**不要求、不建议预读**（该文件对编码手可见，注入制是**降低**而非消除 gaming 暴露面）。
> **清单是下限，不是上限**——发现清单外的新问题永远优先于对照清单。

## 使用协议

| 项 | 规则 |
|---|---|
| 触发标签词表（受控） | `默认值` / `门控` / `安全网` / `文档` / `测试卫生` / `并发`；重命名须留 alias；扩展需走维护协议 |
| ID 治理 | 一经分配**不可变、不回收、不重编号**；归档保留 ID；晋升（promote）后在原位置留 redirect 标记 |
| 注入预算 | 每次审计**注入 ≤5 条**（真闸门）；清单上限 50 条，超出即须归档 |
| 归档判据（出口闸） | 同类审计连续 3 次适用而未被引用（fired 统计）→ 移入下方「归档」区 |
| 入口闸 | 新增条目**先查重合并**（同主题合并进已有条目，不另开新条）；每 5 轮审计盘点一次清单健康度 |
| 防锚定流程 | **先自由审查（发现先落盘）→ 后对照清单**；审计报告**必含"rubric 未触发类说明"一节**；规格模板的"适用条目：R-xxx"必填行**后置到模板末尾** |
| 证据纪律 | 一律引 **commit hash**；行号标注"时效见 commit" |
| promote | 条目成为普适规则时 **move 进 AGENTS.md**（原处留 `R-xxx → promoted to AGENTS.md §Y` redirect，不留副本）；AGENTS.md 侧保留 R 编号作锚 |
| 审计报告落位 | 一律 `qidiwork-docs/审计评审/YYYY-MM-DD-主题.md`；**禁止落 `target/`**（cargo clean 销毁半径） |
| 更新触发 | 返工/审计闭环后合成 durable 教训；commit 信息注明 `rubric: <来源>` |

### R-020 【默认值】matplotlib 中文字体小字号静默丢失；ASCII 正常渲染极具隐蔽性
- **触发**：用 matplotlib（或任何经 FreeType 的渲染栈）生成含中文的图表/图片，尤其是标书图表
- **规则**：①本机 `simsun.ttc` 在 matplotlib 下 **<8.5pt 的中文字形全部不渲染**（FreeType 位图 strike 选择问题；cmap 28849 字形完整、findfont 解析正常，**字体验证全绿而渲染静默失败**）——`Microsoft YaHei`（msyh.ttc）全字号正常；生成脚本一律 `font.sans-serif=["Microsoft YaHei","SimSun"]` 或将全部字号≥8.5pt；②**失败模式极具隐蔽性：ASCII 字符（数字/字母/半角符号）在小字号下照常渲染**——"7d""11-05""5398"清晰可见而中文整体消失，肉眼扫图极易判"正常"；③凡生成中文图表，**成图后必须逐张目检**（不能只看脚本无报错），重点核对小字号标签区；④诊断方法：同文本多字号对照渲染（6.5→13pt 阶梯）即可定位阈值，勿猜
- **证据**：2026-10-18 瑶海技术标配图战役——横道图/网络图/总平面图三图的小字号中文全部静默丢失（横道图只剩"11/48/60/88/82/19/10""5530"等 ASCII 数字、网络图箭线标签只剩"7d/15d/26d"、总平面图材料堆场只剩"/ /"斜杠），而图题（13pt）、轴标签（9-10pt）中文正常；首轮生成后靠逐图目检+阶梯字号测试定位（8.4pt 失败/8.5pt 成功的阈值），切换雅黑后全尺寸恢复

### R-001 【默认值】改公共默认值/常量/比率须全仓核耦合点
- **触发**：审计任何"修改公共默认值、公共常量或共享比率"的 diff
- **规则**：实现改动之外，必须全仓核对该值的**全部断言点与非断言耦合点**（跨 crate、跨测试文件），逐处核对——除测试断言外，还必须检查逆函数、token↔字符/字节等截断与预算换算、golden 硬编码值、生产注释、镜像实现及阈值消费方；枚举式修复必须附"同 bug 类全枚举"步骤。验收按受影响 crate 写全量测试目标，`cargo check` 不得替代测试；涉及 cf-shell 时，派工模板固定写入 `cargo test -p cf-shell --lib`（按 AGENTS.md §12 的 C 盘热 target、DEBUG=0 与既有环境失败跳过口径），不得只列 `cargo check` 或不覆盖该 crate 的其他门禁
- **证据**：`d81a137`（T1 改 `min_score` 默认只同步 `cf-shell/src/config/tests.rs:327`，漏 `acp_session_tests` 两个孪生测试）；修复见 `f98978f`
- **证据**：`5e0c0521`（2026-11-05 M1 估算器收口）——常数变更除断言外还影响 token→字节的逆换算、golden、生产注释、cf-sampler 镜像估算器与 subagent fork/resume 80% 阈值；只列断言点和三道旧门禁会系统性漏检

### R-015 【验证协议】守卫断言须自检"字面可满足性"，且正确性验证前置于数据采集
- **触发**：为非标执行栈（手写并行/手写 LoRA/参考实现算子/新框架大版本）设计验证协议时

### R-029 【门控】交付就绪度判定必须绑定"被检产物指纹"并含渲染层门禁

### R-030 【门控】图表类交付必须校验"印刷有效字号"，脚本字号与无告警都不算证据
- **触发**：用 matplotlib/PIL/任何绘图栈生成将嵌入文档的图表（横道图、网络图、曲线、平面布置图、流程图、矩阵表图），尤其是"画布大、摆放小"的写法
- **规则**：①**有效印刷字号 = 标称字号 × (版面摆放宽度 ÷ 画布物理宽度)**——若画布写 17～20 英寸（物理 43～51cm）而摆放 9.5～13.2cm，缩放 0.21～0.31 倍，标称 10.5pt 印出来只有 **2.2～3.3pt，物理不可读**；②**三类常规检查对此全部无感**：matplotlib 缺字告警为 0（字形都在）、PNG 字节数与尺寸正常（像素够多）、脚本里 `fontsize=10.5` 看着合规——所以"图存在"绝不等于"图能读"；③正确写法：**1 画布英寸 = 1 印刷英寸**（`figsize=(摆放cm/2.54, 等比例高)`），字号直接按最终印刷效果定（正文标注 8～9pt、关键标注 ≥8pt、最低 7pt），`dpi≥300` 只解决锐度不解决字号；④门禁必须算式化（本项目 `_work/fig_print_check.py`：有效字号 ≥7pt 且像素密度 ≥118px/cm，摆放宽度从装配层 `FIG_WIDTHS` 取，防"改了图没改摆放"），并在**终版 PDF 整页渲染**后由视觉席复核一次——单张 PNG 自查看不出错；⑤重制图表时**保持宽高比不变**是硬要求，否则摆放高度变化会引起全文重排、页数与已回填页码一起漂；⑥视觉席的"看不清"要结合算式判断：本例视觉席先判"分辨率受限、低置信"，指挥官算式复核证明是**真实物理缺陷**，低置信不等于假缺陷——两边都要量，谁都不能单独定案
- **证据**：2026-11-07 合肥华侨城技术标——10 张自绘图全部 2.2～3.1pt 有效字号（视觉席：横道图九条阶段名与起止日期"全部看不清"、界面矩阵列名与 12 行行名"全部看不清"、总平面 14 条图例与"4m/2000 目/13243.02 ㎡"均无法辨认），而该缺陷穿过了此前 14 道门禁与三轮视觉复核，直到把 PDF 整页与画布尺寸放在一起算才暴露
