## 2. 工具盘点（含 step-5 补充）

### 2.1 实测结果（22 项原盘 + step-5 补充）

| 状态 | 工具 | 说明 |
|---|---|---|
| ✅ 真可用 | `git` `gh` `python` `node` `cargo` `rustc` `tar` `tree` `ssh` `scp` | 无坑 |
| ⚠️ **有别名陷阱** | `curl`（需写 `curl.exe`）`wget`（**假阳性**，全盘无 exe，仅 PS 别名） | 必须显式后缀 |
| ⚠️ **指向 WSL** | `bash` → `C:\Windows\system32\bash.exe`；实测执行会落入 WSL（未装发行版时表现为长时间等待，非严格"无限挂起"） | 用 Git Bash 全路径 |

### 2.1b 关于 rg 捆绑的定论（Q9）

**内置 grep 工具在 Windows 上不捆绑 rg，装到 PATH 即刻可用，无需重编译。**

证据（双向）：

1. **静态代码**：`crates/codegen/cf-tools/build.rs` 明确写着
   > Skip auto-bundling on Windows: ripgrep ships .zip on Windows (not .tar.gz) and we have no zip-extraction path. Returning here BEFORE emitting `cargo:rustc-cfg=bundle_rg` ... the runtime falls back to `rg` on PATH. **Users install ripgrep separately (winget / scoop).**

   即 `target_os == "windows"` 且无 `QIDI_TOOLS_BUNDLE_RG_PATH` 时**直接 return**，`bundle_rg` cfg 不发出，运行时走 `ripgrep.rs:169` 的 `PathBuf::from("rg")`。
2. **运行态产物**：`%USERPROFILE%\.qidi\vendor` **不存在**（若捆绑生效，启动探针会先落盘）；本会话实测 spawn 报 "program not found"。

**结论**：把 `rg.exe` 放进 `.cargo\bin`（已在启动期 PATH 内）→ **零重启零重编译**可用。放进新增 PATH 目录 → 需重启 qidi。
| ❌ 缺失 | `rg` `jq` `fd` `sqlite3` `7z` `uv` `bat` `delta` | 见 §2.2 |
| ✅ step-5 补正 | `docker` `kubectl` **实际在位**（v1 未测到） | — |
| ❌ 不需要 | `make` `gcc`（纯 Rust 仓库）`yq` `fzf` `rsync` `hyperfine` `pwsh`（会改 shell 级联与尾 `&` 语义） | — |

### 2.2 已在磁盘、零安装可得（step-5 关键发现）

`C:\Program Files\Git\usr\bin` 下有 **245 个 exe**，含：

```
diff file xxd sha256sum base64 unzip patch
sed awk grep head tail wc cut tr xargs perl openssl cygpath
```

**它们只是不在 PATH。**

> ⚠️ **切勿整目录入 PATH**：该目录含 `link.exe`，会遮蔽 MSVC 链接器，
> 导致 `cargo build` 失败（链接错误，且难以定位）。
> 正确做法：建**精选 shim 目录**，只软链/复制需要的，**显式排除 `link.exe`**。

### 2.3 建议补装

| 工具 | 优先级 | 理由 |
|---|---|---|
| **rg** | **P0** | 内置 grep 工具的唯一依赖 |
| **jq** | P1 | relay 场景 JSON 重负载；退回 `python -c` 每次多 2–3 往返 |

## 3. 修复方案

### 3.1 两个根治杠杆（v1 完全遗漏）

#### 杠杆 A：`QIDI_SHELL=bash` 切换工具层 shell

**现状**：工具层默认 PowerShell（PS 5.1），受 `&&` 不支持、别名阴影、双引号 `$()` 展开三类困扰。

**方案**：设用户环境变量 `QIDI_SHELL=bash`，工具层自动改用 Git Bash。

**依据**：
- `cf-config/src/shell.rs:36-66` 支持 `bash` / `pwsh` / `powershell.exe` / `cmd.exe`
- `:50` 明确 Git Bash 分支
- `:363` 已预设 `MSYS_NO_PATHCONV=1`，**路径不会被自动转换**（`C:\x` 保持原样）
- `:848` 有对应断言测试
- hooks 固定走 PowerShell，不受影响

**收益**：`&&` 可用、无别名阴影、管道/引号语义正常。
**工时**：2 分钟（设个环境变量）。
**v1 原估**：1–2 天（工具层加参数）——**高估近两个数量级**。

#### 杠杆 B：把 rg.exe 放进 `.cargo\bin` 实现免重启

**问题**：装进系统 PATH 后，**运行中的 qidi 进程看不到**——子进程继承启动期环境块，而 `ripgrep.rs:170` 的 `PathBuf::from("rg")` 按进程 PATH 解析。

**实测**：本机 2 个 qidi 进程均启动于 11/02，改系统 PATH 后不重启无效。

**方案**：rg.exe 直接丢进 `%USERPROFILE%\.cargo\bin\`：
- 该目录**已在 PATH**（实测）
- 该目录**在 qidi 继承环境内**（cargo 从这里跑）
- 可写，现有 15 个文件

**收益**：无需重启 qidicode 即刻生效。
**工时**：3 分钟。

### 3.2 执行清单（v3，按二审修正执行顺序与 PATH 工艺）

> **关键**：所有环境变量变更（PATH + `QIDI_SHELL`）**合并为唯一一次重启**，中途不重启。

| # | 动作 | 工时 | 何时生效 |
|---|---|---|---|
| 1 | 下载 `rg.exe` → `%USERPROFILE%\.cargo\bin\` | 3 分钟 | **立刻**（该目录在启动期 PATH 内，grep 工具每次调用直 spawn，不缓存可用性） |
| 2 | 用 `[Environment]::SetEnvironmentVariable` 追加 `.shims` 到 **User PATH** | 3 分钟 | 需重启（见下方工艺警告） |
| 3 | 建 `%USERPROFILE%\.shims\`，从 Git `usr\bin` 复制精选工具（**排除 link.exe 及 find/sort/tar/gzip/ssh 等冲突项**） | 15 分钟 | 需重启（在第 2 步的 PATH 里） |
| 4 | `jq.exe` → `.shims\` | 5 分钟 | 需重启（同上） |
| 5 | 设 `QIDI_SHELL=bash`（User 级） | 2 分钟 | 需重启 |
| 6 | 改 AGENTS.md：工具清单 + 正确用法 + 别名陷阱 + 回退法 | 20 分钟 | 立刻（文档） |
| 7 | **一次性重启 qidicode**（激活 2/3/4/5 全部） | 1 分钟 | — |
| **合计** | | **≈49 分钟** | **仅 1 次重启** |

#### ⚠️ PATH 追加工艺（MAJOR-2）

**禁止** `setx PATH "%PATH%"`——本机 User PATH 已达 **1327 字符**，`setx` 有 1024/2048 截断风险，**会静默损坏 PATH**。

正确做法：

```powershell
$userPath = [Environment]::GetEnvironmentVariable('Path', 'User')
if ($userPath -notlike '*\.shims*') {
    [Environment]::SetEnvironmentVariable(
        'Path', "$userPath;$env:USERPROFILE\.shims", 'User')
}
```

- **只读写 User 域**，不碰 Machine 域（避免提权与影响其他用户）
- **执行前先备份**：`$userPath > "$env:USERPROFILE\path-backup-$(Get-Date -f yyyyMMdd).txt"`
- **执行后立刻回读校验**：长度应增加约 20 字符，且不含截断特征

#### 回退法

环境变量回退（取消 `QIDI_SHELL`、移除 PATH 项）**同样需要重启**才生效——不是"立刻取消"。§5 风险表已按此修正。

## 5. 残余风险

| 风险 | 说明 | 缓解 |
|---|---|---|
| `QIDI_SHELL=bash` 的副作用 | 未实测所有工具在 Git Bash 下的行为（尤其 Windows 路径参数）。**注意 `bash -l`**（PTY 交互路径 `pty_session.rs:480`）会加载 profile，本方案的 `-c` 路径不加载；若 profile 有重定义命令，两条路径行为可能不同 | 灰度：先设用户级，观察 1 个会话；异常回退**需重启**（不是立刻生效） |
| shim 目录冲突 | `usr\bin` 除 `link.exe` 外还有 **`find` / `sort` / `tar` / `gzip` / `ssh`** 等与 Windows/系统工具同名者 | 建好后跑 `where <name>` 全量核对；只复制白名单，不整目录 |
| rg 版本与内置工具契约 | 内置工具可能期待特定 rg 版本输出格式 | 装完立刻跑 G1 验收 |
| 免重启方案未经验证 | `.cargo\bin` 在 PATH 是事实，但"qidi 子进程能看见"仍是**推断**（虽已由本会话 cargo 解析实证） | **执行第 1 步后立刻验证**；不行就等到第 7 步统一重启 |
| PATH 追加损坏 | `setx` 会静默截断（本机 User PATH 1327 字符） | 用 `[Environment]::SetEnvironmentVariable` + 前置备份 |
| `QIDI_SHELL` 取值 | 代码只认 `bash` / `pwsh` / `cmd` 等字面量，**不认 `powershell.exe`**（`shell.rs:36-66`） | 文档写死合法值，避免手误 |
