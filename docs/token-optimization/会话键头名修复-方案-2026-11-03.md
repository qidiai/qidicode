## 0. 一句话

`affinity.session_key()` 读 `X-Session-Id`，qidicode 发的是 `x-grok-session-id`。加一级读取即可；但**必须同时处理五个既有事实**（见 §1），否则会引入隐性行为变更。

---

## 1. 事实（全部经 K3.1 逐行核实）

### 1.1 现有 fallback 顺序（`proxy_core/affinity.py:125-165`）

| 序 | 条件 | 返回 | 备注 |
|---|---|---|---|
| 1 | `data["user"]` 非空 | `u:` + 原值 | **不 strip**，空白也命中（`:136-138`） |
| 2 | `headers.get("X-Session-Id")` 非空 | `h:` + 原值 | **不 strip**（`:139-141`） |
| 3 | 首条 user 消息 | `m:` + sha256[:16] | 取 UTF-8 前 512B（`:142-160`） |
| 4 | `key_label` | `k:` + 值 | `:161-162` |
| 5 | `remote_addr` | `r:` + 值 | `:163-164` |
| 末 | 都未命中 | `anon` | `:165` |

**当前 qidicode 流量走第 3 级**（`user` 为空、`X-Session-Id` 不存在）。

### 1.2 `ledger_skey()` 的顺序不同（`proxy_core/db.py:128-152`）

| 序 | `affinity.session_key` | `db.ledger_skey` |
|---|---|---|
| 1 | `user` → `u:` | **Grok 头** → `h:gs:` |
| 2 | `X-Session-Id` → `h:` | **`X-Session-Id`** → `h:` |
| 3 | 消息哈希 → `m:` | **`user`** → `u:` |
| 空白处理 | 不 strip | **strip，空白视为缺席** |

**结论**：两者不能直接互相替换，**必须先裁定 canonical 语义**（§2.1）。

### 1.3 开关默认开（`routes/proxy.py:535-545`、`affinity.py:236-238`）

`features.affinity` 缺省 `True`；当前 `config.json` **无 `features` 段** → 实际生效为开。
**本方案不需要"打开开关"步骤。**

### 1.4 qidicode 的头覆盖（审计实测）

**六种 API 都加头**（`client.rs:91-109`，具体 `:98`），取值 `x_grok_session_id.as_deref().unwrap_or_default()`。

| 场景 | 头值 |
|---|---|
| 主会话 turn | 非空（`turn.rs:1880-1883`） |
| headless | 非空（走同一 `process_conversation_turn`） |
| 子代理 | 非空（同主回路，仅标记 `is_subagent`） |
| **memory note rewrite** | **空**（`memory_dream.rs:731-738`，`..Default::default()`） |
| **AI shell suggest** | **空**（`recap.rs:513-520`） |
| **reasoning summary** | **空**（`reasoning_summarizer.rs:285-301`，函数收了 `session_id` 但没赋） |

**因此**：目标范围必须收窄为"**携带非空 Grok 头的请求**"（MAJOR 2）。

### 1.5 隐藏调用方（MAJOR 3）

`proxy_core/corpus.py:299-300` 有别名导入：

```python
from .affinity import session_key as _skey
```

外层是宽 `except`（`:297-302`），ImportError 会被静默吞成 `session_id=None`。**删掉 `affinity.session_key` 会造成观测回归且不报错。**

### 1.6 旧绑定处置（MINOR 4）

- 旧 `m:` key 与新 `h:gs:` key **不会被同一次 `pick_prefer` 竞争**（`:241-244` 只精确查当前 key）；
- 但旧记录**不会 24h 后物理消失**——只有加载时过滤（`:493-529`）或 LRU 淘汰（`:476-480`）；
- **不需要迁移**。新请求首次为 `cold`，成功后自然建立新绑定。

## 2. 改动

### 2.1 canonical 语义裁定（MAJOR 1）

**唯一顺序**（`proxy_core/sessionkey.py` 新模块，两方共用）：

```
Grok 头(h:gs:) → user(u:) → X-Session-Id(h:) → 消息哈希(m:) → key(k:) → ip(r:) → anon
```

**行为变化声明**（必须写进 commit message 与变更日志）：

| 侧 | 变化 |
|---|---|
| `affinity.session_key` | 新增第 0 级 Grok 头；**其余顺序不变**（`user` 仍优先于 `X-Session-Id`） |
| `db.ledger_skey` | **user 与 X-Session-Id 顺序对调**（原 X-Session 优先 → 现 user 优先），与 affinity 统一 |

**空白策略统一**：全部 `strip()` 后判空；空白视为缺席。这也会改变 `affinity` 的既有行为（原不 strip），**属有意修正**，需在 K4 里显式断言。

### 2.2 模块设计（MAJOR 3）

新建 `proxy_core/sessionkey.py`，**纯函数、零 import 副作用**：

```python
"""会话键唯一来源。禁止在别处重写 fallback（R-007）。"""
_GROK_HEADER = "X-Grok-Session-Id"      # Werkzeug headers 大小写不敏感；
                                         # 普通 dict 测试须用这个精确写法

def _clean(v):
    """strip 后判空。**先 clean 再判，不要写成 `clean(a) or clean(b)`**——
    后者在 a 为大写空白键时应继续尝试 b，但 `or` 的短路会在
    `_clean(a)` 得到空串后继续求值 `_clean(b)`，行为正确；
    容易写错的是 `v = h.get(A) or h.get(B); v = _clean(v)` —— 若 A 命中且为空白，
    会短路掉 B，导致漏掉有效的小写键。因此逐键 clean 再择一。

    headers 可能是 Werkzeug 的 EnvironHeaders（大小写不敏感）或普通 dict
    （大小写敏感），所以逐键双写查找、逐值 clean。
    """
    if not isinstance(v, str):
        return ""
    return v.strip()

def _pick_header(headers, name):
    """先精确名、再小写名；**每次命中都 clean**，空白继续尝试下一个键。"""
    if not headers:
        return ""
    for key in (name, name.lower()):
        v = _clean(headers.get(key))
        if v:
            return v
    return ""

def derive(data, headers, key_label, remote_addr) -> str:
    # 0. qidicode / grok 系：专有头最高优先
    v = _pick_header(headers, _GROK_HEADER)
    if v:
        return "h:gs:" + v
    # 1. Anthropic metadata.user_id（已由 anthropic.py 译入）
    v = _clean((data or {}).get("user"))
    if v:
        return "u:" + v
    # 2. 通用 X-Session-Id
    v = _pick_header(headers, "X-Session-Id")
    if v:
        return "h:" + v
    # 3. 首条 user 消息 512B sha256[:16] —— 沿用现有实现（affinity.py:142-160）
    v = _message_hash(data)
    if v:
        return "m:" + v
    # 4/5/6. key_label / remote_addr / anon
    if key_label:
        return "k:" + str(key_label)
    if remote_addr:
        return "r:" + str(remote_addr)
    return "anon"
```

> `_message_hash(data)` 由实现者从 `affinity.py:142-160` **原样迁移**（含多模态
> `sort_keys=True` 序列化与 UTF-8 前 512B 截断），**不得重写**。

**兼容层**（必须保留，防 corpus 静默回归）：

```python
# proxy_core/affinity.py
from .sessionkey import derive as _derive
def session_key(data, headers, key_label, remote_addr):
    return _derive(data, headers, key_label, remote_addr)   # 名称保留

# proxy_core/db.py
from .sessionkey import derive as _derive
def ledger_skey(data, headers, key_label, remote_addr):
    return _derive(data, headers, key_label, remote_addr)   # 名称保留
```

**不选** `affinity → db`：`db.py` 导入即执行 `kdb = KnowledgeDB()`（`:433-435`），会带上 SQLite 初始化副作用（审计 Q3）。

### 2.3 范围声明（MAJOR 2）

**本方案覆盖**：携带非空 `x-grok-session-id` 的请求（主会话 / headless / 子代理）。

**本方案不覆盖**：memory dream / AI shell suggest / reasoning summary 三类辅助请求——它们发空头，继续走消息哈希 fallback。

**为什么不顺手补**：这三处要改 Rust 客户端（`cf-shell`），属于另一个改动面；且它们的调用频率低、上下文短，缓存收益有限。**若将来要覆盖，作为独立任务。**

### 2.4 不改的部分

- 不改粘性策略（`_CACHE_READ_MIN=1024` / `_STICK_WINDOW_S=300` / rebind 三档）；
- 不改存储（内存 LRU 512 + 原子落盘 + 24h 语义过期）；
- 不改开关（`features.affinity` 默认 True，无需配置）。

## 3. 验收（K6 已按 MINOR 6 收紧）

| # | 项 | 判据 |
|---|---|---|
| K1 | 两个不同 Grok 头 + 相同首条消息 | `derive()` 返回**不同**值（`h:gs:A` ≠ `h:gs:B`） |
| K2 | 同头跨请求 | 返回**相同**值 |
| K3 | 空头/纯空白头 | **不回落到 `h:gs:`**，走既有 fallback（`u:` 或 `m:`） |
| K4 | 无 Grok 头的其他客户端 | `user` 优先于 `X-Session-Id`（新语义，**与旧行为不同**，须断言新顺序而非"完全一致"）；空白 `X-Session-Id` 现在视为缺席（**旧行为是返回带空白的 `h:`**） |
| K5 | affinity 与 ledger 同值 | 同一请求两者返回**完全相同**字符串 |
| K6 | 粘性仍生效（**收紧**） | 同 session 首请求 `why=cold` → 成功后第二次同 UID 且 **`why=cache`**（需上次 `cache_read≥1024` 且间隔 <300s）；工具循环内为 **`why=turn`**。**`no-cache`/`no-data`/`off`/`resting`/`spent`/`disabled` 均不算通过** |
| K7 | corpus 不回归 | `corpus.py` 的 `_skey` 调用仍可用；语料 `session_id` 非空且同键一致（**新增，MAJOR 3**） |
| K8 | 无 **SQLite** 导入副作用 | **全新子进程 + stub 计数**：`python3 -c "import sqlite3,sys; n=[0]; orig=sqlite3.connect; sqlite3.connect=lambda *a,**k:(n.__setitem__(0,n[0]+1),orig(*a,**k))[1]; import proxy_core.sessionkey; print(n[0])"` 必须输出 **0**。**不得**在生产进程或已导入 db 的上下文里对照（那份连接是 db 造成的，与本模块无关） |
