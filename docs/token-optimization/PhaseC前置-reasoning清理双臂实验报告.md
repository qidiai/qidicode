# Phase C 前置实验：reasoning 块清理对续写质量的影响（双臂盲测）

> 2026-10-12。Phase C 设计决策 #1（reasoning 是否纳入低水位批量清）的前置实验。用户裁决链：先实验再拍板 → 本实验完成后定夺。

## 实验设计

- **变量唯一**：assistant 历史消息中的【思考】推理文本块——A 臂保留 vs B 臂剥离（strip 形态），其余消息逐字节一致（脚本内置断言自检）
- **任务集**：6 任务（诊断排除/方案取舍/数据推演/设计约束/排除法记忆/跨轮引用），续写提问设计为**只有读到早期思考过程才答得准**；t3（数据推演）为对照组——答案可从提问内参数重算，预期 A/B 无差异，构成**实验内部有效性校验**
- **模型**：GLM-5.3（max_tokens 16384，思考模型预算实测修正）+ kimi-k2.7-code（1500），luyou 端点，temperature=0
- **执行**：24/24 调用成功（零 429），零编译
- **裁判**：K3 独立盲评（X/Y 匿名随机映射，禁读 map），指挥官揭盲

### 质量缺陷分布（全部在 B 臂）

| 类型 | 实例 |
|---|---|
| 编造 ×5 | GLM-B t1 虚构"30s 采样粒度"；GLM-B t2 虚构"强一致只有三条实现路径"；GLM-B t4 虚构"MISRA/IEC 61508"且与材料约束②直接矛盾；kimi-B t2 虚构"热 key 串行化"；kimi-B t5 把 GPL 错配到 3/4 号候选 |
| 因果错置 ×1 | kimi-B t1 把"排除依据"错述为"回滚后恢复"（时间线矛盾） |
| 输出崩坏 ×1 | kimi-B t4 中段重复循环截断 |

### 关键模式

1. **B 臂退化模式不是"含糊"而是"编造"**：用通用领域知识重写答案，看似专业实则架空材料（逐字数字、排除依据、隐藏约束全部丢失后以貌似合理的虚构填补）。
2. **部分清理比全量 compact 更危险**：compact 是全量重建（模型从摘要重启，无"看到正文却看不到推导"的落差）；低水位清 reasoning 保留正文结论——模型假设推导与正文一致并用通用知识补齐——编造的直接来源。
3. **考古证据（4 生产路径无故障）与实验证据的调和**：无故障记录 ≠ 无质量损失——损失存在但从未被测量/归因。本实验就是那次测量。
4. GLM-5.3 副发现：历史含【思考】块时模型会模仿该格式输出；思考模型 reasoning_content 计入 max_tokens（预算实测：16384 方完整）。

## 对 Phase C 的含义

- 维持 C-1（不清 reasoning）→ 低水位 batched 只清 ToolResult，O-4 实测收益中位 **0.6%**——机制形同虚设
- 纳入 reasoning 裸清 → 本实验证伪（质量代价压倒性）
- **可行方向**：清 reasoning 原文时**摘要化保留关键事实**（数字、排除依据、隐藏约束压缩为 1-3 行留存）——K3 裁判独立建议同向（"至少以摘要形式保留关键数字与排除依据"）
- ~~或高龄阈值+档案回捞指引折中（O-14 已证档案层全量保留 reasoning）~~ **【勘误 2026-10-12（opus-5.5 五模分析抓出）**：O-14 证明的是 tool_use raw_input 保留，**不含 reasoning**；`render_segment_md` doc 明文 reasoning stripped（`compaction_transcript.rs:435-437`），`prepare_conversation_for_segment` = strip_images ∘ strip_reasoning_blocks——**任何档案层均不可回捞 reasoning**（Transcript 模式 updates.jsonl 未核），"档案回捞"前提不成立，该折中方向作废**】**

## r2：五模分析与 C1/C2 闸门链（2026-10-12 追加）

### 五模裁决（GLM-5.3 / kimi-k2.7 / DeepSeek / claude-opus-5.5 / claude-haiku-4.5，原阵容 step5-402/grok-行为异常/K3-429 缺席）

- **五票一致投 ②（摘要化保留）**；③三重否决出局（回捞与"自信编造"机制错配——模型不知道自己缺什么就永不解引用指针；档案层不含 reasoning；age 收益萎缩）
- ①只配当临时态（C 臂未过时的退路）
- 摘要架构仲裁（DeepSeek）：**规则抽取地板（强制）+ LLM 语义增强（闸门后可选）**——规则抽取器结构上无法编造，LLM 摘要是"用编造对冲编造"的循环信任
- 三条硬底：**never-bare-clear**（摘要失败/为空 ⇒ 保留原文不清）；**加密 regime 强制保留**（encrypted_content 改写即 400、加密-only 块摘要源为空）；**摘要一次生成即缓存**（否则逐轮改写击穿 C-2 prefix-growth）
- opus-5.5 抓出本报告初版一处证据混同（已勘误）：O-14 证明的是 tool_use raw_input 保留，**不含 reasoning**——档案层（segments）明文 strip reasoning，"档案回捞"方向作废

### 第 0 步补测（ling，零调用）

- **reasoning age 分布**：触发时口径 31.7% 与 O-4 复现（<1pp 偏差）→ **②收益维持 ~28-32%**；age≥10 reasoning 占全样本 24.5%（存量口径下修）；age≥20 仅 9.3% → **age=10 是甜点**，支持 `hard_clear_age_turns=10` 而非 20

### C1 臂实验（规则地板摘要形态，12/12 调用成功）

- **构建保真**：C1 摘要全部来自 rule_extract.py 真实产出（非手写理想摘要），脚本断言自检（与 A 除思考块替换外逐字节一致）
- **执行员初判**：B 臂 7 处编造 **7/7 归零**；聚合 rp C1 46/60 = A 46/60 ≫ B 26/60——乐观判"C1 追平 A"
- **独立盲评（DeepSeek 裁判）+ 揭盲推翻初判**：**A 优 6 / C1 优 1 / 相当 5**（t3 双平=对照组校验通过）——**闸条二（对 A 胜负差 ≤±2）未通过**（差 5）
- **关键发现：编造分布反转**——摘要侧（C1）出现 3-4 处编造/漂移（t2 双模型把"8k QPS 架构性天花板"漂成虚构"Redis 单点"、t6 GLM 自造"每线程栈 1MB"、t4_kimi 轻微不当添加），执行员非盲初判漏检了这些
- **病灶精确化**：规则地板保住主干数字与断言原句，但丢失**归因框架句**（"8k 是架构性天花板"——无断言词的定性句，规则抓不到）与**次级佐证链**（12MB/每 10 分钟阶梯、3 个重复 ClassLoader、4.2w/8ms）——模型在缺口处用通用知识补白=编造

### C2 臂（预设计，执行因 luyou 池 429 推迟至晚上/次日额度窗口）

- **C2 摘要形态** = 规则地板产物 + **LLM 归因增强行**（1-2 行，必须含：定性归因句逐字保留 + 次级佐证数字含单位；禁止补写原文没有的因果/数字）
- **子集校验（脚本断言）**：LLM 归因行出现的每个数字必须存在于原思考块，校验失败该块降级为纯规则地板摘要

### 定案（Phase C ②最终形态，全部来自五模预设计+C1/C2 实证迭代）

- 清扫范围：ToolResult + Reasoning（age≥10），`low_watermark_percent=40`
- Reasoning 走摘要化替换：规则地板（数字/断言原句，扩展词表）+ LLM 归因增强行（定性归因句逐字+次级佐证含单位；GLM-5.3 级 flash 档即可）
- `never-bare-clear` 铁律：摘要失败/为空/子集校验不过 ⇒ 保留原文不清
- 子集校验：摘要中的数字必须 ⊆ 原块数字集合（越界即降级）
- 加密 regime（encrypted_content 块）整类强制保留不清
- 摘要以可见文本形态存在（合成 sibling；禁放 Reasoning item——部分 provider 丢 reasoning_content）
- 摘要一次生成即缓存（保 C-2 prefix-growth）；异步预生成（35% 逼近后台预算、40% 触发只应用）
- K3 裁判补充建议：t1/t2 类密集次级佐证任务可设更高摘要保真度阈值（后续灰度参数候选）
